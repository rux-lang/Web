# rux login

Store a registry token so [`rux publish`](/cli/publish) can use it.

```sh
rux login
rux login --registry <url>
```

The token is read from standard input, never from an option. On a terminal you are prompted and your
typing is not echoed; anywhere else a single line is read, so a token can be piped in. See
[API Tokens](/packaging/tokens) for creating one.

`rux login` checks the token with the registry before storing it and refuses one that is rejected. A
registry that cannot be reached, or that does not implement the check, produces a warning and the token
is stored unverified.

## Options

| Option             | Description                              |
| ------------------ | ---------------------------------------- |
| `--registry <url>` | Registry API base URL to authenticate to |

## Environment

| Variable           | Description                                   |
| ------------------ | --------------------------------------------- |
| `RUX_TOKEN`        | Takes precedence over a stored token when set |
| `RUX_REGISTRY_URL` | Default registry, overridden by `--registry`  |

## Where the token is stored

Tokens are kept beside the package cache, in a file only your account can read:

- **Windows** — `%LOCALAPPDATA%\Rux\Credentials.toml`
- **Linux / macOS** — `~/.rux/credentials.toml`

```toml
[Registry."https://api.rux-lang.dev"]
Token = "rux_pat_..."
```

Entries are keyed by registry, so pointing `--registry` at a local registry never sends it the
credential for the official one. [`rux logout`](/cli/logout) removes one registry's entry and leaves the
rest.

## Examples

```sh
# Authenticate to the official registry, entering the token when prompted
rux login

# Pipe a token in — the shell reads it, so it never becomes an argument
echo "$RUX_PUBLISH_TOKEN" | rux login

# Authenticate to a local registry
rux login --registry http://localhost:8080
```

```
   Logged in to https://api.rux-lang.dev as octocat
      Stored C:/Users/You/AppData/Local/Rux/Credentials.toml
```
