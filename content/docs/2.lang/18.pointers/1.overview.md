# Pointers

A _raw pointer_ holds the address of a value. `*T` is a **read-only** pointer: the value it points at can be read through it. `*var T` is a **writable** pointer: the value can also be written. A pointer may be `null`, may be stored in a field, returned, offset and compared, and may outlive what it points at — the compiler checks only what the pointer type allows, never whether the address is still good. That is the price of the things only a pointer can do: [foreign functions](/docs/lang/ffi/overview), manual allocation, stored links between values, and walking memory by address. Because the compiler cannot check what a pointer addresses, every operation that reaches through one is a [raw operation](#raw-operations): it needs no mark, and by convention a `// Safety:` comment above it says why it holds.

```text
pointer-type = "*" type
             | "*" "var" type
address-of   = "@" place
dereference  = "*" expression
```

```rux
var score = 10;
let writer = @score;        // *var int: score is a var
let reader: *int = @score;  // a read-only view of the same int
// Safety: both pointers address score, which is live for the whole block.
{
    *writer += 5;           // score is now 15
    let current = *reader;  // 15
}
```

For checked access to a value someone else owns, use a [reference](/docs/lang/references/overview) instead; a pointer is the deliberate step outside those checks.

## Taking an address

The prefix `@` takes the address of a place: a variable, a field, an element, or the target of another pointer. `@x.field` and `@a[i]` address one part of a value. Taking an address is not itself a raw operation; using it is. The pointer's writability comes from the place:

| Place                                         | `@place` has type |
| --------------------------------------------- | ----------------- |
| a `var` binding, or a part of one             | `*var T`          |
| a `let` binding, or a part of one             | `*T`              |
| an element of a `var T[..]` view              | `*var T`          |
| an element of a `T[..]` view                  | `*T`              |
| a field or element reached through a `*var T` | `*var T`          |

```text
error: cannot assign '*int' to '*var int': '@limit' yields a read-only '*T'; declare 'limit' with 'var' for a '*var T'
```

`@` of a reference is the address of its referent, not of the reference: with `p: &Point`, `@p` is a `*Point` equal to the caller's `@point`.

### A loan is not an address

`&x` and `@x` both reach `x` without copying it, and they are not interchangeable. `&x` is a [loan](/docs/lang/references/overview#loans): a reference the compiler tracks, which lives no longer than the call or the block that made it, cannot be null or stored, and keeps `x` from being written or given away while it is in use. `@x` is an address: a plain number with a type, which the program may store, offset and keep past `x`'s life, and which the compiler stops checking the moment it is made. A loan passed where a pointer is expected is a type mismatch whose help names the right operator:

```text
error: argument 1 to 'Store' has type '&var int', but parameter 'target' requires '*var int'
  help: '&' lends a place; write '@' to take its address for a raw pointer
```

A pointer is made only from an address, so a plain value where a pointer is expected is the error `cannot assign 'int' to '*int'`.

Taking the writable address of a variable declared without a value counts as initialising it, because the address exists to be filled through: `var info: SystemInfo; GetSystemInfo(@info);` leaves `info` usable. See [Initialisation](/docs/lang/bindings/initialization).

## Reading and writing through a pointer

The prefix `*` _dereferences_ a pointer: `*p` is the value it points at, a place that can be read, and written when `p` is a `*var T`:

```rux
/// Stores value where target points.
/// Safety: target addresses a live, writable int.
func Store(target: *var int, value: int) {
    // Safety: the caller vouches for target, as documented above.
    *target = value;
}
```

```text
error: cannot modify data through read-only pointer '*int'
```

The pointee type, not the variable it points at, decides what is allowed: a `*int` cannot write even when it points at a `var`.

A write through a pointer **initialises** the storage it addresses and destroys nothing. The pointer cannot tell whether that storage holds a value yet, so `*p = value`, `p[i] = value` and a field write through a `*var T` never run a destructor for what was there before. A read goes the other way: `*p`, `p[i]` or a field reached through a pointer **takes the value out** and leaves the storage empty, for an owning value as for plain data, and nothing tracks it. Code that replaces a value through a pointer reads out the old one or destroys it first:

```rux
struct Noisy {
    id: int;
}

extend Noisy {
    destructor {
        PrintLine("destroy {}", self.id);
    }
}

func Main() -> int {
    var slot = Noisy { id: 1 };
    slot = Noisy { id: 2 };       // assignment: destroys 1
    let p = @slot;
    // Safety: p addresses slot, which is live.
    *p = Noisy { id: 3 };         // through a pointer: 2 is never destroyed
    // Safety: p addresses slot; the read leaves it empty until the write below.
    let taken = *p;
    // Safety: p addresses slot, which the read above left empty.
    *p = Noisy { id: 4 };
    return 0;                     // destroys 3, then 4
}
```

```text
destroy 1
destroy 3
destroy 4
```

[`destroy *p;`](/docs/lang/ownership/ending#destroy) and `destroy p[i];` destroy the value in place instead, and leave the slot empty for a later write to fill.

## Fields, elements and methods

`.` reaches through a pointer to a struct, and `[i]` through a pointer to an element; there is no arrow operator. Reads and writes go straight to the pointed-at value:

```rux
struct Point {
    x: int;
    y: int;
}

func Main() -> int {
    var point = Point { x: 1, y: 2 };
    let p = @point;
    // Safety: p addresses point, which is live.
    let sum = {
        p.x = 7;                 // point.x is now 7
        p.x + p.y
    };
    return 0;
}
```

A method whose receiver is a reference is not called through a raw pointer, because a pointer proves nothing about the address it holds. Dereference first, `(*p).Shift(3)`, to vouch for it where the call is written:

```text
error: cannot call method 'Shift', whose receiver is '&var Point', through raw pointer '*var Point'
  note: a raw pointer does not prove a valid, non-null borrow, so it is not borrowed implicitly
  help: dereference it where it is known to be valid: '(*p).Shift(...)'
```

A method that works on addresses declares a raw receiver, `*self` or `*var self`, and is called on the pointer itself; a field it reads through `self` is a raw operation like any other.

Pointers nest: `**T` is a pointer to a pointer, and each `*` removes one level, so with `pp: **var int`, `**pp = 1` writes the `int`.

## Conversions

| From      | To        | How                                            | A raw operation |
| --------- | --------- | ---------------------------------------------- | --------------- |
| `*var T`  | `*T`      | implicitly                                     | no              |
| `*T`      | `*opaque` | implicitly; `*var T` likewise to `*var opaque` | no              |
| `*opaque` | `*T`      | `as *T`; likewise `as *var T`                  | yes             |
| `*T`      | `*U`      | `as *U`                                        | yes             |
| `*T`      | `*var U`  | never, for any `U` but `opaque`                | —               |
| a pointer | `uint`    | `as uint` — the address as a number            | no              |
| `uint`    | a pointer | `as *T`                                        | yes             |

Losing write access is always allowed; gaining it is not: `cannot assign '*int' to '*var int'`. A cast with `as` is the explicit, unchecked way to retype an address — see [Casts](/docs/lang/expressions/casts) — but it cannot add write access either, whatever pointee it names, so `@x as *var int` and `@x as *var uint64` on a `let x` are refused. Untyped memory is the one way through: writable memory reached through an `*opaque`, such as a fresh allocation, is retyped with `as *var T`, and a `*T` may become a `*var opaque` for a C function that takes a `void *` it only reads. A cast that gives an address a type it did not have is a raw operation; one that only forgets what a pointer says is not:

```text
error: cannot cast '*int' to '*var uint64', which would give a read-only pointer write access
  note: a cast may drop write access but never add it, so a value reached through a '*T' stays unwritten
  help: take the address of a 'var' place, which is already writable
```

## `null`

`null` is the pointer that points at nothing. It converts to every pointer type, and it is the only value a pointer has that is not an address. Compare with `==` and `!=` before dereferencing a pointer that might be `null`:

```rux
struct Node {
    value: int;
    next: *Node;
}

func Main() -> int {
    var tail = Node { value: 3, next: null };
    var head = Node { value: 1, next: @tail };
    var cursor: *Node = @head;
    while cursor != null {
        // Safety: cursor is not null and addresses a live Node of this list.
        {
            PrintLine("{}", cursor.value);
            cursor = cursor.next;
        }
    }
    return 0;
}
```

Reading or writing through `null` is not checked: it compiles, and crashes the program when it runs.

`null` is a pointer value, not absence. It is not a value of an [optional](/docs/lang/optionals/overview) type, and where an optional of a pointer is expected it is a **present** null pointer:

| Type    | Meaning                                   |
| ------- | ----------------------------------------- |
| `(*T)?` | an optional pointer: `none`, or a pointer |
| `*T?`   | a pointer to an optional, `*(T?)`         |

```rux
let present: (*int)? = null;   // present, holding a null pointer
let absent: (*int)? = none;    // absent
```

## `*opaque`

`*opaque` and `*var opaque` point at bytes of no particular type, as C's `void *` does. Allocation functions return them, and foreign functions take and return them. Any typed pointer converts to one implicitly; to use the memory, cast it back to a typed pointer:

```rux
import Memory::Heap::{ Alloc, Free };

func Main() -> int {
    let block = Alloc(4 * sizeof(int));
    if block == null {
        return 1;
    }
    // Safety: block was allocated above and is freed once, when Main returns.
    defer Free(block);
    // Safety: block holds room for four ints.
    {
        let values = block as *var int;
        values[0] = 1;
    }
    return 0;
}
```

Arithmetic on an `*opaque` moves by single bytes.

## Comparison

Two pointers compare with `==` and `!=`, which compare addresses, and with `<`, `<=`, `>` and `>=`, which order them — useful when walking a buffer up to an end pointer. Comparing pointers is not a raw operation, since nothing is read through them. See [Pointer arithmetic](/docs/lang/pointers/arithmetic).

## What a pointer does not have

A pointer has no length: `p.length` is an error. It cannot be iterated with `for`, and slicing it needs an explicit end. To treat raw memory as a sequence, build a [view](/docs/lang/pointers/slicing) of it with a count, `p[..n]`, and iterate that, `for value in p[..n]`:

```text
error: cannot iterate over pointer '*int32'
  note: a pointer has no length, so nothing says where the loop would end
  help: iterate a slice of the memory it points at, as in 'for value in p[..count]'
```

A pointer is 8 bytes on every supported target, whatever it points at.

## Raw operations

The compiler checks references, bounds, ownership and borrows, but it cannot check what a raw pointer addresses, what a foreign function does, or what a function that takes a raw pointer expects of its caller. The operations whose soundness rests on such facts are the **raw operations**. They need no mark and are written anywhere:

| Raw operation                                                                                             | Not a raw operation                                         |
| --------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| `*p`, `*p = v`, `p[i]`, a range `p[a..b]`, a field `p.x` through `*T` or `*var T`                         | taking an address with `@`                                  |
| `p + n`, `n + p`, `p - n`, `p += n`, `p -= n`                                                             | copying, comparing and null-testing pointers                |
| a cast that gives an address a new type: an integer to a pointer, `*opaque` to `*T`, `*A` to `*B`         | a cast that only forgets: `*var T` to `*T`, or to `*opaque` |
| calling an [`extern`](/docs/lang/ffi/overview) or [`asm`](/docs/lang/ffi/assembly) function               | converting a pointer to an integer                          |
| reading or writing an `extern` variable                                                                   | `@` of an extern variable                                   |
| making an [interface handle](/docs/lang/interfaces/interface-values#handles) from a pointer, `p as Shape` | lending a value as an interface view, `&Shape`              |

The convention for each one is a **`// Safety:` comment** whose run ends on the line directly above it. It says why the operation is sound at that place — "`index < self.length`, checked above", "`block` comes from `Alloc` with room for `count` elements and is freed once" — never only that it is safe. Operations that rest on the same reasoning may share one comment, grouped in a plain block when that reads better:

```rux
// Safety: slots has room for two Noisy values, freed once below.
{
    slots[0] = Noisy { id: 1 };
    slots[1] = Noisy { id: 2 };
}
```

The block is an ordinary [value block](/docs/lang/expressions/conditional#plain-value-blocks): it changes nothing about what the program does, its locals end at its `}`, and in value position it yields its last expression written without a `;`, so a single read is `let first = { *p };`.

A function whose caller carries an obligation the compiler cannot check states it in a `Safety:` sentence of its `///` documentation, as `Store` does [above](#reading-and-writing-through-a-pointer) and [`Memory::Block::Copy`](/docs/api/memory/blocks#copy) does for its ranges, and a call to it gets a `// Safety:` comment like any raw operation. A function whose soundness does not depend on its caller states nothing and is called like any other. Interface requirements and their implementations, destructors and operators are called where no call is written, so they never put an obligation on their caller; their raw operations cite the documented contract they rely on instead.

Nothing checks either comment: the compiler accepts a raw operation with or without one. The comment is for the reader, who can find every place a program's soundness rests on a promise by searching for `Safety:`.

The keyword `unsafe` is not part of the language, and stays reserved. A block or a function marked with it is refused, and what follows the word is read as if it were not written:

```text
error: 'unsafe' is not supported
  help: remove it: a raw pointer operation, an extern call and an asm call need no mark
```
