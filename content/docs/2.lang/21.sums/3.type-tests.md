# Type Tests

`value is Type` answers a question about the type of `value` and produces a `bool`. What the question is depends on the operand: on a [sum](/docs/lang/sums/overview) it asks which member is active, on a [fallible](/docs/lang/errors/fallible-values) which side it holds, and on anything else it compares exact types at compile time. A test never consumes, binds or narrows its operand.

```text
type-test    = expr "is" postfix-type
pattern-test = expr "is" pattern
```

```rux
struct Plus {}
struct Minus {}
struct Number {
    value: int32;
}

type Token = Plus | Minus | Number;

func IsOperator(token: Token) -> bool {
    return token is (Plus | Minus);
}

func Count(tokens: Token[..]) -> uint {
    var numbers: uint = 0;
    for token in tokens {
        if token is Number {
            numbers += 1;
        }
    }
    return numbers;
}
```

## What is tested

The tested type is resolved first; together with the operand's type it selects the meaning:

| Operand             | `value is T` is `true` when                                                                                      |
| ------------------- | ---------------------------------------------------------------------------------------------------------------- |
| a sum `A \| B \| C` | the active member is `T`, or one of the members of a tested subset `(A \| B)`                                    |
| a fallible `S ! E`  | `T` is `S` and it holds a success, or `T` is `E` (or a member or subset of an error sum) and it holds that error |
| an optional `P?`    | never: the test is refused, see [below](#optionals-are-compared-not-tested)                                      |
| any other type      | the operand's type is exactly `T`, after aliases are resolved (decided at compile time)                          |

```rux
let maybe: int32 | bool = true;
let a = maybe is bool;               // true: the active member is bool

let outcome = Parse("8080");         // int ! ParseError
let b = outcome is ParseError;       // false: it holds a success

let count: int32 = 7;
let c = count is int32;              // true, known before the program runs
```

A borrowed operand is tested through the borrow, and an owned one stays where it is: after `outcome is ParseError`, `outcome` is still there to be matched or handled.

## A test that cannot be true is an error

A test whose answer is known to be `false` is a mistake, so the compiler rejects it rather than folding it to a constant:

```text
error: type 'bool8' is not a member or subset of sum 'Minus | Number | Plus'
error: type 'bool8' is neither the success nor an error of 'int ! ParseError'
error: 'is int64' can never be true for a value of type 'int32'
  help: an 'is' test on a value that is not a sum or an optional compares its exact type
```

On a value that is neither a sum nor a fallible, `is` compares types by name and identity, never by layout: a struct with the same fields under another name is a different type. An `is` test on such a value can only be `true`, which makes it useful mostly in generic code.

## Optionals are compared, not tested

Presence is not a type, so `is` does not take an [optional](/docs/lang/optionals/overview). Whether one holds a value is a comparison with `none`, and the value itself is bound with `if let`:

```text
error: 'is' does not test an optional
  help: compare with '== none' or '!= none', or bind the value with 'if let name? = ...'
```

The same holds for an optional sum, `(int32 | bool)?`: open the optional level first, then test the member.

## Testing a pattern

`subject is pattern` tests the subject against any pattern a `match` arm takes and is a `bool`; `value is T` is the type test above, which reads as the pattern `_: T`. What follows `is` is a pattern when it starts as only a pattern can — `.Case`, `none`, `_`, a literal, `Type::Case(...)`, `Type { ... }`, or a tuple holding one of these — and a type otherwise, so `token is Number` keeps testing a type. Alternatives are written with `|`:

```rux
if shape is .Circle(_) { circles += 1; }
if color is .Red | .Green { Warm(); }
if outcome is .Failure(.Empty) { Report(); }
```

A test binds nothing. A name where a pattern would bind one is refused, and `_` goes in its place:

```text
error: 'is' tests and does not bind 'n'
  help: bind with 'if let', as in 'if let .Case(name) = subject { ... }', or write '_' to test only
```

## Binding with if let

To use the member a test found, take it out with [`if let`](/docs/lang/statements/if), which tests and binds at once. Its pattern is any pattern a `match` arm takes, and a typed pattern selects a sum member:

```rux
func Show(token: Token) {
    if let n: Number = token {
        PrintLine("{}", n.value);
    }
    if let n: Number = token && n.value > 5 {
        PrintLine("a large number");
    }
    if let _: Plus | Minus = token {
        PrintLine("an operator");
    }
}
```

The names it binds are in scope in the body and in the conditions after it joined with `&&`, never in an `else` branch or after the statement. A binding comes first in the condition and does not combine with `||`. For several members at once, a [`match`](/docs/lang/sums/patterns) is clearer.

## `is` never narrows

A test does not change the static type of its operand. After `token is Number` succeeds, `token` is still the whole sum, and its member's fields are still out of reach:

```rux
if token is Number {
    PrintLine("{}", token.value); // error
}
```

```text
error: type 'Minus | Number | Plus' has no field 'value'
```

Take the member out with `if let n: Number = token`, as above, or with a [pattern](/docs/lang/sums/patterns) in a `match`.

## Grouping

The right operand of a type test is a postfix type, so a sum type, and a fallible type, must be grouped:

```text
error: a sum type after 'is' must be grouped
  help: write 'value is (Plus | Minus)'
error: a fallible after 'is' is grouped
  help: write it in parentheses, as in '(T ! E)'
```

`is` shares its [precedence](/docs/lang/expressions/overview) with `as`: it binds tighter than every binary operator, so `count is int32 && count > 0` needs no parentheses. Group it when it is the operand of a prefix operator: `!(token is Number)`.

## Generic code

A test whose operand or tested type mentions a type parameter is checked again for every instantiation. `value is T` on a `T | U` stays valid when `T` and `U` are the same type and the sum collapses. It is then a plain type comparison, and `true`:

```rux
func IsLeft<T, U>(value: T | U) -> bool {
    return value is T;
}
```

`IsLeft<int32, bool>(true)` is `false`, and `IsLeft<int32, int32>(5)` is `true`.

## Interfaces

`is` does not test whether a value implements an [interface](/docs/lang/interfaces/overview). That would be a run-time question about the value's type, and it is reported as unavailable rather than answered wrongly:

```text
error: type test 'is Shape' is unavailable: interface checks are not implemented
```

Membership is not interface implementation either: knowing that every member of a sum implements an interface, or that a test succeeded, makes no method available on the sum.
