# Loops

Rux has four loops. Each runs a block repeatedly; they differ in when, or whether, they test a condition.

| Loop                    | Tests                          | The body runs               |
| ----------------------- | ------------------------------ | --------------------------- |
| `while c { … }`         | before each pass               | zero or more times          |
| `while let p = s { … }` | before each pass, by a pattern | while the pattern matches   |
| `do { … } while c;`     | after each pass                | at least once               |
| `loop { … }`            | never                          | until a `break` or `return` |
| `for x in s { … }`      | for a next element of `s`      | once per element            |

```text
while-loop = [label ":"] "while" ( condition | "let" pattern "=" expression { "&&" expression } ) block
do-while   = [label ":"] "do" block "while" condition ";"
loop       = [label ":"] "loop" block
for-loop   = [label ":"] "for" pattern "in" expression block
```

Any loop may carry a label, so that a `break` or `continue` inside a nested loop can name it — see [break and continue](/docs/lang/statements/break-continue). Conditions follow the rules in [Statements](/docs/lang/statements/overview#conditions): a `bool`, no parentheses needed, a structure literal wrapped in parentheses.

## while

`while` tests its condition before every pass, including the first, so the body may never run:

```rux
var i = 0;
while i < 3 {
    PrintLine("{}", i);
    i++;
}
```

### while let

Like [`if let`](/docs/lang/statements/if#if-let), a `while` condition may start with `let pattern = subject`, or `var pattern = subject`. The subject is evaluated before every pass; the body runs while the pattern matches, with the names it binds, and the loop ends the first time it does not. The names are bound afresh on every pass and are not in scope after the loop:

```rux
import Io::PrintLine;

struct Countdown {
    left: int;
}

extend Countdown {
    func Next(&var self) -> int? {
        if self.left == 0 {
            return none;
        }
        self.left -= 1;
        return self.left + 1;
    }
}

func Main() -> int {
    var countdown = Countdown { left: 3 };
    while let n? = countdown.Next() {
        PrintLine("{}", n);   // 3, 2, 1
    }
    return 0;
}
```

Further conditions follow with `&&`, as in `while let n? = reader.Next() && n != 0`, and a binding never combines with `||`.

## do while

`do … while` runs the body first and tests afterwards, so the body always runs at least once. The statement ends with `;`:

```rux
var tries = 5;
do {
    tries--;
} while tries > 10;
```

The condition is false from the start, but `tries` is still decremented once, to 4. A `continue` in the body goes straight to the test.

## loop

`loop` repeats until something leaves it — a [`break`](/docs/lang/statements/break-continue), a [`return`](/docs/lang/statements/return), a [`throw`](/docs/lang/errors/overview), or a panic. It says "until I stop it" more directly than `while true`:

```rux
var n = 0;
loop {
    n += 1;
    if n == 4 {
        break;
    }
}
```

## for

`for` runs its body once for each element of a sequence, binding the element to the loop variable:

```rux
let values = [10, 20, 30];
for v in values {
    PrintLine("{}", v);
}
```

The subject is evaluated once, before the first pass. What `for` can iterate:

| Subject                               | Elements                                                  |
| ------------------------------------- | --------------------------------------------------------- |
| a fixed-size array `T[N]`             | each element, in order                                    |
| a slice `T[..]`                       | each element, in order                                    |
| a string literal or other `char8[..]` | each `char8` code unit — a byte of UTF-8, not a character |
| a range `a..b`, `a..=b`               | each integer from `a`, up to `b` exclusive or inclusive   |
| an open range `a..`                   | each integer from `a`, until the loop is left             |
| an iterator, `Next`                   | each value its `Next` returns                             |
| a container lent as `&items`          | each value of the iterator its `Iterate` returns          |
| a named owning container `items`      | each value of the iterator its `IntoIterator` returns     |

```rux
for k in 0..3 {
    Print("{} ", k);
}
for k in 0..=3 {
    Print("{} ", k);
}
```

This prints `0 1 2 0 1 2 3`. An inclusive range visits its end last and stops there, even when the end is its type's maximum, so `for v in start..=255` over `uint8` never wraps around. A range whose start is past its end runs zero times. When both ends are constants, the compiler catches it instead: `for k in 5..2` is `error: range start cannot be greater than its end`. See [Ranges](/docs/lang/ranges/overview).

Any other type is iterated through the iterator convention: an iterator declares `func Next(&var self) -> Item?` in its `extend` block, and a container hands out iterators. Each pass calls `Next` once; a present result is the element, and only the outer `none` ends the loop.

A loop takes its subject as [`match`](/docs/lang/patterns/match#ownership-of-the-subject) does. `for item in &items` lends the container to its parameterless `Iterate`, and the container keeps its elements; `for item in items` over a named owning container takes the container and its elements through its parameterless `IntoIterator`, and whatever the loop does not reach is destroyed with the iterator:

```rux
import Allocator::SystemAllocator;
import Collections::Vector;
import Io::PrintLine;

func Main() -> int {
    var numbers = Vector<int>::New(SystemAllocator::New());
    numbers.Push(1);
    numbers.Push(2);
    for n in &numbers {
        PrintLine("{}", n);           // 1, 2
    }
    PrintLine("{}", numbers.Length());   // 2
    for n in numbers {
        PrintLine("took {}", n);      // took 1, took 2
    }
    return 0;
}
```

After the second loop `numbers` has been given away. A container whose type declares no `IntoIterator` can only be lent:

```
error: 'for' takes 'bag' and its elements, and 'Bag' declares no 'IntoIterator'
  help: lend them with '&bag'
```

An iterator the loop names as a place — a variable, a field, an element — is advanced where it is, so a loop that stops early leaves it where the walk stopped; the place must therefore be writable, and `for x in counter` over a `let counter` is `error: cannot advance immutable iterator 'counter'`. Any other iterator, such as a call's result, is a temporary the loop advances. See [Iteration](/docs/lang/interfaces/iteration).

```rux
for left in countdown {
    Print("{} ", left);
}
```

A type with neither is refused:

```
error: cannot iterate over 'int'
  help: iterate an array, a slice, a range, or a type declaring 'Next' or 'Iterate'
```

### The loop variable

The loop variable is fresh on every pass and immutable: `i = 10;` inside `for i in 0..3` is `error: cannot modify immutable variable 'i'`, and it cannot be declared `var`. Bind a mutable copy inside the body when one is needed.

It may also be a pattern that matches every element — names, `_`, and tuples and structures made of them — which takes each element apart:

```rux
for (key, value) in pairs {
    PrintLine("{} {}", key, value);
}
for Point { x, y } in points {
    PrintLine("{} {}", x, y);
}
```

The element is given to the pattern, so an owning part is the body's to keep or let go of. A pattern that could fail to match, such as `value?` or `(0, value)`, is `error: a 'for' pattern must match every element`; bind the element and test it in the body with `if let` or `if item is …` instead.

Over an array or a slice, each pass gets a copy of its element, destroyed at the end of the pass, so the sequence keeps its elements. Only plain data copies, so a direct loop over [move-only](/docs/lang/ownership/copy-and-move) elements, such as `String`s, is refused; loop over the indices and borrow each element in place:

```
error: 'for' cannot copy elements of move-only type 'Handle' out of 'Handle[..]'
  note: a direct loop over an array or a slice gives each pass a copy of its element
  help: loop over the indices and borrow each element in place
```

## Giving a value away inside a loop

A loop body runs again from where its last pass ended, so a value one pass gives away is not there for the next. Giving an outer variable away inside a loop is an error unless the same pass gives it a new value before the loop repeats, or leaves the loop with `break`, `return` or `throw` after giving it away:

```rux
for i in 0..3 {
    Consume(buffer);
}
```

```
error: 'buffer' is given away inside a loop, and the next pass would use it again
  help: give 'buffer' a new value before the pass ends, or leave the loop after giving it away
```

The loop variable, and bindings declared inside the body, are new on every pass and may be given away freely. See [Copy and move](/docs/lang/ownership/copy-and-move).
