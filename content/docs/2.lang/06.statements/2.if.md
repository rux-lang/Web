# if

`if` runs a block when a condition is `true`. `else if` tests further conditions in turn, and a final `else` runs when none of them held. The first branch whose condition is `true` runs, and the rest are skipped.

```text
if-statement = "if" condition block
               { "else" "if" condition block }
               [ "else" block ]
condition    = expression
             | ( "let" | "var" ) pattern "=" expression { "&&" expression }
```

```rux
if x > 0 {
    PrintLine("positive");
} else if x < 0 {
    PrintLine("negative");
} else {
    PrintLine("zero");
}
```

## The condition

The condition is a `bool`, written without parentheses, and a structure literal inside it is wrapped in parentheses: the rules every condition follows, set out in [Statements](/docs/lang/statements/overview#conditions). Combine tests with the [logical operators](/docs/lang/expressions/logical):

```rux
if age >= 18 && hasTicket {
    Admit();
}
```

A [type or pattern test](/docs/lang/sums/type-tests) with `is` is a `bool` too, so `if shape is Circle { … }` and `if shape is .Circle(_) { … }` read naturally. A test only answers the question: it binds nothing, and the value keeps its type afterwards. Naming a binding after `is` is an error that points at `if let`:

```
error: 'is' tests and does not bind 'radius'
  help: bind with 'if let', as in 'if let .Case(name) = subject { ... }', or write '_' to test only
```

An optional is not tested with `is` either — `entry is int` is `error: 'is' does not test an optional` — but compared with `none`: `if entry != none { … }`.

## if let

A condition may start with `let pattern = subject`. The subject is evaluated once and matched against the pattern; when it matches, the names the pattern declares are bound and the branch runs, and when it does not, the `else` branch runs. Any pattern a [`match`](/docs/lang/patterns/match) arm takes is allowed, and the pattern needs no coverage: a value it does not match is simply the `else` case.

```rux
import Io::PrintLine;

variant DigitError {
    Blank,
    NotADigit(char)
}

struct User {
    name: char8[..];
    active: bool;
}

func Find(id: int) -> User? {
    if id == 1 {
        return User { name: "ada", active: true };
    }
    return none;
}

func Main() -> int {
    if let user? = Find(1) && user.active {
        PrintLine("hello, {}", user.name);   // hello, ada
    } else {
        PrintLine("nobody");
    }
    let error = DigitError::NotADigit('x');
    if let .NotADigit(c) = error && c != ' ' {
        PrintLine("not a digit: {}", c);     // not a digit: x
    }
    return 0;
}
```

The [presence pattern](/docs/lang/patterns/patterns#absence-and-presence) `name?` binds the value of an optional, so `if let user? = Find(1)` runs its branch only when `Find` found someone. A plain name would bind the whole optional and test nothing, so it is refused:

```
error: 'if let' binds the value of an optional, and the pattern has no '?'
  help: add '?' after the name, as in 'if let name? = ...'
```

A typed pattern selects a member of a [sum](/docs/lang/sums/overview), as in `if let circle: Circle = shape { Draw(circle); }`, and a case pattern selects a variant case and binds its payload.

### Further conditions

The subject ends at the first `&&` outside parentheses. Further conditions follow with `&&`, and they see the bound names: `if let user? = Find(id) && user.active` tests `active` only once a user was found. The names are in scope in those conditions and in the branch. They are not in scope in an `else` branch or after the statement.

A binding comes first in a condition and never combines with `||`, since its names would then be in scope where nothing was bound:

```
error: a binding does not combine with '||', because its names would be in scope where nothing was bound
  help: put the binding first and join further conditions with '&&'
```

A binding written anywhere else — after `||`, or as an operand of another operator — is `error: a binding comes first in an 'if' or 'while' condition, and never after '||' or as an operand`.

### if var

`var` in place of `let` makes the bound names mutable inside the branch:

```rux
if var count? = FindCount(line) {
    count += 1;
    Store(count);
}
```

The names are new bindings: writing them changes nothing in the subject. Over a named plain-data local, `if var` binds a copy, which the body may write while the local keeps its value:

```rux
let count: int? = 3;
if var n? = count {
    n += 1;
    PrintLine("{}", n);          // 4
}
PrintLine("{}", count ?? 0);     // 3
```

### What happens to the subject

`if let` takes its subject as [`match`](/docs/lang/patterns/match#ownership-of-the-subject) does. A temporary, such as a call's result, belongs to the bindings, and what they leave is destroyed. A named local that owns resources is taken too: after `if let t? = taken { … }`, reading `taken` is `error: 'taken' is used after it was given away`. To keep it with its owner, lend it: `if let t? = &taken { … }` binds `t` to the value where it lies, and `taken` keeps its value after the statement. Plain data is copied, so its owner keeps it either way. The subject's own type never changes: only the bound names carry the payload.

## Bodies

Every branch is a block, even for a single statement, and the braces are what end the condition. A binding declared in a branch lasts until that branch's closing brace.

## if as a value

The same `if` is also a value wherever an expression is expected: each branch is a block that yields the expression it ends with when that expression has no `;`, and the `else` is required. It takes the place of the conditional operator `c ? a : b`, which Rux does not have — see [Conditional values](/docs/lang/expressions/conditional):

```rux
let label = if count == 1 { "item" } else { "items" };
let size = match count {
    0 => "none",
    1 => "one",
    _ => "many"
};
```

An `if` with a binding is a value like any other: `let ready = if let v? = entry && v == 3 { true } else { false };`.

An `if` at the start of a statement is the statement, and its value is not used: a branch may end with an expression that yields `()`, such as a call that returns nothing, without its `;`, but a branch that ends with any other value is `error: this branch yields a value of type 'int' that is not used`, with `help: add ';' or use the value`. An `if` that ends a value block and yields a value is that block's value.

A `var` declared without a value and assigned in each branch works too; the compiler checks that every branch does — see [Initialization](/docs/lang/bindings/initialization).

## if and when

`when` has the same shape as `if` but is decided by the compiler, which keeps only the branch it selects — see [Conditional compilation](/docs/lang/comptime/conditional). A chain keeps the keyword it starts with:

```
error: expected 'if' after 'else' in a run-time 'if' chain; 'when' is the compile-time conditional
```
