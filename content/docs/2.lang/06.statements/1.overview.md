# Statements

A function body is a block: a sequence of statements between `{` and `}`, run in order. Every statement is one of these:

| Statement                                       | Form                       | Page                                                       |
| ----------------------------------------------- | -------------------------- | ---------------------------------------------------------- |
| Binding                                         | `let x = …;` `var x = …;`  | [Bindings](/docs/lang/bindings/overview)                   |
| Constant                                        | `const X = …;`             | [Constants](/docs/lang/bindings/constants)                 |
| Expression                                      | `expression;`              | below                                                      |
| Block                                           | `{ … }`                    | [below](#blocks)                                           |
| `if`, `if let`                                  | `if c { … } else { … }`    | [if](/docs/lang/statements/if)                             |
| `when`                                          | `when c { … }`             | [Conditional compilation](/docs/lang/comptime/conditional) |
| `match`                                         | `match v { … }`            | [match](/docs/lang/patterns/match)                         |
| `while`, `while let`, `do while`, `loop`, `for` | `while c { … }` …          | [Loops](/docs/lang/statements/loops)                       |
| `break`, `continue`                             | `break;` `continue label;` | [break and continue](/docs/lang/statements/break-continue) |
| `return`                                        | `return value;`            | [return](/docs/lang/statements/return)                     |
| `throw`                                         | `throw error;`             | [Errors](/docs/lang/errors/overview)                       |
| `defer`                                         | `defer statement`          | [defer](/docs/lang/ownership/defer)                        |
| `destroy`                                       | `destroy place;`           | [Ending a value](/docs/lang/ownership/ending)              |

## Expression statements

An expression followed by `;` is a statement, run for its effect: a call, an assignment, an increment.

```rux
PrintLine("hello");
total += price;
count++;
```

The `;` is required. When something else follows a complete expression, the compiler names it: `error: expected ';' after expression, but found ':'`.

A call that can [fail](/docs/lang/errors/overview) is never written as a bare statement, so its error can never be lost: `Save(config)!;` passes the error on, `Save(config) !!;` drops it, and `Save(config) catch { e => Report(e) };` handles it. Bare, it is refused:

```
error: 'Save' can fail with 'IoError', and the result is not used
  help: pass the error on with '!', ignore it with '!!;', or handle it with 'catch { ... }'
```

An `if`, a `match` or a block at the start of a statement is the statement, ended by its `}`, and its value is not used: a branch or arm that ends with a value other than `()` is an error, `this branch yields a value of type 'int' that is not used`, whose help reads `add ';' or use the value`. To use such a value there, bind it or wrap the expression in parentheses.

## Blocks

A block, `{ … }`, is the body of a function, an `if` branch, a loop, or a `match` or `catch` arm, and it is also a statement of its own. Its bindings end at its `}`, where its locals are destroyed, so a block limits how long a value lives:

```rux
let x = 1;
{
    let y = 2;
    PrintLine("{}", x + y);   // 3
}
```

`y` is not in scope after the block. A block written as a statement yields nothing, so a last expression without `;` is `error: this block yields a value of type 'int' that is not used`. In value position the same block yields that expression, as in `let doubled = { let base = Measure(); base * 2 };` — see [Plain value blocks](/docs/lang/expressions/conditional#plain-value-blocks).

A body is always a block, even when it holds one statement: `if ready return 1;` is `error: expected '{' to start the 'if' body before 'return'`.

## Conditions

`if`, `while` and `do while` test a condition, as does an `if` used as a value, and every condition follows the same rules. An `if` or `while` condition may also start with a binding, `let pattern = subject`, which [`if let`](/docs/lang/statements/if#if-let) describes.

**It is a `bool`.** A number, a pointer or an optional is never true or false by itself:

```rux
let count: int32 = 3;
if count {
}
```

```
error: condition for 'if' must have type 'bool', but found 'int32'
```

Write the test: `if count != 0`. An optional is tested with `found != none`, or taken apart with [`if let`](/docs/lang/statements/if#if-let), which also names its payload: `if let value? = found { … }`.

**It needs no parentheses.** `if count > 0 { … }` is the usual form. Parentheses are allowed, as around any expression, but add nothing: `if (count > 0) { … }` means the same.

**A structure literal inside it is parenthesised.** After `if`, `while`, `for … in`, `match` and `when`, the first `{` that could start the body does start the body. The same holds for a block used as a value. So `Point { x: 1, y: 2 }` cannot appear bare in a condition — its brace would be taken as the body:

```rux
if p == (Point { x: 1, y: 2 }) {
    PrintLine("at the start");
}
```

Without the parentheses the compiler reports `error: expected ';' after expression, but found ':'` at the first field. A structure literal inside a call's argument list needs no extra parentheses, since the call's own parentheses already enclose it.
