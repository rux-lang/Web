# return

`return` ends the function it is in and hands a value back to the caller.

```text
return-statement = "return" [expression] ";"
```

```rux
func Sign(n: int32) -> int32 {
    if n < 0 {
        return -1;
    }
    match n {
        0 => return 0,
        _ => return 1
    }
}
```

## With and without a value

A function with a return type returns a value of that type; one without a return type returns with a bare `return;`, or simply by reaching the end of its body:

```rux
func Log(message: char8[..]) {
    if message.length == 0 {
        return;
    }
    PrintLine("{}", message);
}
```

| Mistake                                     | Error                                                            |
| ------------------------------------------- | ---------------------------------------------------------------- |
| a value of the wrong type                   | `'return' value must have type 'int', but found 'char8[..]'`     |
| a value from a function with no return type | `'return' cannot have a value in a function with no return type` |
| no value from a function with a return type | `'return' requires a value of type 'int'`                        |

The value takes its type from the function the way an annotated binding does: an unsuffixed literal takes the return type, and a narrower integer widens to it.

In a function that can fail, declared [`-> T ! E`](/docs/lang/errors/overview), `return value;` completes with the success and `throw error;` leaves with an error. A function declared `-> !E`, which can fail but returns no value, completes with `()` when it returns or falls off its end.

## Every path returns

A function with a return type must return on every path through its body. The compiler follows each branch, and one that can reach the closing brace is an error:

```rux
func Positive(x: int) -> int {
    if x > 0 {
        return 1;
    }
}
```

```
error: function 'Positive' must return a value of type 'int' on every control-flow path
```

A path that cannot continue counts as finished: a `match` whose every arm returns, a `loop` with no `break`, a call to `Panic` or to any function marked [`#NoReturn`](/docs/lang/attributes/noreturn):

```rux
import Core::Diagnostics::Panic;

func Day(n: uint) -> char8[..] {
    if n < 7 {
        return "weekday";
    }
    Panic("no such day");
}
```

## Returning a move-only value

`return name;` uses `name` by value, like any other use: plain data is copied into the result, and a local or a parameter that owns resources or is marked `#NoCopy` is given away to the caller. Nothing marks the difference:

```rux
#NoCopy
struct Token {
    id: int;
}

func Pass(token: Token) -> Token {
    return token;
}
```

A freshly made value, such as a structure literal or the result of a call, is given away the same way. Only a whole local, a parameter or a temporary can be given away, so returning a field of an owning value, or a value reached through a loan, is refused:

```
error: 'token' is a field of 'pair' and cannot be given away by itself
  help: take it with 'Replace(&var pair.token, value)' or 'Swap', or take 'pair' apart with a pattern
```

See [Copy and move](/docs/lang/ownership/copy-and-move).

## return and defer

`return value;` evaluates `value` exactly once, then runs the function's deferred statements, newest first, and only then leaves. An error leaving through the function's error side runs them the same way, after the error has been captured. Changes a deferred statement makes to a local after that point do not alter the value already captured. See [defer](/docs/lang/ownership/defer).

## Inside expressions

`return`, with or without a value, may also stand where an expression would leave rather than produce one: as a whole `match` or `catch` arm, as the fallback of [`??`](/docs/lang/optionals/coalescing), or as the replacement of [`!!`](/docs/lang/errors/fallible-values):

```rux
variant ParseError {
    Empty
}

func Parse(text: char8[..]) -> int ! ParseError {
    if text.length == 0 {
        throw .Empty;
    }
    return text.length as int;
}

func First(values: int32[..]) -> int32 {
    let found: int32? = if values.length > 0 { values[0] } else { none };
    let v = found ?? return -1;
    return v;
}

func Port(text: char8[..]) -> int {
    let port = Parse(text) !! return 8080;
    return port;
}
```

Anywhere else it is `error: 'return' cannot be used as a value here`.
