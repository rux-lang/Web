# Handling Errors

A function that calls a [function that can fail](/docs/lang/errors/overview) either handles the error itself or passes it on. This page covers handling it, at the call, with `catch` or `!!`. Passing it on with `!` is [Passing errors on](/docs/lang/errors/propagation), and keeping the whole outcome for later is [Fallible values](/docs/lang/errors/fallible-values).

```text
catch-expr   = expr "catch" "{" match-arm { "," match-arm } [ "," ] "}"
replace-expr = expr "!!" fallback
discard-stmt = expr "!!" ";"
```

| Form               | The error goes                                 | The result                                |
| ------------------ | ---------------------------------------------- | ----------------------------------------- |
| `x catch { arms }` | to the arms                                    | the success, or what the arm produced     |
| `x !! v`           | nowhere: `v` stands in for the success         | the success, or `v`                       |
| `x !! none`        | nowhere: absence stands in                     | the success made present, `T?`, or `none` |
| `x !! return r`    | nowhere: the function returns `r`              | the success                               |
| `x !!;`            | nowhere: the error and the success are dropped | none — it is a statement                  |

## catch

`catch` hands the error of the expression before it to arms that match it. A success passes through unchanged and no arm runs; the value of the whole expression is the success:

```rux
variant DigitError {
    Blank,
    Letter(char)
}

func Lenient(c: char) -> int {
    return ReadDigit(c) catch {
        .Blank => 0,
        .Letter('O') => 0,
        .Letter(_) => -1
    };
}
```

- The arms are exactly the arms of `match error { ... }`: patterns, the `_` default, `|` alternatives, guards, [typed patterns](/docs/lang/sums/patterns) over an error sum, block arms, and a trailing comma. See [Match](/docs/lang/patterns/match). The braces are always written.
- The arms must cover every error:

  ```text
  error: 'catch' arms do not cover every error of type 'DigitError'; missing DigitError::Letter
    help: add a '_' arm, or bind the whole error, as in 'e => ...'
  ```

- Each arm either produces a value that converts to the **success type** or leaves through `throw`, `return`, `break`, `continue`, a call to [`Panic`](/docs/lang/errors/panics) or a [`#NoReturn`](/docs/lang/attributes/noreturn) function. A leaving arm never decides the result type.
- The type the context expects of the whole expression reaches the operand and every arm, so a case written without its type takes it, and `let r: int? = F() catch { _ => none };` makes the success present.

When the error is a sum, typed patterns tell its members apart:

```rux
func LoadWithDefaults(step: int) -> Options | Defaults ! IoError {
    return Read(step) catch {
        _: ParseError => Defaults {},
        e: IoError => throw e
    };
}
```

### Passing an error on from an arm

Nothing is passed on implicitly: an error that the arms do not want is passed on by an arm of its own, `e => throw e`. An arm is outside its handler, so its `throw` — and an `x!` written in it — leaves the function, and the same `catch` never sees it again:

```rux
func Strict(c: char) -> int ! IoError {
    let digit = ReadDigit(c) catch { _ => throw IoError { code: 22 } };
    return digit * 2;
}
```

Converting the error on the way out — adding context, or mapping it to the function's own error type — is the same kind of arm; see [Mapping errors](/docs/lang/errors/propagation#mapping-errors).

### Block arms

An arm whose body is a block `{ … }` yields the expression it ends with, written without a `;`. A block that ends otherwise completes with `()`, which is valid only where the success is the unit — unless the block ends by leaving:

```rux
let digit = ReadDigit(c) catch {
    e => {
        PrintLine("not a digit");
        0
    }
};
```

Where the success has a value, an arm that completes with `()` is rejected rather than inventing one:

```text
error: a block arm completes with '()', but 'catch' must produce a value of type 'int32'
  help: end the block with the value written without a ';', or leave it with 'throw', 'return', or a call to 'Panic'
```

### A catch statement

A `catch` written as a whole statement drops the success, and its arms run for their effect, as the arms of a match statement do. It ends with a `;`, like any expression statement:

```rux
Close(false) catch {
    e => PrintLine("close failed with {}", e.code)
};
```

## A fallback for every error

`x !! fallback` is the counterpart of [`??`](/docs/lang/optionals/coalescing) for an error: the success, or `fallback` for any error. The fallback converts to the success type, and it is evaluated only when there is an error:

```rux
let digit = ReadDigit(c) !! 0;
let first = ReadDigit(a) !! ReadDigit(b) !! 0;   // tries each in turn
```

A chain `a !! b !! c` tries each operand from the left; every one but the last may itself fail. The fallback may also leave, as a `??` fallback can:

| Fallback                  | On an error                         |
| ------------------------- | ----------------------------------- |
| `!! value`                | the result is `value`               |
| `!! return r`             | the function returns `r`            |
| `!! break`, `!! continue` | the loop ends or moves on           |
| `!! throw e`              | the function fails with `e` instead |
| `!! Panic(msg)`           | the program stops                   |

```rux
func Early(c: char) -> int {
    let digit = ReadDigit(c) !! return -1;
    return digit + 100;
}

let trusted = ReadDigit('8') !! Panic("a literal digit always reads");
```

### From an error to absence

`x !! none` replaces an error with absence, so the result is the success made optional. It keeps an optional success at its own level: absence and an error become the same `none`.

| The operand is | `x !! none` gives |
| -------------- | ----------------- |
| `T ! E`        | `T?`              |
| `T? ! E`       | `T?`              |
| `() ! E`       | `()?`             |

```rux
let maybe = ReadDigit(c) !! none;              // int?
let value = (ReadDigit(c) !! none) ?? 4;
```

## Precedence

`!!` and `catch` bind as loosely as `??`: each takes **everything to its left**. In `1 + ReadDigit(c) !! 0`, the left operand of `!!` is the whole sum, so the `+` meets a fallible and is refused; group the handled call:

```rux
let total = 1 + (ReadDigit('4') !! 0) * 10;   // 41
```

`!!` or `catch` mixed with `??` needs parentheses too, because each would otherwise take the other as part of its operand:

```text
error: '!!' and '??' are mixed without parentheses
  help: group one of them, as in '(x !! none) ?? fallback'
```

The postfix `x!` is the opposite: it binds tightly, to the call it follows. Evaluation stops at the first step that fails, so nothing to its right runs. See [Passing errors on](/docs/lang/errors/propagation). Each form needs an operand that can fail; on a plain value it is refused, as `'!!' replaces an error, and 'int' has none` or `'catch' handles an error, and 'int' has none`.

## Ignoring an error

A call left unhandled is an error, so an error is never dropped by accident. Ignoring one is always written out:

| Write                    | For                                                |
| ------------------------ | -------------------------------------------------- |
| `F() !!;`                | any call: the error and the success are dropped    |
| `F() !! fallback`        | a call with a value, when the error has a stand-in |
| `F() catch { _ => {} };` | a call that returns nothing                        |

```rux
Close(file) !!;
```

`x !!;` is a statement of its own; a success it drops is destroyed there.

::note
**PrintLine does not fail.**\
`Io::PrintLine` returns `IoError?` — an optional that reports a console write problem, not a fallible. An optional may be ignored, which is why `PrintLine(…);` is a valid statement with nothing after it.
::

## Cleanup and finally

There is no `finally`, and the word is reserved:

```text
error: 'finally' is not supported
  help: use 'defer'
```

Cleanup that must run on every exit is a [`defer`](/docs/lang/ownership/defer) or a [destructor](/docs/lang/ownership/destructors), which run when an error leaves their scope as they do on a return.

A deferred statement and a destructor run while their scope or value is already being left, so no error may leave either. A call in them that can fail is handled with `!!` or `catch`; an `x!` or a `throw` there is refused:

```text
error: an error cannot leave a deferred statement
  note: a deferred statement runs while its scope is already being left
  help: handle it with '!!' or 'catch { ... }'
```

A destructor gets the same error, naming `a destructor`.

## Several calls, one handler

There is no block form of `catch`: each handler takes the error of one expression. Statements whose errors one set of arms should take go in a function of their own, which passes each error on with `!`, and that function's call is handled once:

```rux
func Configure(path: char8[..]) -> !IoError | ParseError {
    let options = Parse(ReadText(path)!)!;
    Apply(options);
}

func Main() -> int {
    Configure("app.toml") catch {
        _: IoError => PrintLine("cannot read the configuration"),
        _: ParseError => PrintLine("the configuration is malformed")
    };
    return 0;
}
```

## Ownership

- The state of each local at the handled call is the state the arms start from.
- An arm reads and moves the surrounding locals under the ordinary rules. A local given away only inside an arm that leaves is still owned on the path that continues after the handler.
- An arm that binds the error owns it and destroys it at its end, unless it gives it away; an error no arm binds is destroyed when its arm is chosen. An error whose move is prohibited cannot be bound by value.
- A success that a form drops — `x !!;` or a `catch` statement — is destroyed where it is dropped.

## Idioms

| Wanted                                      | Write                                                                                                            |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| a fallback value for any error              | `F() !! fallback`                                                                                                |
| a fallback per kind of error                | `F() catch { .A => …, .B => … }`                                                                                 |
| an expected success, where failure is a bug | `F() !! Panic("why it cannot fail")`                                                                             |
| translate the error and keep failing        | `F() catch { e => throw Wrap(e, context) }` — see [Mapping errors](/docs/lang/errors/propagation#mapping-errors) |
| pass the error on unchanged                 | [`F()!`](/docs/lang/errors/propagation)                                                                          |
| leave the function on an error              | `F() !! return value`                                                                                            |
| ignore the error and the result             | `F() !!;`                                                                                                        |
| drop the error, keep an optional            | `F() !! none`                                                                                                    |
| store the outcome                           | `let kept = F();` — see [Fallible values](/docs/lang/errors/fallible-values)                                     |
| cleanup on every exit                       | `defer`                                                                                                          |
