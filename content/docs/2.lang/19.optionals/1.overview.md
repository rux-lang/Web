# Optionals

An _optional_ `T?` holds either a present value of type `T` or nothing: _absence_, written `none`. It is a compiler-owned type: no package declares it, it has no methods, and the compiler makes sure absence is dealt with before the value inside is used.

```text
optional-type = type "?"
```

## The type

`?` is a postfix type suffix. Like `[N]` and `[..]`, it binds tighter than every other type operator, so it applies to the type immediately before it. Group with parentheses to put it anywhere else:

| Type               | Meaning                                         |
| ------------------ | ----------------------------------------------- |
| `int32?`           | an optional `int32`                             |
| `int32??`          | an optional of an optional `int32` (two levels) |
| `int32?[..]`       | a slice of optional `int32` values              |
| `int32[..]?`       | an optional slice                               |
| `*int32?`          | a pointer to an optional, `*(int32?)`           |
| `(*int32)?`        | an optional pointer                             |
| `(int32 \| bool)?` | an optional [sum](/docs/lang/sums/overview)     |
| `int32 \| (bool?)` | a sum with an optional member                   |

A `?` never reaches across `|`, so an optional member and an optional sum must be grouped, and neither does it reach across the `!` of a [fallible](/docs/lang/errors/fallible-values): an optional error is written `T ! (E?)`. Without the parentheses the compiler stops:

```text
error: an optional sum member must be grouped
  help: write 'A | (B?)' for an optional member, or '(A | B)?' for an optional sum
error: '?' cannot reach across '!'
  help: write 'T ! (E?)' for an optional error, or '(T ! E)?' for an optional result
```

Any type can be the payload: a struct, a slice, a pointer, a sum, the unit `()` (a `()?` is just "present or not"), and another optional.

## Levels never collapse

`T??` is not `T?`. Each level has its own absence, so an `int32??` has three distinct values:

| State             | Meaning                             | Pattern   |
| ----------------- | ----------------------------------- | --------- |
| absent            | no value at the outer level         | `none`    |
| a present absence | present, holding an absent `int32?` | `none?`   |
| a present value   | present, holding a present `int32`  | `value??` |

This is what lets a lookup tell "there is no such key" from "the key is there, and its value is absent", and an iterator tell "there are no more items" from "the next item is an absent value".

## Writing an optional value

An optional has no case to write. A value is made present by putting it where an optional is expected, and `none` is absence:

```rux
let count: int32? = 4;        // a plain value where an optional is expected is present
let missing: int32? = none;   // absence
let wrapped: int32?? = count; // present, holding a present 4
let hollow: int32?? = missing; // present, holding an absence
```

- **A plain value.** Where an optional is expected (an annotated `let`, an assignment, an argument, a `return` in a function returning `T?`), a value of type `T` is made present. The same happens one level up: an `int32?` placed where an `int32??` is expected becomes present, whether it holds a value or not, so a present absence is written as an absent `int32?` converted outward, as `hollow` is.
- **`none`** is the absence of the _outer_ level of the optional the context expects, never of a level inside it. In a function declared `-> int32? ! E`, `return none;` returns an absent value; it does not fail.

`none` carries no type of its own, so it needs a context:

```text
error: cannot infer the type of 'absent' from 'none'
  help: annotate the optional type, as in 'let value: int32? = none;'
```

A case spelling is not a way to write one, because an optional has no cases:

```text
error: an optional has no case '.Some'
  help: write the value itself, which converts to the optional
```

An optional payload can also widen: an `A?` converts to `(A | B)?`, keeping absence absent. The [sum](/docs/lang/sums/overview) rules apply to the payload.

An annotation gives its type to every arm of a `match` expression and every branch of an `if` value, so `none` and a plain value can stand side by side: in `let r: int32? = match n { 0 => none, _ => n };` the first arm is absent and the second is present.

### `null` is not absence

`null` is the null raw [pointer](/docs/lang/pointers/overview), and it is not a value of any optional type:

```text
error: 'null' is not a value of type 'int32?'
  help: write 'none' for an absent optional
```

A raw pointer may be the payload of an optional, `(*T)?`, when a pointer that might not be there should be checked like any other optional. See [Optional pointer](/docs/learn/optional-pointer).

## Matching

An optional is opened with an ordinary [`match`](/docs/lang/patterns/match). Its _presence patterns_ select one level at a time:

| Pattern      | Matches                                                            |
| ------------ | ------------------------------------------------------------------ |
| `v?`         | a present value, binding its payload to `v`                        |
| `p?`         | a present value whose payload matches the pattern `p`              |
| `0?`         | a present value equal to `0`                                       |
| `none`       | absence of the level being matched                                 |
| `v??`        | two present levels, binding the inner payload                      |
| `none?`      | a present absence                                                  |
| `none \| 0?` | absence or a present `0`; alternatives combine levels              |
| `v: T`       | a present value whose payload has type `T`, binding it (one level) |
| `_?`         | any present value                                                  |
| `_`          | any state                                                          |

```rux
func Find(values: int32[..], wanted: int32) -> uint? {
    for i in 0..values.length {
        if values[i] == wanted {
            return i;
        }
    }
    return none;
}

func Describe(found: uint?) -> char8[..] {
    return match found {
        0? => "at the front",
        index? => "further in",
        none => "missing"
    };
}
```

Every level must be covered. A nested optional needs an arm for each of its states:

```rux
func Lookup(key: int32) -> int32?? {
    if key == 0 {
        return none;
    }
    if key == 1 {
        let absent: int32? = none;
        return absent;
    }
    return key * 10;
}

func Classify(found: int32??) -> char8[..] {
    return match found {
        value?? => "a value",
        none? => "a present absence",
        none => "absent"
    };
}
```

A typed presence pattern takes exactly one level and leaves the rest to the arm:

```rux
func Typed(found: int32??) -> int32 {
    return match found {
        stored: int32? => stored ?? -1,
        none => -2
    };
}
```

A match that leaves a state out names it, spelled as the pattern that would take it:

```text
error: match on 'int32?' is not exhaustive; missing none
error: match on 'int32?' is not exhaustive; missing _?
error: match on 'int32??' is not exhaustive; missing none?
```

A case pattern does not match an optional either: `error: an optional has no case '.Some'`, with `help: match a present value with 'name?', as in 'value? => ...'`.

## if let

When only the present value needs code, `if let` binds it without a whole `match`. The condition starts with `let pattern = subject`; the body runs when the pattern matches, and the names it binds are in scope there:

```rux
if let index? = Find(values, 7) {
    PrintLine("found at {}", index);
}
if let index? = Find(values, 7) && index > 0 {
    PrintLine("not at the front");
}
if let inner?? = wrapped {
    PrintLine("two levels deep: {}", inner);
}
```

- `while let item? = reader.Next() { … }` runs its body for every present value and stops at the first absence.
- `if var n? = Next() { n += 1; … }` binds a name that the body may change.
- Further conditions follow with `&&`, and they see the bound names. A binding comes first and does not combine with `||`, and the bound names are not in scope in an `else` branch or after the statement.
- The pattern must say which level it opens. A plain name is refused, because it would bind the optional itself:

```text
error: 'if let' binds the value of an optional, and the pattern has no '?'
  help: add '?' after the name, as in 'if let name? = ...'
```

See [`if`](/docs/lang/statements/if) for every form of the condition.

## Using the value

An optional is not its payload. It has no arithmetic, no fields, and no `Display`, so `known * 2` with `known: int32?` is `error: operator '*' cannot combine left operand 'int32?' with right operand 'int'`. The value inside is reached in one of these ways:

| Tool                                    | Use it when                                                        |
| --------------------------------------- | ------------------------------------------------------------------ |
| `match`                                 | each state needs its own code                                      |
| [`if let`](#if-let)                     | one state needs code: `if let index? = found { … }` binds `index`  |
| [`??`](/docs/lang/optionals/coalescing) | absence has a stand-in value, or should leave the loop or function |
| [`?`](/docs/lang/optionals/propagation) | absence should make the whole function's result absent             |
| `== none`, `!= none`                    | only presence matters                                              |

`is` does not test an optional. Presence is not a type, so the question is asked with a comparison:

```text
error: 'is' does not test an optional
  help: compare with '== none' or '!= none', or bind the value with 'if let name? = ...'
```

## Equality

`==` and `!=` compare optionals level by level: absent equals absent, and two present values are equal when their payloads are. `x == none` and `x != none` compare no payload, so they work for an optional of any type, even one whose payload has no `==`. A value of the payload type on the other side is made present to compare, which needs `==` on the payload:

```rux
let known: int32? = 5;
let a = known == 5;          // true: the value is made present
let b = known != none;       // true
let c = known == none;       // false
```

## Iteration

The iterator convention is built on optionals: an iterator's `Next` returns `Item?`, and a `for` loop ends at the first outer absence. Because levels never collapse, an iterator whose items are themselves optional returns `Item??`, and an absent item does not end the loop. See [Iteration](/docs/lang/interfaces/iteration).

## No methods

An optional is a compiler-owned form with no declaring package, so it cannot be extended and implements no interface: an `int32?` is not `Display`, even though `int32` is:

```text
error: cannot extend native type 'int32?'
  note: a sum, optional, or unit type has no declaring package to own methods or interface implementations
  help: write a generic function that takes the native type as a parameter
```

A reusable operation on optionals is a generic free function, such as `func OrZero<T>(value: T?, zero: T) -> T`. Inference reaches through `T?` as it does through any generic type.

## Layout

An optional is stored as an 8-byte tag followed by its payload, aligned for the payload; a zero-sized payload takes no room. `sizeof(int32?)` and `sizeof(int64?)` are 16, `sizeof(int32??)` is 24 and `sizeof(()?)` is 8. The tag values are not a stable ABI. See [Layout](/docs/lang/memory/layout).
