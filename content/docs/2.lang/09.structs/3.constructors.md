# Constructors

A _constructor_ is an ordinary static function that builds a value of its type. It is declared in the type's `extend` block, takes no receiver, returns the type — which `Self` names there — and is called through the type by its name: `Time::New(9, 30)`. The everyday one is named `New`; any other gets a name that says what it starts from or what it does, such as `FromMinutes`, `WithCapacity`, `Open` or `Parse`.

```text
constructor = [ "pub" ] "func" Name "(" [ parameters ] ")" "->" ( "Self" | TypeName ) [ "!" type ] block   // inside extend TypeName
```

```rux
import Io::PrintLine;

struct Time {
    hours: int;
    minutes: int;
}

extend Time {
    func New(hours: int, minutes: int) -> Self {
        return Self::FromMinutes(hours * 60 + minutes);
    }

    func FromMinutes(totalMinutes: int) -> Self {
        let inDay = totalMinutes % (24 * 60);
        return Self { hours: inDay / 60, minutes: inDay % 60 };
    }

    func Midnight() -> Self {
        return Self { hours: 0, minutes: 0 };
    }
}

func Main() -> int {
    let start = Time::New(7, 95);                                             // 8:35
    let later = Time::FromMinutes(start.hours * 60 + start.minutes + 135);   // 10:50
    let midnight = Time::Midnight();                                          // 0:00
    PrintLine("{}:{} {}:{}", start.hours, start.minutes, later.hours, later.minutes);
    return 0;
}
```

A constructor ends by building the value itself — usually with a [struct literal](/docs/lang/structs/overview#struct-literals), `Self { … }`, or by calling another constructor, which inside the type's own `extend` block is written `Self::FromMinutes(…)`. It does not replace literals; it decides what goes into one, so a rule such as "minutes are below 60" is written once instead of at every literal. Above, `New` converts to minutes and passes the total to `FromMinutes`, so the wrapping past midnight is written once.

| Kind of function | Name     | First parameter                         | Called as          |
| ---------------- | -------- | --------------------------------------- | ------------------ |
| Method           | anything | `&self`, `&var self`, `self` or `~self` | `start.Show()`     |
| Constructor      | anything | not `self`; returns the type            | `Time::New(9, 30)` |

A constructor takes no receiver, so it is called only through its type. Calling one through a value is refused rather than ignoring the value: `start.FromMinutes(90)` is

```text
error: 'FromMinutes' is an associated function of 'Time' and takes no receiver
  help: call it as 'Time::FromMinutes(...)'
```

A constructor has no rules of its own: it is a static function like `Time::Midnight`, and the language knows it only as one that returns its type. The convention that the everyday one is `New`, and that constructors are not overloaded — a second way to make the value gets a second name — is a convention of Rux packages rather than a rule of the language, and [`rux lint`](/docs/cli/lint) reports `constructor 'New' is overloaded` for a second `New`.

## Calling a type is an error

A type is not a function. Writing its name as if it were one is refused, with the constructor call to write instead:

```rux
let t = Time(9, 30);
```

```
error: 'Time' is a type, not a function
  help: call a constructor by its name, as in 'Time::New(...)'
```

The same holds for `Self(…)` inside an `extend` block and for an instantiated generic type, `Pair<int>(7)`. A function named after its own type is not a constructor either: `func Time() -> Time` inside `extend Time` is `error: a function named after its type 'Time' is not a constructor`, with `help: name it for what it does, as in 'func New(...)'`.

## Nothing is constructed implicitly

`var value: T;` calls no constructor, even when `T::New()` takes no arguments: it declares empty storage that must be assigned before it is read. A value that needs a constructor is written with one:

```rux
var midnight = Time::Midnight();
```

See [Initialization](/docs/lang/bindings/initialization) for how empty storage becomes initialized, whole or field by field.

## Generic types

A generic type's constructor is declared in its generic `extend` block and called through the type with its type arguments written out, as in `Pair<int>::New(1, 2)`. Inside the block, `Self::New(…)` passes the block's own type arguments:

```rux
struct Pair<T> {
    first: T;
    second: T;
}

extend Pair<T> {
    func New(first: T, second: T) -> Self {
        return Self { first, second };
    }

    func Swapped(self) -> Self {
        let Pair { first, second } = self;
        return Self::New(second, first);
    }
}

func Main() -> int {
    let pair = Pair<int>::New(1, 2).Swapped();
    return pair.first;   // 2
}
```

A value of a type parameter is owning inside generic code, so `New` gives each argument away once; using `first` twice would be `error: 'first' is used after it was given away`, whatever `T` turns out to be.

## A convenience, not a lock

A type with constructors can still be built with a literal wherever its fields are visible, so a constructor's rules can be bypassed inside its package. Making the fields private to the package, and the constructor `pub`, leaves other packages only the constructor; see [Visibility](/docs/lang/modules/visibility).

## Constructors that can fail

A constructor that can fail declares its error after the type, `-> Self ! E`, and its call is a [fallible](/docs/lang/errors/fallible-values) like any other call that can fail, taken apart with `!`, `!!` or `catch`:

```rux
import Io::PrintLine;

struct Percent {
    value: int32;
}

variant PercentError {
    OutOfRange(int32)
}

extend Percent {
    func New(value: int32) -> Self ! PercentError {
        if value < 0 || value > 100 {
            throw .OutOfRange(value);
        }
        return Self { value };
    }
}

func Run() -> !PercentError {
    let half = Percent::New(50)!;
    let rejected = Percent::New(150) !! none;   // none
    PrintLine("{} {}", half.value, rejected == none);   // 50 true
}

func Main() -> int {
    Run() !! return 1;
    return 0;
}
```

No value exists unless the constructor returns one: a failed constructor leaves nothing behind to destroy. A lookup that may find nothing is not a failure: it returns `T?`, as in `T::Find(…)`. See [Errors](/docs/lang/errors/overview).

## Rules and errors

| Mistake                                         | Error                                                                                     |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------- |
| Calling a type, `Time(9, 30)` or `Self(…)`      | `'Time' is a type, not a function`                                                        |
| A function named after its type inside `extend` | `a function named after its type 'Time' is not a constructor`                             |
| A free function with the type's name            | `name 'Time' cannot be declared as a function because it is already a type in this scope` |
| Reading `var t: Time;` before assigning it      | `variable 't' is used before it is initialized`                                           |
