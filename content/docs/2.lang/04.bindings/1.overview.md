# Bindings

A _binding_ gives a name to a value. Rux has three kinds, each introduced by its own keyword:

| Keyword | Binds                       | Can change | Computed        | Page                                       |
| ------- | --------------------------- | ---------- | --------------- | ------------------------------------------ |
| `let`   | an immutable run-time value | no         | at run time     | this page                                  |
| `var`   | a mutable run-time value    | yes        | at run time     | this page                                  |
| `const` | a compile-time value        | no         | by the compiler | [Constants](/docs/lang/bindings/constants) |

```text
binding     = ("let" | "var") pattern [":" type] [initializer] ";"
initializer = "=" expression
```

The pattern is usually a single name. It can also take a tuple or a structure apart; see [Destructuring](/docs/lang/bindings/destructuring).

```rux
let answer = 42;
var counter = 0;
counter += 1;
```

## let

`let` binds a value that never changes. The name keeps the value it was given for as long as it is in scope:

```rux
let limit: int32 = 10;
limit = 11;
```

```
error: cannot modify immutable variable 'limit'
  help: declare 'limit' with 'var' to make it mutable
```

Because a `let` can never be assigned later, it must be initialized where it is declared. `let total: int32;` is `error: immutable variable requires an initializer`.

Prefer `let`. A name that cannot change is one less thing for the reader to track, and the compiler rejects an accidental write instead of letting it through.

## var

`var` binds a value that may be replaced. Assignment, the compound operators and `++`/`--` all need a `var` (or another mutable place, such as a field of one):

```rux
var score: int32 = 10;
score = 12;
score += 5;
score++;
```

A `var` may also be declared without a value and assigned later. Until then it holds nothing, and the compiler makes sure no path reads it too early; see [Initialization](/docs/lang/bindings/initialization).

## Types and inference

With an initializer and no annotation, the binding takes the initializer's type. Literals have a default type:

| Initializer              | Inferred type               |
| ------------------------ | --------------------------- |
| `42`, `3000000000`       | `int`                       |
| `1.5`                    | `float64`                   |
| `'A'`                    | `char32`                    |
| `true`                   | `bool`                      |
| `"text"`                 | `char8[..]`                 |
| `7u8`, `2.5f32`, `c8'A'` | the suffix or prefix's type |

An annotation, `: Type`, chooses the type instead. An unsuffixed integer literal then takes the annotated type, provided its value fits:

```rux
let small: uint8 = 200;
let wide: int64 = 5;
```

`let small: uint8 = 300;` is `error: integer literal is out of range for type 'uint8'`.

A binding's type is fixed once it is declared. A value of another type is not converted to fit, with one exception: an integer widens to a wider integer of the same signedness, because no value can change on the way. Every other change of type is written with [`as`](/docs/lang/expressions/casts):

```rux
let narrow: int32 = 7;
let widened: int64 = narrow;
let converted = narrow as float64;
```

The reverse, `let back: int32 = widened;`, is `error: cannot assign 'int64' to 'int32'`.

## Copying and giving away

An initializer is always written with `=`, and nothing marks what happens to the source: that follows from its type.

| Form                 | Meaning                                                                                 |
| -------------------- | --------------------------------------------------------------------------------------- |
| `let b = a;`         | plain data is **copied**: `b` gets its own copy, and `a` is unchanged                   |
| `let b = a;`         | an owning value is **given away**: it belongs to `b` now, and `a` may not be read again |
| `let b = Make();`    | a fresh value belongs to `b` directly; there is no source left behind                   |
| `let b = &a;`        | a **loan**: `b` reads `a` where it is, and `a` keeps its value                          |
| `let b = a.Clone();` | an explicit copy of an owning value, by the convention of a `Clone` method              |

Plain data is numbers, booleans, characters, pointers, views and aggregates of them. A type that owns resources, because it or something it holds has a [destructor](/docs/lang/ownership/destructors), is move-only, so a named value of it is given away:

```rux
import Io::PrintLine;

struct Buffer {
    size: int;
}

extend Buffer {
    destructor {}
}

func Main() -> int {
    let first = Buffer { size: 4 };
    let second = first;
    PrintLine("{}", second.size);   // 4
    return 0;
}
```

Reading `first` after that is an error that says where it went:

```text
error: 'first' is used after it was given away
  help: lend it with '&first' where it is only read, or clone it where both uses need a value
```

Only a whole local, a parameter or a temporary can be given away. A field of an owning value is not taken out by itself: `let taken = holder.item;` is `error: 'item' is a field of 'holder' and cannot be given away by itself`, whose help offers Core's `Replace` and `Swap`, or taking `holder` apart with a [pattern](/docs/lang/bindings/destructuring). The arrow form `let b <- a;` is `error: '<-' is not a binding operator` with `help: write 'let name = source'`. The full rules are in [Copy and move](/docs/lang/ownership/copy-and-move), and loans in [References](/docs/lang/references/overview).

## Mutability

Mutability belongs to the binding and reaches all the way into the value. A `let` structure cannot have any field changed, at any depth; a `var` one can have every field changed, or be replaced whole:

```rux
let fixed = Point { x: 1, y: 2 };
var moving = Point { x: 1, y: 2 };
moving.x = 5;
moving = Point { x: 0, y: 0 };
```

`fixed.x = 5;` is `error: cannot modify immutable variable 'fixed'`. There is no per-field opt-out in either direction. The same holds for tuples and fixed-size arrays.

A function changes a caller's value only through a writable reference, `&var T`, or a writable pointer, `*var T`; see [References](/docs/lang/references/overview) and [Pointers](/docs/lang/pointers/overview). A parameter itself is always immutable; a function that needs mutable local storage gives the argument to a local, as in `var local = value;`.

A reference is never reseated, so a `var` cannot hold one: `var alias = &var count;`, or any `var` whose type is a reference, written or inferred, is `error: 'var' binding 'alias' cannot hold reference '&var int'`, with `help: references cannot be reseated; use a pointer or a new binding`. Bind a loan with `let`, as in `let alias = &var count;`; assigning through it writes the referent.

## Scope

A binding is visible from its declaration to the end of the block that contains it. Declaring the same name twice in one block is an error:

```rux
let total = 1;
let total = 2;
```

```
error: variable 'total' is already declared in this scope
```

Each name a [destructuring](/docs/lang/bindings/destructuring) pattern declares counts separately, so `let (p, p) = (1, 2);` is refused the same way.

A block nested inside another (the body of an `if` or a loop) may declare a name that is already used outside it. The inner binding hides the outer one until the block ends, and the two stay separate bindings: after the inner block the name reads the outer binding's own value again.

```rux
let total = 1;
if ready {
    let total = 2;
    PrintLine("{}", total);   // 2
}
PrintLine("{}", total);       // 1
```

## Discarding a value

`_` is not a name. `let _ = value;` evaluates `value` and throws it away, and nothing can read `_` afterwards; see [Destructuring](/docs/lang/bindings/destructuring#discarding-a-value).
