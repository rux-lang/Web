# Arithmetic

The arithmetic operators compute with integers and floating-point numbers.

| Operator | Operation               | Example  | Level |
| -------- | ----------------------- | -------- | ----- |
| `-`      | negation (prefix)       | `-a`     | 16    |
| `*`      | multiplication          | `a * b`  | 14    |
| `/`      | division                | `a / b`  | 14    |
| `%`      | remainder               | `a % b`  | 14    |
| `+`      | addition                | `a + b`  | 13    |
| `-`      | subtraction             | `a - b`  | 13    |
| `*%`     | wrapping multiplication | `a *% b` | 14    |
| `+%`     | wrapping addition       | `a +% b` | 13    |
| `-%`     | wrapping subtraction    | `a -% b` | 13    |

```rux
let a: int32 = 17;
let b: int32 = 5;
PrintLine("{} {} {} {} {} {}", a + b, a - b, a * b, a / b, a % b, -a);
```

This prints `22 12 85 3 2 -17`. Multiplication, division and remainder bind more tightly than addition and subtraction, and each level groups from the left — see [Precedence](/docs/lang/expressions/overview#precedence).

## Operand types

Both operands must agree on a type, following the [operand rules](/docs/lang/expressions/overview#operand-types): one type, a literal that takes the other operand's type, or two integers of one signedness, where the narrower widens. The result has that type.

An unsuffixed integer literal adapts only to another integer. Beside a floating-point value, write a floating-point literal:

```rux
let half = 1.5 + 2;
```

```
error: operator '+' cannot combine left operand 'float64' with right operand 'int'
```

Write `1.5 + 2.0`. A `bool` is not a number, and `flag + flag` is `error: operator '+' cannot combine left operand 'bool8' with right operand 'bool8'`. To compute with a character's code, convert it with [`as`](/docs/lang/expressions/casts) first, as in `(c as int32) - ('0' as int32)`.

## Integer overflow stops the program

Integer `+`, `-`, `*` and unary `-`, and the compound `+=`, `-=`, `*=`, `++` and `--`, are checked at every width from `int8` to `uint512`, on every target and in every build profile. A result that does not fit the operation's type stops the program, naming the operator as written:

```rux
var top: int8 = int8::Max;
top += 1;
```

```
Panic: integer overflow in '+='
  at Main (Src/Main.rux:2:9)
```

Negation names `'-'`, and nothing is unwound — see [Panics](/docs/lang/errors/panics). An operation whose operands are known while compiling is a compile error instead: `const Sum: uint8 = 200u8 + 100u8;` is `error: integer overflow in '+': the constant result does not fit 'uint8'`. A release build removes a check it can prove passes, such as the counter of a loop bounded by a comparison, so the checks cost little where they cannot fail.

A literal is not allowed to overflow on its way in either: `let narrow: uint8 = 0; narrow + 300` is `error: integer literal is out of range for type 'uint8'`.

## Wrapping arithmetic

The wrapping operators `+%`, `-%` and `*%`, and their compound forms `+%=`, `-%=` and `*%=`, compute the two's-complement result at the operation's type and never stop: a result that does not fit keeps its low bits.

```rux
var top: int8 = int8::Max;
top +%= 1;
let small: uint8 = 0;
let m: uint8 = 200;
PrintLine("{} {} {}", top, small -% 1, m *% 2);
```

This prints `-128 255 144`. `0 -% value` is the negation that wraps at the minimum. The wrapping operators take integer operands only, typed as `+`, `-` and `*` are, so a float, character or pointer operand is an error that names the checked operator to use instead. Hashes, random number generators, checksums and ciphers write their arithmetic with them; everything else keeps the checked forms, so an overflow nobody meant is a report rather than a wrong value.

Where overflow is an expected answer rather than a mistake, Core's integer methods `CheckedAdd`, `CheckedSub` and `CheckedMul` return `none` for a result that does not fit, and `SaturatingAdd`, `SaturatingSub` and `SaturatingMul` clamp to the type's limits — see [Integers](/docs/lang/types/integers#checked-and-saturating-methods) and the Learn lessons [Wrapping arithmetic](/docs/learn/wrapping-arithmetic) and [Checked arithmetic](/docs/learn/checked-arithmetic).

## Integer division

Integer `/` truncates towards zero, and `%` gives the remainder that goes with it, so it has the sign of the dividend:

| Expression | Value |
| ---------- | ----- |
| `7 / 2`    | `3`   |
| `-7 / 2`   | `-3`  |
| `7 % 2`    | `1`   |
| `-7 % 2`   | `-1`  |
| `7 % -2`   | `1`   |

Dividing by zero is never allowed to produce a value. Integer `/` and `%`, and the compound `/=` and `%=`, stop the program when the divisor is zero, on every target and in every build profile:

```rux
func Divide(a: int32, b: int32) -> int32 {
    return a / b;
}
```

```
Panic: division by zero
  at Divide (Src/Main.rux:4:14)
```

The same happens to the one signed division whose quotient does not fit its type — the type's minimum divided by `-1` — which stops with `Panic: division overflow`. A divisor written as a non-zero literal needs no check, and a release build drops a check it can prove will pass. The panic is the same kind a call to `Panic` produces — see [Panics](/docs/lang/errors/panics).

## Floating-point arithmetic

Floating-point arithmetic follows IEEE 754 at every width, from `float8` to `float512`. Division by zero does not stop the program; it gives an infinity, or NaN for `0.0 / 0.0`:

```rux
PrintLine("{} {}", 1.0 / 0.0, 0.0 / 0.0);
PrintLine("{} {}", 7.5 % 2.0, -7.5 / 2.0);
```

This prints `Inf NaN`, then `1.5 -3.75`. `%` on floating-point values is the remainder of truncated division, with the sign of the dividend. See [Floating-point types](/docs/lang/types/floating-point) for the special values and their comparisons.

## No power operator

Rux has no exponentiation operator. `a ** b` is two operators, multiplication and a [dereference](/docs/lang/pointers/overview), `a * (*b)`, so with integers it fails:

```
error: operator '*' requires a pointer operand, but found 'int'
```

Use [`Pow`](/docs/api/math/powers#pow) from the Math package for floating-point powers, or a loop for small integer ones.

There is no unary `+` either: `+5` does not parse.

## Compound assignment

Each binary arithmetic operator has a compound form, `+=` `-=` `*=` `/=` `%=` `+%=` `-%=` `*%=`, that updates a mutable place, and `++` and `--` add or subtract one — see [Assignment](/docs/lang/expressions/assignment).
