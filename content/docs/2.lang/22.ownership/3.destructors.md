# Destructors

A **destructor** is code the compiler runs when a value's life ends. It is the block `destructor { … }` in an `extend` block of its type, and inside it `self` is a `&var` loan of the value being destroyed. Nothing calls it by name: the compiler invokes it exactly once for each initialized value that still owns its state, and never for a value that was given away, [ended](/docs/lang/ownership/ending) another way, or never initialized.

## Syntax

```text
extend T {
    destructor { … }
}
```

```rux
struct Guest {
    name: char8[..];
}

extend Guest {
    destructor {
        PrintLine("{} leaves", self.name);
    }
}
```

A destructor is not a function: it has no name of its own, no parameter list, no result and no type parameters, and for a generic type it is written once in `extend Store<T>`. A type has at most one, declared in an `extend` block of its own package. It takes no visibility modifier, because it runs wherever a value of the type ends, in any package. No error may leave it, so a call in it that can fail is handled with `!!` or `catch`.

| Mistake                                 | Error                                                       |
| --------------------------------------- | ----------------------------------------------------------- |
| `func ~Guest(&var self) { … }`          | `a destructor is not a function`                            |
| `destructor(x: int) { … }`              | `a destructor takes no parameter list`                      |
| `destructor -> int { … }`               | `a destructor returns nothing`                              |
| `pub destructor { … }`                  | `a destructor takes no visibility modifier`                 |
| a second `destructor` for the same type | `'Guest' already has a destructor`                          |
| a destructor outside `extend`           | `a destructor is declared in an 'extend' block of its type` |
| `Close()!` inside it                    | `an error cannot leave a destructor`                        |
| `seat.~();`                             | `'.~()' is not supported`                                   |

The first three carry `help: write 'destructor { ... }'`. A destructor cannot be called; to end a value's life early, [`destroy`](/docs/lang/ownership/ending#destroy) it, replace it, or give it to a function that lets it go.

## When destruction runs

| Event                                                                       | What is destroyed                                 |
| --------------------------------------------------------------------------- | ------------------------------------------------- |
| The owning scope ends — a block, a function, each pass of a loop body       | every value it still owns                         |
| `return`, `break`, `continue`, `?` propagation                              | the values of every scope being left              |
| An error leaving a scope for its handler or the caller                      | the values of every scope being left              |
| The statement that made an owning temporary ends                            | the temporary, unless it was given away           |
| The statement holding a branch ends, when only some paths gave a value away | the value, on the paths that kept it              |
| `=` into a live place                                                       | the old value, after the new one is produced      |
| `destroy value;`                                                            | the value, at the statement                       |
| A destructuring `let`, or a `match` or `catch` arm that owns its subject    | each part bound to `_` or left out of the pattern |
| `let _ = value;`                                                            | the value, at the statement                       |
| A by-value parameter                                                        | the parameter, when the function returns          |

| Not destroyed                                                                 | Why                                                     |
| ----------------------------------------------------------------------------- | ------------------------------------------------------- |
| A value given away                                                            | its new owner destroys it                               |
| A value returned with `return value;`                                         | the caller owns it now                                  |
| A value whose [ending method](/docs/lang/ownership/ending#ending-methods) ran | the method ends it in place of the destructor           |
| Storage declared without a value and never assigned                           | it holds nothing                                        |
| The old contents of storage written through a raw pointer                     | a pointer cannot tell whether the storage holds a value |
| Anything, when the program panics or exits                                    | panics do not unwind                                    |

A write through a raw pointer — `*p = value`, `p[i] = value`, or a field reached through `*var T` — initializes the storage it addresses and destroys nothing. Code that replaces a value through a pointer reads out the old one, or ends it with `destroy *p;`, first.

## Order

Values that end together are destroyed in **reverse order of declaration**, last declared first: a value made later may depend on one made earlier, so it has to go while the earlier one is still there. A scope's [deferred statements](/docs/lang/ownership/defer) take part in the same sequence — see [Defers and destructors](/docs/lang/ownership/defer#defers-and-destructors) — and the parameters of a function go last.

A value's own destructor runs first, while its fields are still intact. Then the compiler destroys its contents — fields, tuple and array elements, and the payload of a variant case or optional — in reverse construction order: the last field first, the last element first.

```rux
struct Part {
    name: char8[..];
}

extend Part {
    destructor {
        PrintLine("~Part {}", self.name);
    }
}

struct Machine {
    first: Part;
    second: Part;
}

extend Machine {
    destructor {
        PrintLine("~Machine");
    }
}

func Build() {
    let machine = Machine { first: Part { name: "first" }, second: Part { name: "second" } };
    let a = Part { name: "a" };
    let b = Part { name: "b" };
}
```

`Build` prints `~Part b`, `~Part a`, `~Machine`, `~Part second`, `~Part first`.

A type with no destructor of its own still has its droppable parts destroyed: the compiler generates that cleanup for every structure, tuple, array, variant and optional that contains something to destroy.

## Temporaries

An owning temporary that nobody takes — a call's result lent to a call with `&`, the receiver of a method that borrows it, or the value of an expression statement that nobody keeps, as in `Make("unused");` — is destroyed where the statement that made it ends, or at an exit that leaves the statement first, the last made first:

```rux
func Make(name: char8[..]) -> Part {
    return Part { name };
}

extend Part {
    func Look(&self) -> int32 {
        PrintLine("look {}", self.name);
        return 1;
    }
}

func Main() -> int {
    let n = Make("temp").Look() + Make("other").Look();
    PrintLine("after the statement");
    return 0;
}
```

`Main` prints `look temp`, `look other`, `~Part other`, `~Part temp`, `after the statement`.

## Where paths rejoin

When a value is given away on only some paths of a branch, it is destroyed on the others where the statement holding the branch ends, and it is finished after the branch on all of them. The decision is made when the program is compiled: nothing records at run time whether a local still holds its value, and nothing waits for the end of the scope:

```rux
func Visit(away: bool) {
    let guest = Guest { name: "Dee" };
    if away {
        let taken = guest;    // destroyed at the end of this block, as 'taken'
    }                         // destroyed here when away is false
    PrintLine("visit over");
}
```

Either way `Dee leaves` is printed once, before `visit over`. See [Where paths rejoin](/docs/lang/ownership/overview#where-paths-rejoin) for the rule and the error for a value assigned on some paths only.

## Replacement

Assigning to a place that holds a value replaces it in three steps: the new value is produced — a copy, a value given away, or a `Clone` call — then the old value is destroyed, then the new one is installed. A field, a tuple element and an element of an array or slice are places like any other, whether they belong to a local or are reached through a `&var` reference:

```rux
var seat = Guest { name: "Bob" };
seat = Guest { name: "Cy" };    // Bob leaves here
```

A part of a local holds a value only while the local holds one. A droppable local declared without a value, or given away, is assigned **whole** before any part of it is written, because a part written into empty storage would never be destroyed:

```text
error: cannot write field 'guest' of 'table', which holds no value
  note: 'table' was declared without a value at …
  note: 'Table' needs destruction, and a value written into a part of storage that holds none would never be destroyed
  help: initialize 'table' whole, as in 'table = Table { ... }'
```

A type with nothing to destroy may still be filled one part at a time; see [Initialization](/docs/lang/bindings/initialization).

## Destructors make a type move-only

A type that declares a destructor owns resources, so it is never copied implicitly: copying its bytes would leave two owners to release the same memory or close the same file. Such a type, and anything holding one, is move-only, and each value is destroyed by its last owner. A named value of it written bare is given away, and duplicated only by a method such as `Clone` that duplicates the resource; see [Copy and move](/docs/lang/ownership/copy-and-move).

## Destructuring

A destructure that takes its value over owns every part of it: a destructuring `let`, a `match` arm whose subject the match took — a named owning value, a temporary such as a `Clone` result, or the copy a match makes of plain data — and a `catch` arm, which owns the error. A part bound to a name belongs to that binding. A part bound to `_`, and a structure field the pattern leaves out, has no owner left, so it is destroyed on the spot — at the `let`, or at the top of the arm before its body runs — in the order the parts appear in the pattern:

```rux
let (_, second) = pair;    // the first element is destroyed here
let _ = guest;             // 'guest' is destroyed here
```

An arm that binds nothing from a consumed subject destroys it whole, and a consumed subject no arm takes is destroyed as the match ends; `match &value` takes nothing and leaves the value with its owner. A structure that declares a destructor cannot be split by a moving pattern, because its destructor runs on the whole value; it can still be tested with a pattern that binds none of its fields, bound whole, or matched through a loan:

```text
error: cannot split 'Handle' with a moving pattern, because it declares a destructor
```

## No unwinding

A [panic](/docs/lang/errors/panics) stops the program where it happens. Nothing is unwound: no destructor runs and no [deferred statement](/docs/lang/ownership/defer) runs, in the panicking function or in any caller. The same holds for ending the process. Cleanup that must survive a failure belongs on an error path — an error leaving through `throw` or `!` does run destructors.
