# Ownership

Every value in Rux has exactly one **owner**: a binding, a parameter, a field or element of a larger value, or a temporary that nothing has named yet. The owner decides when the value's life ends, and at that point the compiler [destroys](/docs/lang/ownership/destructors) it, once.

A named value written where a value goes leaves its owner in one of two ways, and neither is marked. **Plain data is copied**: a second, independent value is made and the source keeps its own. **An owning value is given away**: the value itself goes to its new owner, and the old name is finished. A copy of an owning value is asked for explicitly, with `Clone()`. A [loan](/docs/lang/references/overview#loans), `&x` or `&var x`, is the third way to reach a value: it lends without owning, so nothing changes hands.

## Syntax

```text
let name = source;             // copy plain data, or take an owning value
target = source;               // the same, replacing target's value
F(source)                      // the same, into the parameter
return source;                 // the same, out of the function
Type { field: source }         // the same, into an aggregate
match source { … }             // the arms take the subject
source.Clone()                 // an explicit copy of an owning value
F(&source), F(&var source)     // a loan: source keeps its value
match &source { … }            // the arms borrow the subject
```

The same source is copied or given away depending only on its type. `move` is not part of the language and stays reserved, so it cannot name a binding; written before a value it is refused, and the value after it is read as written:

```text
error: 'move' is not supported
  help: remove it: a bare value is given away
```

`<-` is no operator either: `let x <- y;` is `'<-' is not a binding operator` with `help: write 'let name = source'`, and `a <- b;` is `'<-' is not an assignment operator` with `help: write 'target = source'`.

## Copy or give away

A local or a parameter written bare in a by-value position — a binding, an argument, a receiver taken by value, a return, an assignment, an aggregate field or field shorthand, a conditional arm, an operand of `??`, or the subject of `match`, `if let` or `for` — is **copied** when its type is plain data and **given away** when it is move-only.

Plain data is numbers, `bool`, characters, raw pointers, slices, function values, and structures, tuples, variants, unions, optionals and arrays made only of them. Every other type is **move-only**: a type with a [destructor](/docs/lang/ownership/destructors) owns resources, and so does anything holding one, so copying its bytes would leave two owners to release them. [Copy and move](/docs/lang/ownership/copy-and-move) gives the exact rule and the attributes that change it.

```rux
struct Ticket {
    seat: int32;
}

extend Ticket {
    destructor {
        PrintLine("ticket {} torn up", self.seat);
    }

    func Clone(&self) -> Ticket {
        return Ticket { seat: self.seat };
    }
}

func Keep(ticket: Ticket) -> Ticket {
    return ticket;                      // given away to the caller
}

func Show(ticket: &Ticket) {
    PrintLine("seat {}", ticket.seat);
}

func Main() -> int {
    let count = 3;
    let copy = count;                   // plain data: copied, count keeps its value
    let ticket = Ticket { seat: 7 };
    Show(&ticket);                      // lent: ticket keeps its value
    let spare = ticket.Clone();         // an explicit copy
    let kept = Keep(ticket);            // given away: ticket is finished
    PrintLine("{} {} {} {}", count, copy, spare.seat, kept.seat);
    return 0;
}
```

```mermaid
flowchart LR
    a(["`a`: a value<br/>with a name"])
    a -- "`let b = a`<br/>plain data" --> c["two values<br/>`a` and `b` both usable"]
    a -- "`let b = a`<br/>an owning value" --> m["one value, now `b`'s<br/>`a` is finished"]
    a -- "`let b = &a`<br/>a loan" --> r["one value, still `a`'s<br/>`b` refers to it"]
```

|              | Copy                 | Give away          | `Clone()`            | Loan `&x` / `&var x` |
| ------------ | -------------------- | ------------------ | -------------------- | -------------------- |
| Applies to   | plain data           | an owning value    | an owning value      | any place            |
| Values after | two                  | one                | two                  | one                  |
| The source   | unchanged and usable | finished           | unchanged and usable | still the owner      |
| Destroyed by | each owner, its own  | the new owner only | each owner, its own  | the original owner   |

Giving a value away is a byte copy followed by forgetting the source; no user code runs, the source's destructor does not run, and the value is destroyed exactly once, by its last owner. Copying never touches the source: changing one value never shows in the other.

## Temporaries

A value nobody has named (the result of a call, a literal, a constructor call, or the value a conditional or `match` produces) has no other owner, so it is given away directly, and no copy runs:

```rux
func Main() -> int {
    let ticket = Keep(Ticket { seat: 8 });   // a literal, given to Keep; Keep's result, given to ticket
    Show(&Keep(Ticket { seat: 9 }));         // a temporary lent to a call
    return 0;
}
```

An owning temporary that is not given away — lent to a call, as `Show(&Keep(…))` above, the receiver of a method that borrows it, as in `Make().Look()`, or the value of an expression statement that nobody keeps, as in `Keep(Ticket { seat: 7 });` — is destroyed where the statement that made it ends, the last made first. Here `ticket 9 torn up` is printed before the `return`.

## After giving a value away

Using a name whose value was given away is a compile-time error. The note points at where it went:

```text
error: 'ticket' is used after it was given away
  note: 'ticket' was given away at …
  help: lend it with '&ticket' where it is only read, or clone it where both uses need a value
```

A `var` whose value was given away is empty, not ruined. Assigning it a whole new value makes it usable again:

```rux
var ticket = Ticket { seat: 1 };
let held = ticket;
ticket = Ticket { seat: 2 };
PrintLine("ticket is {} again", ticket.seat);
```

A loop body runs again from where its last pass ended, so a value one pass gives away is not there for the next. Giving an outer local away inside a loop body is an error unless the same pass gives it a new value before the loop repeats, or leaves the loop with `break`, `return` or `throw` after giving it away. The loop's own `for` variable and the locals declared inside the body are fresh on every pass.

```rux
var slot = Ticket { seat: 3 };
for pass in 0..2 {
    let taken = slot;
    PrintLine("pass {} took {}", pass, taken.seat);
    slot = Ticket { seat: 10 + pass as int32 };    // refilled before the next pass
}
```

Without the last line of the body, the second pass would find `slot` empty:

```text
error: 'slot' is given away inside a loop, and the next pass would use it again
  help: give 'slot' a new value before the pass ends, or leave the loop after giving it away
```

## `match`, `if let` and `for`

A subject is a value position like any other. `match outcome { … }`, `if let found? = maybe` and `for item in items` on a named owning value **take** it: the arms or the loop own it, and the name is finished afterwards. Written with a loan, `match &outcome`, `if let found? = &maybe` and `for item in &items` **lend** it, and it stays with its owner. A named plain-data subject is matched as a copy, so it is never finished.

```rux
let maybe: Ticket? = Ticket { seat: 5 };
if let ticket? = &maybe {
    PrintLine("lent {}", ticket.seat);   // a reference into maybe
}
if let ticket? = maybe {
    PrintLine("took {}", ticket.seat);   // maybe is finished from here
}
```

A `for` over a named owning container takes the container through its `IntoIterator` method, and whatever the loop does not reach is destroyed with the iterator; `for item in &items` lends the container to `Iterate` instead. A container whose type declares no `IntoIterator` cannot be taken by a loop:

```text
error: 'for' takes 'items' and its elements, and 'Vector<String>' declares no 'IntoIterator'
  help: lend them with '&items'
```

See [Iteration](/docs/lang/interfaces/iteration) and, for what the arms of a `match` own, [Destructors](/docs/lang/ownership/destructors#destructuring).

## Fields, elements and referents

Only a local, a parameter, a temporary, or a value read through a [raw pointer](/docs/lang/pointers/overview) can be given away. A field, an element of an array, a tuple or a slice, and the referent of a reference are **read**: plain data is copied out, and an owning value cannot leave on its own, because the value around it would be left without it. `let taken = holder.item;` is refused for a local `var holder`, and through a `holder: &Holder` parameter:

```text
error: 'item' is a field of 'holder' and cannot be given away by itself
  note: only a local, a parameter or a temporary is given away; the rest of the value would be left without it
  help: take it with 'Replace(&var holder.item, value)' or 'Swap', or take 'holder' apart with a pattern
error: 'holder.item' is reached through a loan and cannot be given away
```

Such a value is taken in one of four ways, each of which leaves every value with exactly one owner:

- [`Core::Ownership::Replace`](/docs/api/core/ownership#replace)`(&var place, value)` installs a new value and returns the old one; [`Swap`](/docs/api/core/ownership#swap)`(&var a, &var b)` exchanges two places. Neither copies or destroys anything.
- A destructuring pattern takes the **whole** value apart, giving each part a new owner; see [Partial moves](/docs/lang/ownership/copy-and-move#partial-moves).
- A method of the container hands an element over, as `Pop` and `Remove` do.
- A method taking [`~self`](/docs/lang/ownership/ending#ending-methods) ends the value and may give its fields away.

```rux
import Core::Ownership::Replace;

struct Booking {
    ticket: Ticket;
}

func Rebook(booking: &var Booking, seat: int32) -> Ticket {
    return Replace(&var booking.ticket, Ticket { seat });
}
```

## Where paths rejoin

When the paths of a branch rejoin, a value given away on some of them and kept on the others is **destroyed where the statement holding the branch ends**, on the paths that still hold it. Afterwards it is finished on all of them, so a later use is `'ticket' is used after it was given away`. Nothing waits for the end of the scope, and nothing records at run time whether the value is still there:

```rux
func Visit(give: bool) {
    let ticket = Ticket { seat: 1 };
    if give {
        let taken = Keep(ticket);    // destroyed at the end of this block, as 'taken'
    }                                // destroyed here when give is false
    PrintLine("after the if");
}
```

Either way `ticket 1 torn up` is printed once, before `after the if`. Values kept that way are destroyed last declared first. An `if` used as a value, a `match`, `&&`, `||` and `??` follow the same rule, and so does a loop: a value one `break` gave away and the loop's own exit kept is destroyed where the loop ends.

The reverse is an error. A local that was empty or given away before the paths split is assigned on every path or on none, because nothing could tell later whether it holds a value:

```text
error: 'ticket' is assigned on this path only, so nothing could tell later whether it holds a value
  note: a value that may be absent is a 'Ticket?'
  help: assign 'ticket' on every path or on none
```

A value that may be absent is an [optional](/docs/lang/optionals/overview). Plain data keeps the ordinary definite-initialisation rule, since nothing destroys it.

## Generic code

A value of a type parameter counts as owning inside generic code, so the body is correct for every type argument: a local or a parameter of type `T` written bare is given away, and a second use of it is `'value' is used after it was given away` whatever `T` turns out to be. Under a [`T: Copyable`](/docs/lang/generics/bounds) bound it is copied instead, and the bound is checked at the call; `Clone()` under `T: Cloneable` makes an explicit copy. A field or element of type `T` read by value is still a copy, checked for each instantiation: instantiating it with an owning type reports `cannot copy 'Owner', which owns resources` at the copy in the generic body.

## What cannot be given away

| Written                                      | Error                                                              |
| -------------------------------------------- | ------------------------------------------------------------------ |
| `let item = holder.item;`                    | `'item' is a field of 'holder' and cannot be given away by itself` |
| `let item = view.item;` with `view: &Holder` | `'view.item' is reached through a loan and cannot be given away`   |
| `ticket = ticket;`                           | `cannot give 'ticket' to itself`                                   |
| `Keep(ticket)` while `&ticket` is in use     | `cannot move 'ticket' while it is immutably borrowed`              |
| `let other = pinned;`                        | `moving type 'Pinned' is prohibited`                               |
| `defer Keep(ticket);`                        | `a deferred statement cannot give 'ticket' away`                   |
| `let taken = Name;` on a `#NoCopy` extern    | `cannot move out of extern variable 'Name'`                        |

A type can [prohibit moving](/docs/lang/ownership/copy-and-move#prohibiting-moves) altogether; a [deferred statement](/docs/lang/ownership/defer#defers-and-loans) only lends.
