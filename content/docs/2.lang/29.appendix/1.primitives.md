# Primitive Data Types

A consolidated summary of every built-in primitive type in Rux, grouped by family. These names are **predefined identifiers** — some are compiler-provided aliases — not [keywords](/docs/lang/lexical/keywords); they live in the type namespace. Each entry links to its full page.

In the **Status** column, ✓ marks types available in the current release; **Planned** marks types that are specified but not yet implemented.

## Defaults and Aliases

- An unsuffixed integer literal is inferred as [`int`](/docs/lang/signed/int); an unsuffixed floating-point literal is inferred as [`float64`](/docs/lang/floating/float64).
- [`int`](/docs/lang/signed/int) and [`uint`](/docs/lang/unsigned/uint) track the target's pointer width — `int32`/`uint32` on 32-bit targets, `int64`/`uint64` on 64-bit targets.
- [`float`](/docs/lang/floating/float) → `float64`, [`bool`](/docs/lang/boolean/bool) → `bool8`, and [`char`](/docs/lang/character/char) → `char32` are compiler-provided aliases (see [Built-in Aliases](/docs/lang/aliases/builtin)).
- [`byte`](/docs/lang/unsigned/uint8) is a compiler-provided alias for [`uint8`](/docs/lang/unsigned/uint8) — a clearer spelling for raw 8-bit byte values.
- Rux performs no implicit numeric conversions; every cross-type conversion uses the [`as`](/docs/lang/operations/type-cast) operator.
