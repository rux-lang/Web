# Iteration

A [`for` loop](/docs/lang/statements/loops) walks an array, a slice or a range directly. Any other subject is driven by a convention of method shapes: an **iterator** declares `Next`, which hands out one item per call, and a **container** declares `Iterate`, which lends itself to a fresh iterator, and may declare `IntoIterator`, which gives itself and its elements away to one.

## The protocol

```text
extend It {
    func Next(&var self) -> Item? { … }        // an iterator
}

extend Container {
    func Iterate(&self) -> It { … }            // a container, lent to the loop
    func IntoIterator(self) -> Owning { … }    // a container, given to the loop
}
```

| Subject of `for item in subject`                           | What the loop does                                            |
| ---------------------------------------------------------- | ------------------------------------------------------------- |
| an array, a slice, a range                                 | built in                                                      |
| `&items`, a loan of a type declaring `Iterate`             | calls `Iterate` once, then drives the iterator it returns     |
| a named owning `items` whose type declares `Iterate`       | takes `items`, calls `IntoIterator`, and drives that iterator |
| a plain-data value or a temporary whose type has `Iterate` | calls `Iterate` once, then drives the iterator it returns     |
| a type declaring `Next`                                    | drives the subject itself                                     |
| anything else                                              | `cannot iterate over 'T'`                                     |

A loop takes its subject the way `match` does: a named [owning](/docs/lang/ownership/overview) value written bare is given away to the loop, and `&items` lends it.

The loop calls `Next` once per pass. A present result runs the body with its payload bound to the loop variable; `none` ends the loop.

```mermaid
flowchart LR
    start["`for item in subject`"] --> it["`Iterate()` or `IntoIterator()`<br/>(containers only)"]
    it --> next["call `Next()`"]
    next --> q{"an item,<br/>or none?"}
    q -- "an item" --> body["run the body<br/>with `item` bound"]
    body --> next
    q -- "none" --> done["leave the loop"]
```

The same walk written by hand is a `loop` with a [coalescing exit](/docs/lang/optionals/coalescing):

```rux
var countdown = Countdown { remaining: 3 };
loop {
    let second = countdown.Next() ?? break;
    PrintLine("{}", second);
}
```

## Iterators

```rux
struct Countdown {
    remaining: int32;
}

extend Countdown : Iterator {
    func Next(&var self) -> int32? {
        if self.remaining == 0 {
            return none;
        }
        let current = self.remaining;
        self.remaining -= 1;
        return current;
    }
}

func Main() -> int {
    for second in (Countdown { remaining: 5 }) {
        Print(" {}", second);
    }
    PrintLine(" liftoff");
    return 0;
}
```

`Next` must take a **writable** receiver, since advancing an iterator changes it, and must return a native optional. The item type is whatever the optional carries:

```text
error: iterator method 'Next' on 'A' must take a mutable receiver
  note: advancing an iterator writes it, so 'Next' cannot borrow its receiver read-only
  help: write the receiver as '&var self'
```

A `Next` returning something else is not an iterator: `cannot iterate over 'B'`, with the note `type 'B' declares 'Next', but not as 'func Next(&var self) -> T?' returning a native optional`. `Next` takes no parameters besides its receiver. A `Next` returning a variant with `Some` and `None` cases is rejected where it is declared, because a loop ends only at the absence of a native optional:

```text
error: iterator method 'Next' on 'It' must return a native optional
  note: 'Step' is an ordinary variant; 'for' ends only at the absence of a native optional
  help: return 'Item?' and report the end with 'none'
```

An iterator is consumed as it is read. Once `Next` has reported `none`, it should keep reporting `none`; nothing promises that an iterator can be restarted.

A struct literal written directly after `in` must be parenthesised, as above. Without the parentheses its `{` is taken for the start of the loop body, and the parser stops with `expected ';' after expression, but found ':'`.

A loop over an iterator it names as a place (a variable, a field, an element) advances it where it is: after `for second in countdown` stops early with `break`, `countdown` holds the items not yet read, and a later loop or `Next` call continues from there. The variable must therefore be writable:

```text
error: cannot advance immutable iterator 'countdown'
  note: a loop over an iterator advances it where it is, and 'Next' writes it
```

Any other iterator, such as a call's result or a struct literal, is a temporary the loop advances.

## Containers

A container is not an iterator itself. It hands one out, so two loops over the same container walk independently, and the container is unchanged afterwards:

```rux
struct Span {
    limit: int32;
}

extend Span : Iterable {
    func Iterate(&self) -> Countdown {
        return Countdown { remaining: self.limit };
    }
}

func Main() -> int {
    let span = Span { limit: 3 };
    for n in span {
        Print(" {}", n);
    }
    for n in span {
        Print(" {}", n);    // starts again from 3
    }
    PrintLine();
    return 0;
}
```

`Iterate` takes no parameters besides the receiver. It usually borrows the container read-only (handing out an iterator changes nothing), and the iterator it returns usually borrows from the container in turn, so the container must outlive it and must not be changed while it is in use. An `Iterate` declared with `&var self` writes the container, so it needs one lent for writing, `for item in &var items`, or a writable place; through `&items`, a read-only reference or a `let` it is `'Iterate' writes its receiver, but 'items' is lent for reading`, with the help `lend it with '&var items', or declare 'Iterate(&self)'`.

`Span` is plain data, so `for n in span` works on a copy of it and `span` keeps its value. A container that owns resources is either lent to the loop or given to it:

```rux
var numbers = Vector<int>::New(SystemAllocator::New());
numbers.Push(4);
numbers.Push(5);
for n in &numbers {
    PrintLine("{}", n);    // lent: 'numbers' keeps its elements
}
for n in numbers {
    PrintLine("{}", n);    // taken: the loop owns 'numbers' and its elements
}
```

- **`for item in &items`** lends the container to `Iterate`, and it stays with its owner.
- **`for item in items`**, with a named owning `items`, gives the container to the loop, which calls its parameterless `IntoIterator`. Each item comes out by value, so an owning element is the body's to keep, and whatever the loop does not reach is destroyed with the iterator. `items` is gone afterwards: a later use is `'items' is used after it was given away`.

`Vector`, `HashMap`, `HashSet`, `TreeMap` and `TreeSet` declare `IntoIterator`. It takes its receiver by value: `Vector`'s is an [ending method](/docs/lang/ownership/ending), `func IntoIterator(~self)`, that hands its storage to the iterator without running the destructor. A container that declares none cannot be taken by a loop:

```text
error: 'for' takes 'bag' and its elements, and 'Bag' declares no 'IntoIterator'
  help: lend them with '&bag'
```

::note
**rux 0.4.0.**\
`Vector`'s `Iterate` hands out each item by value, which is sound only for plain data: `for item in &items` over a `Vector` of move-only elements destroys each element twice, once at the end of its pass and again with the vector. Walk such a vector through `items.References()`, which lends each element as a `&T`, or take it with `for item in items`.
::

`Iterator` and `Iterable`, from `Core::Iteration`, are empty [marker interfaces](/docs/lang/interfaces/core-interfaces#iterator-and-iterable). Writing `: Iterator` or `: Iterable` records the role; the loop goes by the method names and shapes alone and works without them.

## Items

An item may itself be an optional, a sum or the unit type. Only the **outer** absence that `Next` returns ends the loop; an absent item is an ordinary value the body receives:

```rux
struct Readings {
    index: int32;
}

extend Readings {
    // Each item is an int32?, so Next returns int32??.
    func Next(&var self) -> int32?? {
        self.index += 1;
        if self.index > 3 {
            return none;
        }
        if self.index == 2 {
            let missing: int32? = none;
            return missing;
        }
        let present: int32? = self.index * 10;
        return present;
    }
}

func Main() -> int {
    for reading in (Readings { index: 0 }) {
        PrintLine("{}", reading ?? -1);    // 10, -1, 30
    }
    return 0;
}
```

No error channel is added to iteration. An outcome an iterator wants to report is part of its item (a sum with an error member, or a [fallible](/docs/lang/errors/fallible-values) `T ! E`), which the body receives as data, and the loop continues past it.

## Patterns

The loop variable may be a pattern that matches every element (names, `_`, and tuples and structures made of them), which takes each element apart: `for (key, value) in pairs`, `for Point { x, y } in points`, `for (_, value) in entries`. The element is given to the pattern, so an owning part is the body's to keep or let go of. A pattern that could fail to match, such as `value?` or `(0, value)`, is refused:

```text
error: a 'for' pattern must match every element
  help: bind the element and test it in the body, as in 'for item in items { if item is ... { ... } }'
```

Bind the element and test it in the body instead, with `is`, or take it apart there with `if let`.

## Giving values away inside a loop

The loop variable and the locals declared in the body are fresh on every pass and may be given away freely. An outer local given away inside the body is not there for the next pass, so the same pass must give it a new value, or leave the loop with `break`, `return` or `throw`, after giving it away:

```text
error: 'slot' is given away inside a loop, and the next pass would use it again
  help: give 'slot' a new value before the pass ends, or leave the loop after giving it away
```

See [Ownership](/docs/lang/ownership/overview).
