# Exclusivity

At any moment a value may be borrowed by **any number of shared references**, `&T`, or by **one exclusive reference**, `&var T` — never both. While a `&var` borrow is in use, the value is reached only through it; while `&` borrows are in use, nothing changes the value under them. The compiler checks this for every [reference](/docs/lang/references/overview), so a reader never sees a value change mid-read and two writers never overlap.

| While the value is borrowed by | Reading the value directly | Writing it directly | Another `&` borrow | Another `&var` borrow |
| ------------------------------ | -------------------------- | ------------------- | ------------------ | --------------------- |
| one or more `&T`               | allowed                    | error               | allowed            | error                 |
| one `&var T`                   | error                      | error               | error              | error                 |

The rule covers every loan: an argument for a reference parameter, whether the loan is written or the argument binds bare, a method call through a `&self` or `&var self` receiver, a local alias such as `let wallet = &var alice;`, a `match &value` or `for item in &items` over the subject, and a [returned reference](/docs/lang/references/overview#returning-a-reference), which borrows the argument it came from until its last use.

## A borrow lasts until its last use

A borrow made for a call lasts for that call. A borrow bound to a local lasts from the binding to the **last use** of that local — not to the end of the block. Once the reference is used for the last time the value is free again:

```rux
struct Account {
    balance: int;
}

func Main() -> int {
    var alice = Account { balance: 10 };
    let wallet = &var alice;
    wallet.balance += 5;       // last use of wallet: the borrow ends here
    alice.balance -= 1;        // fine: alice is no longer borrowed
    return 0;
}
```

```mermaid
flowchart LR
    b["`let wallet = &var alice`"] --> u["`wallet.balance += 5`<br/>(last use)"]
    u --> f["`alice` is free again"]
    b -. "`alice` reachable only through `wallet`" .-> u
```

Moving the direct access before the borrow's last use is what makes the program wrong:

```rux
let wallet = &var alice;
let before = alice.balance;    // error: wallet is still to be used
wallet.balance += 5;
```

```
error: cannot read 'alice.balance' while 'wallet' holds an exclusive borrow
  help: read through 'wallet' or wait until its last use
```

Read through the reference instead, or move the read after the reference's last use.

## What overlaps

Two accesses conflict only when they reach the same storage. The compiler compares the places as written:

- A whole value overlaps each of its fields and elements, and they overlap it.
- **Different fields** of one struct do not overlap, so one can be borrowed exclusively while another is read or borrowed.
- Elements overlap when their indexes are the same constant or the same expression: `v[0]` and `v[0]`, `v[i]` and `v[i]`.

```rux
struct Pair {
    x: int;
    y: int;
}

func Swap(a: &var int, b: &var int) {
    let saved: int = a;
    a = b;
    b = saved;
}

func Main() -> int {
    var pair = Pair { x: 1, y: 2 };
    Swap(&var pair.x, &var pair.y);          // two fields: no overlap
    var values = [1, 2, 3];
    Swap(&var values[0], &var values[2]);    // two different elements
    return 0;
}
```

## The errors

Each conflict has its own message. All of them carry a note giving the line and column where the conflicting borrow began, and a help line naming the reference to use instead.

**Reading a value while a `&var` borrow of it is in use.**

```
error: cannot read 'alice.balance' while 'wallet' holds an exclusive borrow
  help: read through 'wallet' or wait until its last use
```

**Writing a value while a borrow of it is in use.** A shared borrow forbids writes because a reader expects the value to hold still; an exclusive one forbids every direct access:

```
error: cannot modify 'alice.balance' while it is immutably borrowed
error: cannot modify 'alice' while it is exclusively borrowed
```

**Giving a value away while a borrow of it is in use.** The new owner could change or destroy it under the reference, so [giving it away](/docs/lang/ownership/overview) waits for the borrow's last use too. With `let view = &ticket;` still to be used, `Keep(ticket)` is refused:

```
error: cannot move 'ticket' while it is immutably borrowed
  help: use 'view' for the access or wait until its last use
```

**Borrowing for writing while a reader is in use**, including through a method with a `&var self` receiver:

```
error: cannot borrow exclusively 'alice' while it is immutably borrowed
  help: use 'view' for the access or wait until its last use
```

**Borrowing at all while a writer is in use**, including by calling a method with a `&self` receiver. Such a call is reported both as a read and as a borrow:

```
error: cannot read 'alice' while 'wallet' holds an exclusive borrow
  help: read through 'wallet' or wait until its last use
error: cannot borrow 'alice' while it is exclusively borrowed
  help: use 'wallet' for the access or wait until its last use
```

**One value in two arguments** of the same call, when at least one of them is `&var`. Two `&T` arguments may share a value; an exclusive one must have it to itself:

```
error: call arguments create overlapping exclusive borrows of 'alice'
  help: split the accesses into non-overlapping calls
```

The same message names a field or an element when that is what is passed twice: `Swap(&var pair.x, &var pair.x)` reports `'pair.x'`, and `Swap(&var values[0], &var values[0])` reports `'values[0]'`.

## Outside the rule

[Raw pointers](/docs/lang/pointers/overview) are not borrows. Taking an address with `@`, holding several `*var T` to one value, and writing through them are all accepted; keeping such accesses apart is the program's responsibility, stated in the [`// Safety:` comment](/docs/lang/pointers/overview#raw-operations) above each one. A [slice](/docs/lang/slices/overview) is a view built on a pointer and is not tracked as a borrow either.
