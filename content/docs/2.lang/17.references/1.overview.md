# References

A _reference_ lets code use a value that belongs to someone else, without copying it and without taking it over. `&T` is a **shared** reference: it can read the value. `&var T` is an **exclusive** reference: it can read and write it. A reference never owns its referent, is never null, is never pointed at other storage, and lives no longer than the call or the block that made it.

```text
reference-type = "&" type
               | "&" "var" type
loan           = "&" place
               | "&" "var" place
```

```rux
struct Account {
    owner: char8[..];
    balance: int;
}

func Report(account: &Account) {
    PrintLine("{}: {}", account.owner, account.balance);
}

func Deposit(account: &var Account, amount: int) {
    account.balance += amount;
}

func Main() -> int {
    var alice = Account { owner: "alice", balance: 10 };
    Deposit(&var alice, 5);   // lent for writing: alice.balance is now 15
    Report(alice);            // only read: plain data binds bare
    return 0;
}
```

References are the checked way to share. A [raw pointer](/docs/lang/pointers/overview) is an address the program vouches for itself; a reference is one the compiler checks, under the rules on [Exclusivity](/docs/lang/references/exclusivity).

## Loans

A reference is made by a **loan**, written where it starts: `&place` lends a place for reading and `&var place` lends it for writing. The loan has type `&T` or `&var T`, it never copies or [gives away](/docs/lang/ownership/overview) the place, and the owner keeps the value afterwards. The same two spellings lend in every position:

| Written                    | Lends                                                                                    |
| -------------------------- | ---------------------------------------------------------------------------------------- |
| `Deposit(&var alice, 5)`   | `alice` to the call, for writing                                                         |
| `let alias = &alice;`      | `alice` to a local, until the local's last use                                           |
| `match &alice { … }`       | the subject to the arms, which bind references into it                                   |
| `if let found? = &maybe`   | the optional, so `found` is a reference to its payload                                   |
| `for name in &names { … }` | the container to its `Iterate` method — see [Iteration](/docs/lang/interfaces/iteration) |

Without the `&`, `match alice`, `if let found? = maybe` and `for name in names` take a named owning subject, as a binding does; see [Ownership](/docs/lang/ownership/overview).

The operand is a **place** — a local, a parameter, a field, an element, or `*p` through a raw pointer — or a reference, which lends what it refers to. A temporary may be lent to a call, as in `Report(&Make())`, and lives until its statement ends; a loan of one bound to a name would outlive it:

```text
error: this loan would outlive the 'Account' made by 'Make', which is destroyed when the statement ends
```

`&var` needs a place that may be written. A temporary is lent only for reading, since whatever was written through the loan would be lost when the statement ends, so `Deposit(&var Make(), 5)` and `&var 5` are refused:

```text
error: '&var' lends a place for writing, but this is a temporary value
  note: what is written through the loan would be lost when the statement ends
  help: store the value in a 'var' local and lend the local
```

With `let savings = Account { … };`, `Deposit(&var savings, 10)` is refused too, and a read-only loan does not reach a `&var` parameter:

```text
error: '&var' lends for writing, but this place is immutable
  help: declare 'savings' with 'var' to make it mutable
error: argument 1 to 'Deposit' has type '&Account', but parameter 'account' requires '&var Account'
```

A `&var T` is accepted wherever a `&T` is expected: an exclusive reference can always lend reading.

### When the loan must be written

A place that reaches a reference parameter — an element of a variadic `&T...` tail included, such as `PrintLine`'s `args: &Display...` — is lent with a written `&` or `&var` in three cases:

1. **The callee writes it.** The parameter is `&var T`, so the reader of the call has to see that the argument changes.
2. **The value owns resources.** Its type is move-only — it has a [destructor](/docs/lang/ownership/destructors), holds something that does, or is [`#NoCopy`](/docs/lang/ownership/copy-and-move#prohibiting-copies) — so a bare name would read as giving it away.
3. **The callee's result borrows from it.** The [returned reference](#returning-a-reference) keeps the argument borrowed after the call, plain data included.

```rux
struct Names {
    count: int;
}

extend Names {
    destructor {}
}

func Add(total: &var int, amount: int) {
    total += amount;
}

func Show(names: &Names) -> int {
    return names.count;
}

func Pick(value: &int) -> &int {
    return value;
}

func Main() -> int {
    var total = 0;
    let names = Names { count: 2 };
    let count = 3;
    Add(&var total, 5);
    let shown = Show(&names);
    let first = Pick(&count);
    return total + shown + first;
}
```

Leaving out any of those three loans is an error that says which case applies:

```text
error: 'Add' writes its argument 'total', so the loan must be written
  help: write '&var total'
error: 'Show' borrows its argument, and 'Names' owns resources, so the loan must be written
error: the result of 'Pick' borrows from its argument, so the loan must be written
```

Everything else binds bare. Plain data that the callee only reads — `Report(alice)` above, or `Twice(total)` below — needs no `&`, since a copy and a read loan of it cannot be told apart; `rux lint` reports a written one, `Report(&alice)`, as `the '&' on 'alice' is redundant`. A name that is already a loan — a reference parameter, a `let` alias, or a binding a pattern made over a lent subject — is passed on bare, and so is a method's receiver: `alice.Reset()` lends `alice` to a method declared with `&var self`.

```rux
func Count(names: &Names) -> int {
    return Show(names);   // already a loan: passed on as it is
}
```

### A loan is not an address

`&` lends; it never takes an address. A loan passed where a [raw pointer](/docs/lang/pointers/overview) is expected is a type mismatch whose help points at `@`, the operator that does:

```text
error: argument 1 to 'Store' has type '&var int', but parameter 'target' requires '*var int'
  help: '&' lends a place; write '@' to take its address for a raw pointer
```

## Using a reference

A reference is used as if it were the value. Fields, methods, indexing and `.length` all reach through it with no `*` and no arrow:

```rux
func First(values: &int[3]) -> int {
    return values[0] + values.length as int;
}
```

A reference to a scalar — an integer, a float, a `bool`, a character — supplies the scalar's value wherever a value is expected: in arithmetic and comparisons, in a condition, in a cast, in an assignment or a typed binding, as a by-value argument:

```rux
func Twice(value: &int) -> int {
    return value * 2;
}
```

To copy a scalar out of a reference, give the binding its type: `let saved: int = value;`. `*` is a raw-pointer operator and never applies to a reference:

```text
error: operator '*' requires a pointer operand, but found '&var int'
  note: a reference reads and writes its referent without '*'
  help: write 'r' in place of '*r', as in 'r += 1'
```

## Writing through `&var`

Through a `&var T` the referent can be written in three ways.

**Fields and elements** are written as usual: `account.balance += 5`, `values[i] = 0`.

**A scalar referent** is written by assigning to the reference itself. `=`, the compound assignments and `++`/`--` all store into the caller's value:

```rux
func Bump(count: &var int) {
    count += 1;
}

func Main() -> int {
    var total = 4;
    Bump(&var total);            // total is now 5
    let alias = &var total;
    alias = 20;
    alias++;                     // total is now 21
    return 0;
}
```

**Any other referent** — a struct, a tuple, an array, a value of a type parameter — is replaced whole with `=`. This is how a method replaces the value it was called on:

```rux
extend Account {
    func Reset(&var self) {
        self = Self { owner: self.owner, balance: 0 };
    }
}
```

The write follows the [assignment rules](/docs/lang/ownership/copy-and-move#assignment) for `T` exactly as an assignment to a `var` local would: the new value is produced first, the old one is destroyed, and the new one is installed; an owning value is given away bare or copied with an explicit `Clone()`. Compound assignment and `++`/`--` apply to scalar referents only, and an interface view cannot be replaced, because its referent's type is not known.

Through a shared reference every write is an error:

```text
error: cannot modify data through immutable reference '&Account'
```

### A reference is never reseated

`=` through a reference always writes through to its referent; nothing points a reference at other storage. A reference local is therefore declared with `let`, and a `var` binding of reference type, written or inferred, is an error:

```text
error: 'var' binding 'alias' cannot hold reference '&var int'
  help: references cannot be reseated; use a pointer or a new binding
```

To refer to another value, declare a new binding.

## Returning a reference

A function may return `&T`, `&var T`, or the optional reference `&T?`, with no lifetime written anywhere: the signature alone says what the result borrows from. It is the receiver when the function takes one by reference, `&self` or `&var self`; otherwise it is the one parameter that is a reference or a slice:

```rux
struct Slots {
    items: int32[4];
    count: uint;
}

extend Slots {
    func At(&self, index: uint) -> &int32 {
        return self.items[index];            // borrows self
    }

    func AtMutable(&var self, index: uint) -> &var int32 {
        return self.items[index];
    }

    func Find(&self, index: uint) -> &int32? {
        if index >= self.count { return none; }
        return self.items[index];            // made present
    }
}

func First(items: int32[..]) -> &int32 {
    return items[0];                         // the only slice parameter
}
```

A receiver taken by value lends nothing, and neither does a variadic parameter. Any other signature — two reference parameters, or none — is `cannot tell what the returned reference borrows from`, with `help: return an owned value`. An operator, `[]` included, cannot return a reference, so an accessor that lends an element is a method such as `At`.

Every `return` yields a reference derived from the source: the source itself, a field or element of it, a reference a call returned from it, or a local reference holding one of those. A reference to a local is `cannot return a reference to local 'copy'`, one to a by-value parameter `cannot return a reference to parameter 'value'`, one to a temporary is `cannot return a reference to a temporary value`, and one borrowed from another reference parameter is `cannot return a reference borrowed from 'other'`. `&var T` needs storage the function may write, so a method taking `&self` cannot return a `&var` to its fields: `cannot return a part of immutable 'self' as '&var int32'`.

At the call site the result is a reference like any other: it lives in a `let` local, is passed on to a reference parameter, or is returned again under the same rule. A scalar is read from it as from any reference, so `let first: int32 = slots.At(0);` copies the value. While the result is in use, the argument it borrows from is borrowed — a `&T` result keeps it from being written or given away, and a `&var T` result from being used any other way, until the result's last use. A plain-data argument for such a parameter is therefore lent with a written `&`, as [above](#when-the-loan-must-be-written). That argument must be storage that outlives the statement, so `Make().At(0)` is `the returned reference would borrow from a temporary value`. A function value never returns a reference: calling one whose type would is `cannot call a function value that returns reference '&int32'`.

An optional reference `&T?` — the suffix after the referent; `&(T?)` is a reference to an optional — may be a return type and the type of a `let` local, and nothing else. `found ?? fallback` yields a reference, so the fallback is a place or a reference too, or leaves, as `?? return` does; `if let value? = found` and a match arm `value?` bind a reference. `?` does not propagate the absence of an optional reference; match it, or use `??`.

## Where a reference may appear

A reference is a non-owning alias for the length of a call or a block, so it may appear in exactly four places: a **parameter**, a **receiver**, a **`let` local**, and the **result** of a function whose signature says what it borrows from, as [above](#returning-a-reference). It cannot be stored in a field, an array or a tuple:

```text
error: field 'r' in struct 'Holder' cannot store reference type '&int'
  note: references are non-owning aliases and cannot escape into aggregate storage
  help: store the owned value or a raw pointer when an address must outlive the borrow
```

Nothing is given away through a reference either. A plain-data part of the referent is read as a copy, while an owning one cannot leave it — `let item = holder.item;` with `holder: &Holder` is refused, and only a clone can be taken:

```text
error: 'holder.item' is reached through a loan and cannot be given away
  note: a loan does not own the value it reaches
  help: clone it; it cannot be taken with 'Replace' or 'Swap', which write the place
```

Through `holder: &var Holder` the place may be written, so the help offers [`Replace`](/docs/api/core/ownership#replace) or `Swap`, which take the part and leave another value in its place: `take it with 'Replace(&var holder.item, value)' or 'Swap', or clone it`.

A reference is no [type argument](/docs/lang/generics/overview) either, written or deduced. A generic body is checked once for whatever its parameter stands for, so nothing there proves it does not store the value — `Thread::Spawn` keeps its context for the new thread — and `Hold<&Counter>(&counter)` is refused, as is `Spawn(ByRef, counter)` with `func ByRef(counter: &Counter)`:

```text
error: type argument '&Counter' of function 'Hold' cannot be or hold a reference
  note: type parameter 'T' may be stored by the generic code, and a reference cannot outlive the call that borrowed it
  help: pass an owned value, or a raw pointer when the address must be shared
```

A reference cannot [end](/docs/lang/ownership/ending) its referent either: `destroy` through a loan is `a value reached through a loan cannot be destroyed`, and replacing a value through `&var T` installs a new one in its place. When an address must be stored or must outlive the call, use a [raw pointer](/docs/lang/pointers/overview).

A reference is 8 bytes, the size of the address it holds.
