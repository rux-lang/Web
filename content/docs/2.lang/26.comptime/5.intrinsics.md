# Intrinsics

An **intrinsic** is something the compiler implements itself: the value of `float64::Infinity`, the fields of `#target`, the code an `Assert` turns into, the decision whether a type is `Copyable`. A program reaches it only through an `intrinsic` **declaration**, which names it and gives its type, with no body. The `Core` package holds the standard declarations, and a program imports them from its modules like any other name — `import Core::Compilation::#target;`, `import Core::Diagnostics::Assert;`.

```text
intrinsic-decl = [ "pub" ] "intrinsic" ( "const" identifier ":" type ";"
                                       | "#" identifier ":" type ";"
                                       | "interface" identifier ";"
                                       | function-signature ";" )
```

`intrinsic const` is written inside an `extend` block, and `intrinsic func` may be too, where it declares a method.

## The intrinsics package

Exactly one package of a build may declare intrinsics, so that every compiler-supplied name has one declaration. That is the **intrinsics package**, which the root manifest names with `Intrinsics` in its `[Package]` table — a dependency, by its name in `[Dependencies]`, or the package itself. It is `Core` when the manifest says nothing. Anywhere else an `intrinsic` declaration is refused:

```
error: 'intrinsic' is allowed only in the intrinsics package
  note: this build binds the intrinsics package to 'Core', not 'Scratch'
  help: give the declaration a body, or bind 'Scratch' with 'Intrinsics' in [Package]
```

`Core` has no other privilege: the compiler does not recognise it by name. A program that does not want `Core` binds a package of its own, and imports the same names from it.

## Five kinds

| Declaration                          | The compiler supplies          | The provider writes                      |
| ------------------------------------ | ------------------------------ | ---------------------------------------- |
| `intrinsic const Infinity: float64;` | the value                      | the name and type, in an `extend` block  |
| `intrinsic #target: Target;`         | each field the struct declares | the struct, with the fields it exposes   |
| `intrinsic func Assert(…);`          | the code at every call         | the exact signature the compiler expects |
| `intrinsic func HasFeature(…);`      | the answer, while compiling    | the method, in an `extend` of its struct |
| `intrinsic interface Copyable;`      | which types satisfy it         | the name                                 |

A provider package, declaring a little of each beside the constants it adds to built-in types:

```rux
// A built-in type needs no declaration. Its constants are ordinary source in an extension.
extend int8 {
    pub const Min: int8 = -128i8;
    pub const Max: int8 = 127i8;
}

// A constant no literal can spell.
extend float64 {
    pub intrinsic const Infinity: float64;
}

// A compiler-supplied value, exposing only the fields this provider chooses.
pub struct Target {
    pub pointerBits: uint;
}

pub intrinsic #target: Target;

// Functions the compiler emits at each call.
pub intrinsic func Assert(condition: bool, message: char8[..]);
pub intrinsic func #Error(message: char8[..]);

// A capability the compiler decides for itself.
pub intrinsic interface Copyable;
```

A program binds it in its manifest:

```toml
[Package]
Name = "App"
Version = "0.1.0"
Type = "Executable"
Intrinsics = "Basis"

[Dependencies]
Basis = { Path = "../Basis" }
```

and imports the same kinds of names it would otherwise take from `Core`, which work the same way. Importing `int8` and `float64` imports the provider's extensions of those built-in types:

```rux
import Basis::{ #target, #Error, Assert, Copyable, float64, int8 };

func Twice<T: Copyable>(value: T) -> (T, T) {
    return (value, value);
}

func Main() -> int {
    when #target.pointerBits < 64 {
        #Error("needs a 64-bit target");
    }
    Assert(int8::Max == 127i8, "the provider's constant");
    Assert(float64::Infinity > 1.0e308, "a compiler-supplied constant");
    let pair = Twice(3);
    return pair.0 - 3;
}
```

Only what the provider declares is available: with `Basis` alone, `int16` still exists as a type, but `int16::Max` does not, and `import Basis::int16;` is refused:

```
error: package 'Basis' declares no extension of primitive type 'int16'
  help: a primitive type needs no import; import it only from a package that declares 'extend int16 { ... }'
```

## Where `Core` declares them

| Module              | Intrinsics                                                                                  |
| ------------------- | ------------------------------------------------------------------------------------------- |
| `Core::Compilation` | `#target`, `#build`, `#compiler`, `#source`, `#config` and their `HasFeature`, `Get`, `Has` |
| `Core::Diagnostics` | `Assert`, `DebugAssert`, `Panic`, `#Error`, `#Warn`                                         |
| `Core::Machine`     | the atomic operations, `Fence`, `SpinHint`, `Zeroize`, `ProcessStartFrame`                  |
| `Core::Ownership`   | the capabilities `Copyable` and `Sendable`                                                  |
| `Core::Arithmetic`  | the numeric capabilities `Integer`, `SignedInteger` and `Float`                             |
| `Core::Primitives`  | the floating-point limits, and `Truncate` on every integer type                             |
| `Core::Convert`     | `ConvertBits`, which `Core` keeps to itself and uses to build its public conversions        |

## Primitive types are not intrinsics

Every primitive type is built into the compiler — `int8` … `int512`, `uint8` … `uint512`, `int`, `uint`, `float8` … `float512`, `bool8` … `bool512`, `char8` … `char512`, and the aliases `bool`, `byte`, `char` and `float` — so no package declares one, and `intrinsic type` no longer exists:

```
error: intrinsic type declarations have been removed; primitive types are built in
  help: declare its associated constants in 'extend int8 { ... }' instead
```

A primitive's representation exists everywhere; an extension supplies its _API_. That is why `int8::Max` needs `import Core::Primitives::int8;` while the type `int8` does not — see [Imports](/docs/lang/modules/imports#compile-time-values-and-primitive-constants).

## Constants

Associated constants are normally plain source (`pub const Max: int8 = 127i8;`). The only compiler-supplied ones are the floating-point limits `Max`, `Lowest`, `MinPositive`, `Epsilon`, `Infinity` and `NaN`, at every width from `float8` to `float512`. Each is declared without an initializer in an `extend` of its own type, and has that type:

```rux
extend float128 {
    pub intrinsic const Max: float128;
    pub intrinsic const Epsilon: float128;
}
```

`Max` is the largest finite value, `Lowest` its negation, `MinPositive` the smallest positive normal value, `Epsilon` the gap between one and the next value up, and `NaN` a quiet NaN. `Core` declares `Infinity` and `NaN` this way at every width, and all six for `float80` and wider, whose limits are too long to be worth spelling in decimal; it writes the finite limits of `float8` through `float64` as literals. Any other name, or a type other than the extended one, is refused:

```
error: intrinsic associated constants support only floating-point Infinity, NaN, Max, Lowest, MinPositive and Epsilon
error: intrinsic associated constant must have its owning floating-point type
```

A [`when` condition](/docs/lang/comptime/conditional#conditions) keeps each floating-point width and computes exactly, so it reads every one of these constants at every width, including the finite limits of `float80` and wider.

## Compile-time values

`intrinsic #name: Root;` declares a value the compiler fills in. The type names which value it is — one of the structs `Target`, `Build`, `Source`, `Compiler` or `Config` — and the `#` name is how code refers to it. `Core` uses `#target`, `#build`, `#source`, `#compiler` and `#config`.

The struct may declare any subset of the fields the compiler supplies for its root, and nothing else, since nothing would fill a field it does not know:

```
error: field 'wordSize' of 'Target' is not one the compiler supplies for '#target'
  help: remove 'wordSize'; the compiler supplies 'os', 'arch', 'abi', 'endian', 'pointerBits', 'dataModel', 'objectFormat', 'triple'
error: 'Widget' is not a value the compiler supplies for '#thing'
  help: declare '#thing' with one of 'Target', 'Build', 'Source', 'Compiler', 'Config'
```

The fields themselves are listed in [Context](/docs/lang/comptime/context). Field visibility is ordinary: a field the provider leaves private cannot be read by another package, in an expression or in a `when` condition.

## Functions

`intrinsic func` names a function the compiler implements, so only those it knows are accepted:

| Intrinsic                                                                                                   | Signature                                                           | Purpose                                                                  |
| ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| `Assert`                                                                                                    | `(condition: bool, message: char8[..])`                             | stop the program unless `condition` holds                                |
| `DebugAssert`                                                                                               | `(condition: bool, message: char8[..])`                             | the same, removed without debug assertions                               |
| `Panic`                                                                                                     | `(message: char8[..])`                                              | stop the program                                                         |
| `#Error`                                                                                                    | `(message: char8[..])`                                              | stop the build — see [Diagnostics](/docs/lang/comptime/diagnostics)      |
| `#Warn`                                                                                                     | `(message: char8[..])`                                              | warn during the build                                                    |
| `Truncate`                                                                                                  | method `<T>(&self) -> T`, in an `extend` of an integer type         | the low bits at another integer width, without the range check `as` adds |
| `ConvertBits`                                                                                               | `<From, To>(value: From) -> To`                                     | the conversion `as` makes, without its range check, for generic code     |
| `Zeroize`                                                                                                   | `(memory: *var uint8, length: uint64)`                              | a clearing write the optimizer may not remove                            |
| `AtomicLoad`, `AtomicStore`, `AtomicExchange`, `AtomicCompareExchange`, `AtomicFetchAdd` … `AtomicFetchXor` | generic over `T`, taking a raw pointer to a `T` and a `MemoryOrder` | [atomic operations](/docs/lang/memory/atomics)                           |
| `Fence`, `SpinHint`                                                                                         | `(order: MemoryOrder)`, `()`                                        | a memory fence and a spin-loop hint                                      |
| `ProcessStartFrame`                                                                                         | `() -> *uint`                                                       | the address the kernel started the program at, where its arguments are   |
| `Target.HasFeature`                                                                                         | method `(&self, feature: TargetFeature) -> bool`                    | [`#target.HasFeature`](/docs/lang/comptime/context#target)               |
| `Compiler.HasFeature`                                                                                       | method `(&self, feature: char8[..]) -> bool`                        | [`#compiler.HasFeature`](/docs/lang/comptime/context#compiler)           |
| `Config.Get`, `Config.Has`                                                                                  | methods `(&self, name: char8[..]) -> char8[..]` / `-> bool`         | [`#config`](/docs/lang/comptime/config)                                  |

An intrinsic that takes a raw pointer, such as `Zeroize` or an atomic operation, is called like any other function. What it requires of the pointer is stated in a `Safety:` sentence of its `///` documentation, and by convention a `// Safety:` comment above the call says why that holds there — see [Raw operations](/docs/lang/pointers/overview#raw-operations). Nothing marks the declaration: `pub intrinsic unsafe func …` is `'unsafe' is not supported`. Checked integer arithmetic is not an intrinsic: `CheckedAdd`, `CheckedSub` and `CheckedMul` are ordinary `Core` methods of every integer type that return `T?`, `none` when the result does not fit.

A method intrinsic is declared inside an `extend` of its struct, which is what gives it its `Type.Name` key:

```rux
extend Target {
    pub intrinsic func HasFeature(&self, feature: TargetFeature) -> bool;
}
```

The diagnostic intrinsics are checked against their signatures, because the compiler emits the call in its own shape:

```
error: 'Square' is not a supported intrinsic function
  help: give the function a body, or declare a foreign function in an 'extern' block
error: intrinsic 'DebugAssert' must be declared as 'func DebugAssert(condition: bool, message: char8[..])'
  note: parameter 'condition' has type 'int'
error: 'intrinsic' function cannot have a body
```

## Capabilities

`intrinsic interface Name;` declares a bound the compiler decides from what a type is, rather than from an `extend`. It knows five:

| Capability      | Satisfied by                                                                                                       |
| --------------- | ------------------------------------------------------------------------------------------------------------------ |
| `Copyable`      | plain data — see [Copy and move](/docs/lang/ownership/copy-and-move)                                               |
| `Sendable`      | every type except a reference and a type that is or holds an [`#Unsendable`](/docs/lang/attributes/unsendable) one |
| `Integer`       | an integer of any width; implies `Copyable`                                                                        |
| `SignedInteger` | a signed integer of any width; implies `Integer`                                                                   |
| `Float`         | a floating-point number of any width; implies `Copyable`                                                           |

`Integer`, `SignedInteger` and `Float` admit the operators of their numbers on a value of the type parameter — see [Bounds](/docs/lang/generics/bounds). An ordinary interface that happens to share one of these names means nothing to the compiler. An `intrinsic interface` with any other name is refused where it is declared, since the compiler would have no rule to decide it by. A capability is only ever a bound:

```
error: 'Frobnicable' is not a supported intrinsic interface
  note: the compiler decides 'Copyable', 'Sendable', 'Integer', 'SignedInteger' and 'Float'
  help: declare an ordinary interface, which a type implements in an 'extend' block
error: 'Copyable' is decided by the compiler and cannot be implemented
  note: whether a type is 'Copyable' follows from what the type is
error: 'Copyable' is only a bound, not the type of a value
  help: write it on a type parameter, as in 'func Twice<T: Copyable>(value: T)'
```

## Not intrinsics

Slices, ranges, optionals, fallibles and sums are native types with no declaration at all. `intrinsic struct` does not exist (`error: intrinsic aggregate declarations have been removed; use native slice or range types`), and an ordinary struct never gains compiler-owned behaviour from its name. An `intrinsic` declaration can only bind what the compiler already implements; it cannot add a feature.
