# Initialization

::note
<!-- sync:needs:start -->

**You'll need**: [Else if](/docs/learn/else-if), [Constructor](/docs/learn/constructor)
<!-- sync:needs:end -->

::

A `var` may be declared before its value is known, and given one later. Until then it is _empty storage_ (memory of the right type that holds no value), and the compiler tracks it: every path that reaches a read must have assigned it first. A read that some path can reach without an assignment is rejected at compile time, so a Rux program never sees leftover garbage from an unassigned variable.

This is the last lesson of the part, and it closes the circle on ownership. A value's life ends with its destructor; this lesson is about how it begins, and why the compiler must always know whether a variable holds a value at all.

## Declare now, assign later

Sometimes the value depends on a decision that has not been made yet. `grade` is declared with a type and no value, and each branch of an [`else if`](/docs/learn/else-if) chain assigns it:

```rux
func Grade(score: int32) -> char8[..] {
    var grade: char8[..];
    if score >= 90 {
        grade = "excellent";
    } else if score >= 50 {
        grade = "pass";
    } else {
        grade = "retry";
    }
    return grade;
}
```

The compiler follows every path from the declaration to the `return`, and on each one `grade` has been assigned. The read is accepted.

```mermaid
flowchart TD
    d["`var grade: char8[..]`<br/>empty storage"] --> q{"`score`?"}
    q -- "`>= 90`" --> a1["`grade =`<br/>`excellent`"]
    q -- "`>= 50`" --> a2["`grade =`<br/>`pass`"]
    q -- "`else`" --> a3["`grade =`<br/>`retry`"]
    a1 --> r["`return grade`<br/>assigned on every path"]
    a2 --> r
    a3 --> r
    r ~~~ x["without the final `else`:<br/>`error: value 'grade' may be`<br/>`uninitialized on some`<br/>`control-flow paths`"]
```

Delete the final `else`, and a score below 50 reaches the `return` with nothing assigned. The compiler refuses the program and points at where that path starts.

## Reading too early

The simplest case is a read straight after the declaration:

```rux
var total: int32;
PrintLine("{}", total);
```

```
error: variable 'total' is used before it is initialized
  note: 'total' was declared without an initializer at 47:5
  help: assign a value to 'total' before this use
```

Many languages would print whatever happened to be in that memory, or a silent zero. Rux makes you say what the value is.

## A let needs its value now

A `let` has no such freedom. It can never be assigned later, so it needs its value where it is declared: `let total: int32;` on its own is rejected with `error: immutable variable requires an initializer`.

## Nothing is built behind your back

Empty storage is empty even when the type has a [constructor](/docs/learn/constructor). `Tally` has one, `Tally::New`:

```rux
extend Tally {
    func New() -> Tally {
        PrintLine("    Tally::New() starts the count at zero");
        return Tally { count: 0 };
    }
}
```

Declaring `var tally: Tally;` would not call it. The variable would hold nothing, so `tally.count += 1`, which reads the count before changing it, would be refused just as the read of `total` was. A variable that should start from a constructor calls it by name, as its initializer:

```rux
var tally = Tally::New();
tally.count += 1;
```

The output shows the constructor's line before the count, because the call is right there in the source.

| Declaration                 | Starts as                              |
| --------------------------- | -------------------------------------- |
| `var grade: char8[..];`     | empty storage: assign before reading   |
| `var tally: Tally;`         | empty storage too: no constructor runs |
| `var tally = Tally::New();` | whatever `Tally::New()` returns        |
| `let total: int32;`         | an error: a `let` needs its value      |

## One field at a time

A plain struct of numbers may be filled in one field at a time, and it counts as assigned once every field has been written. The compiler tracks the fields individually: after `var p: Point; p.x = 1;`, reading `p.x` is fine, but reading `p.y` is refused, with a note that only `p.x` has been written.

A type that needs destroying is different. When a struct holds a `Guest` — the type with a destructor from the [Destructor](/docs/learn/destructor) lesson — a guest written into one field of an empty struct would belong to no whole value, and nothing would ever destroy it. So such a variable must get its value whole:

```rux
var table: Table;
table.guest = Guest { name: "Gus" };
```

```
error: cannot write field 'guest' of 'table', which holds no value
  note: 'table' was declared without a value at 59:5
  note: 'Table' needs destruction, and a value written into a part of storage that holds none would never be destroyed
  help: initialize 'table' whole, as in 'table = Table { ... }'
```

It is the same rule as in [Replace and swap](/docs/learn/replace-swap), seen from the other end: a value with a destructor is alive whole, or not at all.

## Every path or none

A variable that needs destroying has one more rule. Nothing records while the program runs whether it holds a value, so at the end of its scope the compiler must already know whether there is a guest to destroy. Assigning it on some paths only is therefore refused:

```rux
var seated: Guest;
if early {
    seated = Guest { name: "Gus" };
}
```

```
error: 'seated' is assigned on this path only, so nothing could tell later whether it holds a value
  note: a value that may be absent is a 'Guest?'
  help: assign 'seated' on every path or on none
```

The note names the fix when absence is really what you mean: an [optional](/docs/learn/optional), `var seated: Guest? = none;`, which does record whether a guest is there. A plain number has nothing to destroy, so it only needs assigning before it is read.

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/Ownership/Initialization). Its comments explain every step.

<!-- sync:program:start -->

```rux [Src/Main.rux]
// A `var` may be declared before its value is known, and given one later. Until then it holds
// nothing, and the compiler tracks it: every path that reaches a read must have assigned it
// first. A read that some path can reach without an assignment is rejected at compile time, so
// a Rux program never sees leftover garbage from an unassigned variable.
//
// A `let` has no such freedom. It cannot be assigned later, so it needs its value where it is
// declared.
//
// Nothing is built behind your back. `var value: T;` is empty storage even when `T` has a
// constructor; a variable that should start from one calls it by name, `var value = T::New();`.
import Io::PrintLine;

// Every branch assigns `grade`, so the read in `return` is accepted. Delete the final `else` and
// one path reaches the read with nothing assigned:
//
// error: value 'grade' may be uninitialized on some control-flow paths
//   note: one unavailable path for 'grade' originates at 20:5
//   help: initialize or preserve 'grade' on every path before this use
func Grade(score: int32) -> char8[..] {
    var grade: char8[..];
    if score >= 90 {
        grade = "excellent";
    } else if score >= 50 {
        grade = "pass";
    } else {
        grade = "retry";
    }
    return grade;
}

struct Tally {
    count: int32;
}

extend Tally {
    func New() -> Tally {
        PrintLine("    Tally::New() starts the count at zero");
        return Tally { count: 0 };
    }
}

func Main() -> int {
    PrintLine("grades: {}, {}, {}", Grade(95), Grade(72), Grade(31));

    // Declared without a value and read straight away:
    //
    //     var total: int32;
    //     PrintLine("{}", total);
    //
    // error: variable 'total' is used before it is initialized
    //   note: 'total' was declared without an initializer at 47:5
    //   help: assign a value to 'total' before this use

    // When the type needs destroying, a variable without a value must also get its value whole.
    // Here `Table` is a struct holding a `Guest`, the type with a destructor from the Destructor
    // lesson. A guest written into one field would belong to no whole table, and nothing would
    // ever destroy it:
    //
    //     var table: Table;
    //     table.guest = Guest { name: "Gus" };
    //
    // error: cannot write field 'guest' of 'table', which holds no value
    //   note: 'table' was declared without a value at 59:5
    //   note: 'Table' needs destruction, and a value written into a part of storage that holds
    //         none would never be destroyed
    //   help: initialize 'table' whole, as in 'table = Table { ... }'
    //
    // Such a variable is also assigned on every path or on none. Nothing records at run time
    // whether it holds a guest, so the end of its scope could not tell whether to destroy one:
    //
    //     var seated: Guest;
    //     if early {
    //         seated = Guest { name: "Gus" };
    //     }
    //
    // error: 'seated' is assigned on this path only, so nothing could tell later whether it holds
    //        a value
    //   note: a value that may be absent is a 'Guest?'
    //   help: assign 'seated' on every path or on none

    // `var tally: Tally;` would run no constructor, so `tally.count += 1` would read empty
    // storage and be refused as `total` was above. The constructor is called where it is wanted.
    PrintLine("tally:");
    var tally = Tally::New();
    tally.count += 1;
    PrintLine("    count {}", tally.count);
    return 0;
}
```

## Common mistakes

::mistake
**A path that never assigns.**\
Without the final `else` in `Grade`, `return grade;` fails with:

```text
error: value 'grade' may be uninitialized on some control-flow paths
  help: initialize or preserve 'grade' on every path before this use
```

Every branch that can reach the read must assign: add the missing `else`, or give the variable a sensible starting value.
::

::mistake
**Expecting a constructor to run.**\
`var tally: Tally; tally.count += 1;` fails with:

```text
error: variable 'tally' is used before it is initialized
  help: assign a value to 'tally' before this use
```

A declaration without a value runs no constructor, even when the type has one. Call it by name: `var tally = Tally::New();`. In the same way there is no hidden zero for a number. If zero is what you mean, write `var total: int32 = 0;`.
::

::mistake
**A `let` without a value.**\
`let total: int32;` fails with:

```text
error: immutable variable requires an initializer
```

Declare it with `var` if it must be assigned later, or give it its value on the spot.
::

::mistake
**Assigning a guest on one path only.**\
`var seated: Guest;` assigned inside an `if` with no `else` fails with:

```text
error: 'seated' is assigned on this path only, so nothing could tell later whether it holds a value
  help: assign 'seated' on every path or on none
```

Assign it on every path, or declare it as an optional, `var seated: Guest? = none;`, when it may really be absent.
::

## Try it yourself

1. Delete the final `else` in `Grade` and read the error and its note.
2. Declare `struct Point { x: int32; y: int32; }`, then `var p: Point; p.x = 1;`, and print `p.y`. Then assign `p.y` too and print both.
3. Change `var tally = Tally::New();` to `var tally: Tally;`. Which line is now rejected, and does the constructor's line still print?
4. Copy `Guest` from the [Destructor](/docs/learn/destructor) lesson and write a function that takes `early: bool`, declares `var seated: Guest? = none;`, and seats a guest only when `early` is true. Call it with `true` and `false`. When does the guest leave?
