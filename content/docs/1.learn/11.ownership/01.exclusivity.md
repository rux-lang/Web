# Exclusivity

::note
<!-- sync:needs:start -->

**You'll need**: [Mutable reference](/docs/learn/mutable-reference), [Reference](/docs/learn/reference)
<!-- sync:needs:end -->

::

This part is about _ownership_: which name a value belongs to, who may change it, and when it is cleaned up. It starts with a rule you have already bumped into. A `&var` loan is **exclusive**: while it is alive, it is the only way to reach the value. No second `&var` loan, and no reading the value by its own name either. Read-only `&` loans have no such limit, because any number of readers can look at a value without harming it.

"While it is alive" is shorter than it looks. A loan ends at its **last use**, not at the end of the block it was made in, so a loan that has finished its work is no obstacle.

## A loan is written where it starts

`Merge` moves everything from one account into another. It takes both as `&var`, because it changes both:

```rux
func Merge(into: &var Account, from: &var Account) {
    into.balance += from.balance;
    from.balance = 0;
}
```

The call lends both accounts for writing, and says so:

```rux
var alice = Account { owner: "Alice", balance: 100 };
var bob = Account { owner: "Bob", balance: 20 };
```

```rux
Merge(&var alice, &var bob);
```

`&var alice` lends `alice` for writing, and `&alice` would lend it for reading. The `&var` is never left out: a reader who sees `Merge(&var alice, &var bob)` knows, without opening `Merge`, that both accounts may change on that line. Write `Merge(alice, &var bob)` and the compiler refuses, and its help spells out the fix:

```text
error: 'Merge' writes its argument 'alice', so the loan must be written
  help: write '&var alice'
```

Two different accounts make two exclusive loans that do not overlap, so all is well. Alice ends with 120 and Bob with 0.

Not every loan has to be spelled out. The rule is about what a reader would otherwise miss:

| The argument…                                | Written          |
| -------------------------------------------- | ---------------- |
| is changed by the callee                     | `&var x`, always |
| owns resources, and the callee only reads it | `&x`, always     |
| is borrowed by the callee's result           | `&x` or `&var x` |
| is plain data the callee only reads          | `x`, or `&x`     |
| is the receiver of a method, `x.Method()`    | `x`              |
| is a name that already holds a reference     | `x`              |

An account is plain data, so a read-only loan of it and a copy of it cannot be told apart, and the `&` may go. The [Give away](/docs/learn/give-away) and [Destructor](/docs/learn/destructor) lessons meet values that own something, where it may not.

## Why the rule exists

`Merge` is written for two _different_ accounts. Follow what it would do if `into` and `from` were the same one, with a balance of 100:

1. `into.balance += from.balance` — the balance becomes 200.
2. `from.balance = 0` — but `from` is `into`, so the balance becomes 0.

Merging an account with itself would wipe out the money. Nothing in `Merge` is wrong; it simply assumes its two parameters are two things. Exclusivity makes that assumption safe, by making the bad call impossible to write:

```rux
Merge(&var alice, &var alice);
```

```text
error: call arguments create overlapping exclusive borrows of 'alice'
  note: an earlier argument borrows the same storage at 47:11
  help: split the accesses into non-overlapping calls
```

The note points at the first `&var alice`, the loan the second one would overlap.

## Readers may share

Read-only loans may overlap freely. `Richer` takes two `&Account` and changes neither, so the same account twice is fine:

```rux
func Richer(left: &Account, right: &Account) -> char8[..] {
    let owner = if left.balance >= right.balance { left.owner } else { right.owner };
    return owner;
}
```

```rux
PrintLine("richer of Alice and Alice: {}", Richer(alice, alice));
```

An account is plain data, so the call passes it bare. `Richer(&alice, &alice)` is accepted too, and means the same.

| While this is alive… | Another `&` loan | Another `&var` loan | Reading by name | Writing by name |
| -------------------- | ---------------- | ------------------- | --------------- | --------------- |
| a `&` loan           | yes              | no                  | yes             | no              |
| a `&var` loan        | no               | no                  | no              | no              |

## A loan ends at its last use

A loan does not have to be an argument. Here `wallet` is a local `&var` loan of `alice`:

```rux
let wallet = &var alice;
wallet.balance -= 30;
wallet.balance -= 20;
PrintLine("after spending: Alice {}", alice.balance);
```

`wallet` already holds a reference, so it is used bare: `wallet.balance` writes through to `alice`. The second `wallet` line is its last use, and from there on `alice` is free again, so reading it by name on the next line is accepted.

```mermaid
flowchart LR
    b["`let wallet = &var alice`"] --> u1["`wallet.balance -= 30`"]
    u1 --> u2["`wallet.balance -= 20`<br/>last use: the loan ends"]
    u2 --> r["`alice.balance`<br/>free again"]
    u1 -. "reading `alice` here<br/>is refused" .-> x["`error: cannot read 'alice.balance'`<br/>`while 'wallet' holds an exclusive borrow`"]
```

Move that `PrintLine` above the second `wallet` line and `wallet` is still alive when `alice` is read. The compiler refuses, and its help names both ways out: read through `wallet`, or wait until its last use.

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/Ownership/Exclusivity). Its comments explain every step.

<!-- sync:program:start -->

```rux [Src/Main.rux]
// A `&var` borrow is exclusive. While it is alive, it is the only way to reach the value: no
// second `&var` borrow, and no reading the value by its own name either. Read-only `&` borrows
// have no such limit, because any number of readers can look at a value without harming it.
//
// "While it is alive" is shorter than it looks. A borrow ends at its last use, not at the end of
// the block it was made in, so a borrow that has finished its work is no obstacle.
//
// A loan is written where it starts: `&var alice` lends `alice` for writing, and `&alice` for
// reading. The `&var` is never left out, so every call that may change a value says so at the call.
//
// The rule exists for functions like `Merge` below. It takes two accounts and is written for two
// different ones. Handed the same account twice, it would add the balance to itself and then wipe
// it out. Exclusivity makes that call impossible to write.
import Io::PrintLine;

struct Account {
    owner: char8[..];
    balance: int32;
}

// Moves everything from one account into another.
func Merge(into: &var Account, from: &var Account) {
    into.balance += from.balance;
    from.balance = 0;
}

// Two read-only borrows of the same account are fine: neither can change it.
func Richer(left: &Account, right: &Account) -> char8[..] {
    let owner = if left.balance >= right.balance { left.owner } else { right.owner };
    return owner;
}

func Main() -> int {
    var alice = Account { owner: "Alice", balance: 100 };
    var bob = Account { owner: "Bob", balance: 20 };

    // Two different accounts: two exclusive borrows that do not overlap. Leave out a `&var` and
    // the call is refused, since nothing at the call would show that `alice` changes:
    //
    // error: 'Merge' writes its argument 'alice', so the loan must be written
    //   help: write '&var alice'
    Merge(&var alice, &var bob);
    PrintLine("after merge: Alice {}, Bob {}", alice.balance, bob.balance);

    // The same account twice is refused:
    //
    //     Merge(&var alice, &var alice);
    //
    // error: call arguments create overlapping exclusive borrows of 'alice'
    //   note: an earlier argument borrows the same storage at 47:11
    //   help: split the accesses into non-overlapping calls

    // Shared borrows may overlap freely. An account is plain data, so a read needs no `&`: a copy
    // and a read-only loan of it cannot be told apart.
    PrintLine("richer of Alice and Alice: {}", Richer(alice, alice));

    // A local `&var` borrow. Its last use is the second line below, and from there on `alice`
    // is free again, so reading it by name is accepted.
    let wallet = &var alice;
    wallet.balance -= 30;
    wallet.balance -= 20;
    PrintLine("after spending: Alice {}", alice.balance);

    // Move that `PrintLine` above the second `wallet` line and `wallet` is still alive when
    // `alice` is read:
    //
    // error: cannot read 'alice.balance' while 'wallet' holds an exclusive borrow
    //   note: exclusive borrow begins at 59:18
    //   help: read through 'wallet' or wait until its last use
    return 0;
}
```

## Common mistakes

::mistake
**Leaving out the `&var` at the call.**\
`Merge(alice, &var bob)` fails with:

```text
error: 'Merge' writes its argument 'alice', so the loan must be written
  help: write '&var alice'
```

A callee that writes its argument always gets a written `&var` loan, so the change is visible where the call is.
::

::mistake
**Passing one value to two `&var` parameters.**\
`Merge(&var alice, &var alice)` fails with:

```text
error: call arguments create overlapping exclusive borrows of 'alice'
```

Each `&var` argument must be a different value.
::

::mistake
**Reading a value while a `&var` loan of it is still in use.**\
With a later `wallet` line still to come, reading `alice.balance` fails with:

```text
error: cannot read 'alice.balance' while 'wallet' holds an exclusive borrow
  help: read through 'wallet' or wait until its last use
```

Read through `wallet` instead, or move the read after the last use of `wallet`.
::

::mistake
**Lending for writing while a reader is still in use.**\
`let view = &alice;` followed by `let wallet = &var alice;`, with `view` used again later, fails with:

```text
error: cannot borrow exclusively 'alice' while it is immutably borrowed
```

A reader expects the value not to change under it, so a writer has to wait until the reader is done.
::

## Try it yourself

1. Add a third account, `carol`, and merge both others into her with two calls to `Merge`.
2. Move the `PrintLine` with `alice.balance` above the second `wallet` line and read the error. Then change it to print `wallet.balance` instead. Is that accepted?
3. Make two local `&var` loans of `alice`, one after the other, where the first is finished before the second begins. Does the compiler allow it?
