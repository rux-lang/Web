# Give away

::note
<!-- sync:needs:start -->

**You'll need**: [Copy](/docs/learn/copy), [Exclusivity](/docs/learn/exclusivity)
<!-- sync:needs:end -->

::

A [copy](/docs/learn/copy) leaves two values behind. Giving a value **away** leaves one: the value is handed to its new owner, and the old name is finished. Nothing is written for it. Plain data is copied, as the last lesson showed, and a value that must not be duplicated is given away, in every place a copy would happen.

A relay baton is the picture to keep in mind. One runner holds it at a time, and once it has been handed on, the runner who passed it no longer has it. The compiler enforces exactly that: any later use of a name whose value was given away is an error.

For a `Baton` holding one number, the point of giving it away is not speed. It is what is left afterwards — and in the lessons after this one, that becomes the difference between a value cleaned up once and a value cleaned up twice.

## A value that is never copied

A `Baton` is one number, so on its own it would be plain data and copy like a [`Point`](/docs/learn/copy). The attribute `#NoCopy` turns that off:

```rux
#NoCopy
struct Baton {
    laps: int32;
}

struct Team {
    name: char8[..];
    baton: Baton;
}
```

From then on a baton used by value is given away, never copied. The [Non-copyable types](/docs/learn/no-copy) lesson comes back to the attribute. A type with a destructor, the [next lesson](/docs/learn/destructor), needs no attribute: it owns something, so it is given away the same way.

## Four places a value is given away

A value is given away in the same places a copy happens. What is written does not change; the type decides:

| Where              | Written                 | Plain data | A baton    |
| ------------------ | ----------------------- | ---------- | ---------- |
| A binding          | `let taken = value;`    | copied     | given away |
| An argument        | `Run(value)`            | copied     | given away |
| A return           | `return value;`         | copied     | given away |
| A field of a value | `Team { baton: value }` | copied     | given away |

## A binding

```rux
let baton = Baton { laps: 0 };

// A binding takes the baton over.
let first = baton;
```

`first` now holds the baton. `baton` still exists as a name in the source, but it no longer holds anything, and the compiler will not let you read it:

```text
error: 'baton' is used after it was given away
  note: 'baton' was given away at 42:5
  help: lend it with '&baton' where it is only read, or clone it where both uses need a value
```

The help names the two ways to keep using `baton`: lend it with `&baton`, so that it stays where it is, or make a second baton on purpose with a `Clone` method, as [Custom copy](/docs/learn/custom-copy) writes one.

## An argument and a return

`Run` takes the baton, runs one lap with it, and hands it back:

```rux
func Run(baton: Baton, runner: char8[..]) -> Baton {
    var held = baton;
    held.laps += 1;
    PrintLine("{} runs lap {}", runner, held.laps);
    return held;
}
```

A parameter cannot be changed, so `var held = baton;` gives it to a mutable local: still one baton, just under a new name. `return held;` gives it on to the caller.

The caller passes the baton along the line of runners:

```rux
let second = Run(first, "Ana");
let third = Run(second, "Ben");
let last = Run(third, "Cleo");
```

Each call gives up a name: after the first line, `first` is finished, after the second, `second`, and so on. One baton runs three laps.

What a call _returns_ is a fresh value that nobody else holds, so the binding simply takes it. The same is true of any value made on the spot: there is no old name to give up:

```rux
let spare = Run(Baton { laps: 0 }, "Dev");
```

## Reading a part copies it

Reading a field of plain data copies the field, not the whole value:

```rux
PrintLine("laps run: {}", last.laps);
```

The number of laps is an `int32`, so `last.laps` is a copy of a number, and `last` is left whole.

## A field of a new value

Building a value from another gives that one away too:

```rux
let team = Team { name: "Relay", baton: last };
```

The team takes the baton over, and `last` is finished.

## Matching a loan keeps the value

A `match` takes its subject like any other place a value goes. Matching a loan, `&team`, lends the team to the arms instead, and it stays put:

```rux
match &team {
    Team { name, baton } => PrintLine("{} finished with {} laps", name, baton.laps),
}
PrintLine("{} still holds the baton", team.name);
```

Write `match team` and the `PrintLine` after it is refused with "'team' is used after it was given away". An `if let` on a named value works the same way: `if let … = team` takes it, and `if let … = &team` lends it.

## Copy, give away or lend

You now have three ways to hand a value to someone else:

```mermaid
flowchart LR
    a(["`a`: a value<br/>with a name"])
    a -- "`let b = a`<br/>plain data" --> c["copied: two values<br/>`a` and `b` both usable,<br/>each changes alone"]
    a -- "`let b = a`<br/>a baton" --> m["given away: one value,<br/>now `b`'s<br/>`a` is finished"]
    a -- "`let b = &a`<br/>a loan" --> r["lent: one value,<br/>still `a`'s<br/>`b` refers to it"]
```

|                   | Copied             | Given away     | Lent, `&` / `&var`   |
| ----------------- | ------------------ | -------------- | -------------------- |
| Values afterwards | two                | one            | one                  |
| The old name      | still usable       | finished       | still the owner      |
| The new name      | owns its own value | owns the value | owns nothing; refers |

## Given away on some paths

The compiler tracks values through loops and branches. A value given away inside a loop is checked against the next pass too: the first pass would take the baton, and the second would find nothing left to take:

```rux
for lap in 0..3 {
    let runner = first;
}
```

```text
error: 'first' is given away inside a loop, and the next pass would use it again
  note: 'first' is given away at 56:9
  help: give 'first' a new value before the pass ends, or leave the loop after giving it away
```

A value given away inside an `if` and used after it is refused too: on the path where the `if` ran, the value is gone.

```text
error: value 'first' may have been given away on some control-flow paths
```

A `var` whose value was given away is not ruined for good. Assigning it a new value with `=` gives it something to hold again, and from then on it can be read as before.

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/Ownership/GiveAway). Its comments explain every step.

<!-- sync:program:start -->

```rux [Src/Main.rux]
// A copy leaves two values behind. Giving a value away leaves one: the value is handed to its new
// owner and the old name is finished. Nothing is written for it. Plain data is copied, as Copy
// showed, and a value that must not be duplicated is given away, in every place a copy would
// happen:
//
//     let taken = value;          a binding
//     Run(value)                  an argument
//     return value;               a return
//     Team { baton: value }       a field of a new value
//
// A relay baton is the picture to keep in mind. One runner holds it at a time, and once it has
// been handed on, the runner who passed it no longer has it. The compiler enforces exactly that:
// any later use of a name whose value was given away is an error.
//
// `#NoCopy` marks `Baton` as such a value. The NoCopy lesson comes back to the attribute, and a
// type with a destructor, the next lesson, is given away the same way.
import Io::PrintLine;

#NoCopy
struct Baton {
    laps: int32;
}

struct Team {
    name: char8[..];
    baton: Baton;
}

// Takes the baton, runs one lap with it, and hands it back. A parameter cannot be changed, so
// `var held = baton;` gives it to a mutable local: still one baton, just under a new name.
func Run(baton: Baton, runner: char8[..]) -> Baton {
    var held = baton;
    held.laps += 1;
    PrintLine("{} runs lap {}", runner, held.laps);
    return held;
}

func Main() -> int {
    let baton = Baton { laps: 0 };

    // A binding takes the baton over.
    let first = baton;

    // From here on, `baton` cannot be used:
    //
    //     PrintLine("{}", baton.laps);
    //
    // error: 'baton' is used after it was given away
    //   note: 'baton' was given away at 42:5
    //   help: lend it with '&baton' where it is only read, or clone it where both uses need a value
    //
    // A value given away inside a loop is checked against the next pass too. The first pass would
    // take the baton, and the second would find nothing left to take:
    //
    //     for lap in 0..3 {
    //         let runner = first;
    //     }
    //
    // error: 'first' is given away inside a loop, and the next pass would use it again
    //   note: 'first' is given away at 56:9
    //   help: give 'first' a new value before the pass ends, or leave the loop after giving it away

    // Arguments and returns. What a call returns is a fresh value that nobody else holds, and the
    // binding simply takes it.
    let second = Run(first, "Ana");
    let third = Run(second, "Ben");
    let last = Run(third, "Cleo");

    // The number of laps is plain data, so reading it copies the number and leaves `last` whole.
    PrintLine("laps run: {}", last.laps);

    // The same is true of any value made on the spot. There is no old name to give up.
    let spare = Run(Baton { laps: 0 }, "Dev");
    PrintLine("spare laps: {}", spare.laps);

    // A field of a new value: the team takes the baton over, and `last` is finished.
    let team = Team { name: "Relay", baton: last };

    // A `match` takes its subject like any other place a value goes. Matching a loan, `&team`,
    // lends the team to the arms instead, and it stays put. Write `match team` and the next line
    // is refused with "'team' is used after it was given away".
    match &team {
        Team { name, baton } => PrintLine("{} finished with {} laps", name, baton.laps),
    }
    PrintLine("{} still holds the baton", team.name);
    return 0;
}
```

## Common mistakes

::mistake
**Using a name after its value was given away.**\
After `let first = baton;`, `PrintLine("{}", baton.laps)` fails with:

```text
error: 'baton' is used after it was given away
```

The note points at the line where it was given away. Lend it with `&baton` where it is only read, or write a `Clone` method when both names really need a baton.
::

::mistake
**Giving a value away inside a loop.**\
`let runner = first;` in a loop body fails with:

```text
error: 'first' is given away inside a loop, and the next pass would use it again
```

The second pass would have nothing to take. Give the value away before the loop, assign the name a new value before the pass ends, or leave the loop with `break` right after giving it away.
::

::mistake
**Giving one field away.**\
`let baton = team.baton;` fails with:

```text
error: 'baton' is a field of 'team' and cannot be given away by itself
```

The team would be left half alive, without its baton. Only a whole local, a parameter or a temporary is given away. [Replace and swap](/docs/learn/replace-swap) shows the ways the help suggests to take a field out while leaving the value whole.
::

## Try it yourself

1. Add `PrintLine("{}", baton.laps);` right after `let first = baton;` and read the error, its note and its help.
2. Change `match &team` to `match team`. Which line is refused now, and why?
3. Declare `var reserve = Baton { laps: 0 };`, give it away with `let used = reserve;`, then assign it `Baton { laps: 7 }` and print the laps of both.
