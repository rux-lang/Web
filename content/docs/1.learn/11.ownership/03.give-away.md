# Give away

::note
<!-- sync:needs:start -->

**You'll need**: [Copy](/docs/learn/copy), [Exclusivity](/docs/learn/exclusivity)
<!-- sync:needs:end -->

::

A [copy](/docs/learn/copy) leaves two values behind. A _move_ leaves one: the value is handed to its new owner, and the old name is finished. Rux writes a move as `move value`, so the word itself tells a reader which name stops working on that line.

A relay baton is the picture to keep in mind. One runner holds it at a time, and once it has been handed on, the runner who passed it no longer has it. The compiler enforces exactly that: any later use of a moved-from name is an error.

For a `Baton` holding one number, the point of a move is not speed. It is what is left afterwards — and in the lessons after this one, that becomes the difference between a value cleaned up once and a value cleaned up twice.

## Three places to move

A move works in the same three places a copy happens. Only the `move` in front of the name changes:

| Where       | Copy                 | Move                      |
| ----------- | -------------------- | ------------------------- |
| A binding   | `let taken = value;` | `let taken = move value;` |
| An argument | `Run(value)`         | `Run(move value)`         |
| A return    | `return value;`      | `return move value;`      |

## A binding

```rux
let baton = Baton { laps: 0 };
let first = move baton;
```

`first` now holds the baton. `baton` still exists as a name in the source, but it no longer holds anything, and the compiler will not let you read it:

```
error: value 'baton' is used after it was moved
  note: 'baton' was moved at 31:17
  help: clone 'baton' before moving it if both uses are required
```

## An argument and a return

`Run` takes the baton, runs one lap with it, and hands it back:

```rux
func Run(baton: Baton, runner: char8[..]) -> Baton {
    var held = move baton;
    held.laps += 1;
    PrintLine("{} runs lap {}", runner, held.laps);
    return move held;
}
```

A parameter cannot be changed, so `var held = move baton` moves it into a mutable local: still one baton, just under a new name. `return move held` hands it on to the caller.

The caller passes the baton along the line of runners:

```rux
let second = Run(move first, "Ana");
let third = Run(move second, "Ben");
let last = Run(move third, "Cleo");
```

Each `move` gives up a name: after the first line, `first` is finished, after the second, `second`, and so on. One baton runs three laps, and `last.laps` is 3.

## Fresh values need no `move`

What a call _returns_ is a fresh value that nobody else holds, so `=` simply takes it — there is no old name to give up, and nothing to copy from. `let second = Run(…)` above is already a move in all but spelling.

The same is true of any value made on the spot:

```rux
let spare = Run(Baton { laps: 0 }, "Dev");
```

`move` is for a value that has a name. It is there so that a reader can see, at a glance, which names stop working on that line.

## Copy, move or borrow

You now have three ways to hand a value to someone else:

```mermaid
flowchart LR
    a(["`a`: a value<br/>with a name"])
    a -- "`let b = a`<br/>copy" --> c["two values<br/>`a` and `b` both usable,<br/>each changes alone"]
    a -- "`let b = move a`<br/>move" --> m["one value, now `b`'s<br/>`a` is finished"]
    a -- "`let b: &T = a`<br/>borrow" --> r["one value, still `a`'s<br/>`b` refers to it"]
```

|                   | Copy `=`           | Move `move`    | Borrow `&` / `&var`  |
| ----------------- | ------------------ | -------------- | -------------------- |
| Values afterwards | two                | one            | one                  |
| The old name      | still usable       | finished       | still the owner      |
| The new name      | owns its own value | owns the value | owns nothing; refers |

## Moves on some paths

The compiler tracks moves through loops and branches. A move inside a loop is checked against the next pass too — the first pass would take the baton, and the second would find nothing left to take:

```rux
for lap in 0..3 {
    let runner = move first;
}
```

```
error: value 'first' may have been moved on some control-flow paths
  help: initialize or preserve 'first' on every path before this use
```

The same error appears when a move happens inside an `if` and the name is used after it: on the path where the `if` ran, the value is gone.

A moved-from `var` is not ruined for good. Assigning it a new value with `=` gives it something to hold again, and from then on it can be read as before.

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/Ownership/Move). Its comments explain every step.

<!-- sync:program:start -->

```rux [Src/Main.rux]
// A copy leaves two values behind. Giving a value away leaves one: the value is handed to its new
// owner and the old name is finished. Nothing is written for it. Plain data is copied, as Copy
// showed, and a value that must not be duplicated is given away, in every place a copy would
// happen:
//
//     let taken = value;          a binding
//     Run(value)                  an argument
//     return value;               a return
//     Team { baton: value }       a field of a new value
//
// A relay baton is the picture to keep in mind. One runner holds it at a time, and once it has
// been handed on, the runner who passed it no longer has it. The compiler enforces exactly that:
// any later use of a name whose value was given away is an error.
//
// `#NoCopy` marks `Baton` as such a value. The NoCopy lesson comes back to the attribute, and a
// type with a destructor, the next lesson, is given away the same way.
import Io::PrintLine;

#NoCopy
struct Baton {
    laps: int32;
}

struct Team {
    name: char8[..];
    baton: Baton;
}

// Takes the baton, runs one lap with it, and hands it back. A parameter cannot be changed, so
// `var held = baton;` gives it to a mutable local: still one baton, just under a new name.
func Run(baton: Baton, runner: char8[..]) -> Baton {
    var held = baton;
    held.laps += 1;
    PrintLine("{} runs lap {}", runner, held.laps);
    return held;
}

func Main() -> int {
    let baton = Baton { laps: 0 };

    // A binding takes the baton over.
    let first = baton;

    // From here on, `baton` cannot be used:
    //
    //     PrintLine("{}", baton.laps);
    //
    // error: 'baton' is used after it was given away
    //   note: 'baton' was given away at 42:5
    //   help: lend it with '&baton' where it is only read, or clone it where both uses need a value
    //
    // A value given away inside a loop is checked against the next pass too. The first pass would
    // take the baton, and the second would find nothing left to take:
    //
    //     for lap in 0..3 {
    //         let runner = first;
    //     }
    //
    // error: 'first' is given away inside a loop, and the next pass would use it again
    //   note: 'first' is given away at 56:9
    //   help: give 'first' a new value before the pass ends, or leave the loop after giving it away

    // Arguments and returns. What a call returns is a fresh value that nobody else holds, and the
    // binding simply takes it.
    let second = Run(first, "Ana");
    let third = Run(second, "Ben");
    let last = Run(third, "Cleo");

    // The number of laps is plain data, so reading it copies the number and leaves `last` whole.
    PrintLine("laps run: {}", last.laps);

    // The same is true of any value made on the spot. There is no old name to give up.
    let spare = Run(Baton { laps: 0 }, "Dev");
    PrintLine("spare laps: {}", spare.laps);

    // A field of a new value: the team takes the baton over, and `last` is finished.
    let team = Team { name: "Relay", baton: last };

    // A `match` takes its subject like any other place a value goes. Matching a loan, `&team`,
    // lends the team to the arms instead, and it stays put. Write `match team` and the next line
    // is refused with "'team' is used after it was given away".
    match &team {
        Team { name, baton } => PrintLine("{} finished with {} laps", name, baton.laps),
    }
    PrintLine("{} still holds the baton", team.name);
    return 0;
}
```

## Common mistakes

::mistake
**Using a name after moving from it.**\
After `let first = move baton;`, `PrintLine("{}", baton.laps)` fails with:

```text
error: value 'baton' is used after it was moved
```

The note points at the line of the move. If both names really need a value, copy with a plain `=` instead of moving.
::

::mistake
**Moving inside a loop.**\
`let runner = move first;` in a loop body fails with:

```text
error: value 'first' may have been moved on some control-flow paths
```

The second pass would have nothing to take. Move before the loop, or give each pass a value of its own.
::

::mistake
**Moving inside a branch, then using the name.**\
`if ready { let first = move baton; }` followed by `baton.laps` fails the same way:

```text
error: value 'baton' may have been moved on some control-flow paths
```

The compiler does not know whether the `if` ran, so it assumes the worst.
::

## Try it yourself

1. Add a fourth runner, Dana, to the relay, and print the laps run.
2. Add `PrintLine("{}", baton.laps);` after `let first = move baton;` and read the error and its note.
3. Change `Run(move first, "Ana")` to `Run(first, "Ana")`. The program still compiles — why? Print `first.laps` at the end: which baton does `first` still hold?
4. Declare `var baton`, move it into `first`, then assign it a new `Baton { laps: 7 }` and print both.
