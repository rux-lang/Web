# Non-copyable types

::note
<!-- sync:needs:start -->

**You'll need**: [Destructor](/docs/learn/destructor), [Give away](/docs/learn/give-away)
<!-- sync:needs:end -->

::

A hotel key stands for a room. The key itself is plain data — a room number — so the compiler would happily [copy](/docs/learn/copy) it, and then two guests could each check out of the same room. For a type like this the automatic copy is wrong, and Rux lets the type turn it off.

Once copying is off, a key used by value is [given away](/docs/learn/give-away), never copied. One key, one owner, one checkout — and the compiler checks all three.

## Turning copying off

The attribute `#NoCopy` on the declaration says "this type has no copy":

```rux
#NoCopy
struct RoomKey {
    room: int32;
}
```

That is all. `RoomKey` keeps its one `int32` field and needs no `extend` block; it simply stops being copyable.

A type with a [destructor](/docs/learn/destructor) needs no attribute: it owns resources, so it is already never copied. `#NoCopy` is for plain data that must still never be duplicated, such as a handle that something else releases. Its sibling `#NoMove` goes further and keeps a value in the place where it was built.

## Given away, never copied

`CheckIn` builds a new key and returns it, and `Main` binds it to `key`:

```rux
func CheckIn(room: int32) -> RoomKey {
    PrintLine("    key {} issued", room);
    return RoomKey { room: room };
}
```

```rux
let key = CheckIn(12);
```

From then on, writing `key` where a value goes hands the key on. A binding takes it:

```rux
let friend = key;
PrintLine("    friend holds key {}", friend.room);
```

`friend` holds the key now, and `key` is empty. A spare key would be a copy, and there is none to make — taking the key a second time is refused:

```rux
let spare = key;
```

```
error: 'key' is used after it was given away
  note: 'key' was given away at 53:5
  help: lend it with '&key' where it is only read, or clone it where both uses need a value
```

Passing by value gives the key away too. `CheckOut` takes it, so after the call nobody holds it any more:

```rux
// Takes the key, so after this call nobody holds it any more.
func CheckOut(key: RoomKey) {
    PrintLine("    checking out of room {}", key.room);
    PrintLine("    key {} handed back", key.room);
}
```

```rux
CheckOut(friend);
```

## Looking without taking

A function that only needs to look at a key takes `&RoomKey`, and the caller writes the loan:

```rux
// Only looks at the key, so the caller keeps it.
func Show(key: &RoomKey) {
    PrintLine("    key {} opens room {}", key.room, key.room);
}
```

```rux
Show(&key);
```

For plain data that is only read, the `&` could be left out: the compiler would lend the value for you. A `#NoCopy` type is treated like any value that owns something, so here the loan must be written — which also means every place that only _looks_ at a key says so in the source.

```mermaid
flowchart LR
    k(["`key: RoomKey`<br/>`#NoCopy`"]) -- "`Show(&key)`" --> b["lent for the call<br/>`key` still holds it"]
    k -- "`let friend = key`" --> f["`friend` holds the key<br/>`key` is empty"]
    f -- "`let spare = key`" --> x["`error: 'key' is used`<br/>`after it was given away`"]
    f -- "`CheckOut(friend)`" --> c["checked out<br/>nobody holds it"]
```

## Everywhere a copy would happen

Every by-value use of a named key gives it away. Only a written loan leaves it where it is:

| Where          | Written                | Afterwards               |
| -------------- | ---------------------- | ------------------------ |
| A binding      | `let friend = key;`    | `key` is empty           |
| An argument    | `CheckOut(friend)`     | `friend` is empty        |
| A return       | `return key;`          | the caller holds the key |
| A struct field | `Booking { key: key }` | `key` is empty           |
| An assignment  | `first = second;`      | `second` is empty        |
| A loan         | `Show(&key)`           | `key` still holds it     |

The rule also spreads outwards. A struct with a `RoomKey` field cannot be copied either — copying it would copy the key — so `let copy = booking;` gives the whole `booking` away, and a later use of `booking` is refused the same way.

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/Ownership/NoCopy). Its comments explain every step.

<!-- sync:program:start -->

```rux [Src/Main.rux]
// A hotel key stands for a room. The key itself is plain data, a room number, so the compiler
// would happily copy it, and then two guests could each check out of the same room. For a type
// like this the automatic copy is wrong, and Rux lets the type turn it off.
//
// The attribute `#NoCopy` on the declaration says "this type has no copy":
//
//     #NoCopy
//     struct RoomKey { room: int32; }
//
// From then on a key used by value is given away, never copied, as GiveAway showed: `let spare =
// key;` leaves `key` empty, and a second use of it is an error. One key, one owner, one checkout.
// Looking at a key without taking it is a loan, and the loan is written, `&key`, as for any
// value that owns something.
//
// A type with a destructor needs no attribute: it owns resources, so it is already never copied,
// as Destructor showed. `#NoCopy` is for plain data that must still never be duplicated, such as
// a handle that something else releases. (Its sibling `#NoMove` goes further and keeps a value
// where it was built.)
import Io::PrintLine;

#NoCopy
struct RoomKey {
    room: int32;
}

func CheckIn(room: int32) -> RoomKey {
    PrintLine("    key {} issued", room);
    return RoomKey { room: room };
}

// Only looks at the key, so the caller keeps it.
func Show(key: &RoomKey) {
    PrintLine("    key {} opens room {}", key.room, key.room);
}

// Takes the key, so after this call nobody holds it any more.
func CheckOut(key: RoomKey) {
    PrintLine("    checking out of room {}", key.room);
    PrintLine("    key {} handed back", key.room);
}

func Main() -> int {
    PrintLine("check in:");
    let key = CheckIn(12);

    // A loan leaves the key where it is. Leave out the `&` and the call is refused:
    //
    // error: 'Show' borrows its argument, and 'RoomKey' owns resources, so the loan must be written
    //   help: write '&key'
    Show(&key);

    PrintLine("give the key to a friend:");
    let friend = key;
    PrintLine("    friend holds key {}", friend.room);

    // A spare key would be a copy, and there is none to make. The binding above gave the key
    // away, so taking it a second time is refused:
    //
    //     let spare = key;
    //
    // error: 'key' is used after it was given away
    //   note: 'key' was given away at 53:5
    //   help: lend it with '&key' where it is only read, or clone it where both uses need a value

    // Passing by value gives the key away too, so after the checkout `friend` is finished.
    PrintLine("check out:");
    CheckOut(friend);
    PrintLine("    done");
    return 0;
}
```

## Common mistakes

::mistake
**Lending a key without writing the loan.**\
`Show(key)` fails with:

```text
error: 'Show' borrows its argument, and 'RoomKey' owns resources, so the loan must be written
  help: write '&key'
```

Plain data that is only read may be lent bare, but a `#NoCopy` type is treated as owning something, and its loans are written: `Show(&key)`.
::

::mistake
**Using a key after giving it away.**\
After `let friend = key;`, any later use of `key` — `let spare = key;`, or even `Show(&key)` — fails with:

```text
error: 'key' is used after it was given away
  help: lend it with '&key' where it is only read, or clone it where both uses need a value
```

The note points at the line that gave the key away. Lend the key there instead if you still need it afterwards, or use the name that holds it now, `friend`.
::

::mistake
**Turning copying off with a bodyless `=`.**\
Declaring `func =(&var self, other: &RoomKey);` in `extend RoomKey`, without the attribute, does not prohibit anything:

```text
error: a bodyless 'func =' does not prohibit copying
  help: mark 'RoomKey' with '#NoCopy' instead
```

The attribute is the only spelling, and like every attribute without arguments it takes no parentheses — `#NoCopy()` is refused with `'#NoCopy' is written without parentheses`.
::

## Try it yourself

1. Remove `#NoCopy`, add `let spare = key;` after the friend's line, and print `spare.room`. It compiles and runs — what has gone wrong in the hotel?
2. Write `func Spare(room: int32) -> RoomKey` that stores a new key in a `let` before returning it with `return key;`. Does the `return` need anything special?
3. Make two `var` keys and replace the first with `first = second;`. Can `second` still be read afterwards?
4. Declare `struct Booking { guest: char8[..]; key: RoomKey; }`, build one, bind it again with `let copy = booking;`, and then print `booking.guest`. What does the error say?
