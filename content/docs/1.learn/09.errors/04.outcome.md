# Outcome

::note
<!-- sync:needs:start -->

**You'll need**: [Fail](/docs/learn/fail), [Match expression](/docs/learn/match-expression)
<!-- sync:needs:end -->

::

A call that can fail is usually handled right where it is made, so it leaves nothing to keep. Sometimes, though, an _outcome_ has to outlive the call: it is stored in a variable, passed to a function and looked at later. Nothing extra is needed for that, because the call's result already is the outcome. Keep it.

## Keep the fallible

`Share` deals out pizza slices and fails when there is nobody to share them with:

```rux
func Share(slices: int, people: int) -> int ! NobodyToShare {
```

Each call's outcome is stored first and examined afterwards:

```rux
let party = Share(12, 4);
let empty = Share(12, 0);
Describe(party);
Describe(empty);
```

`party` and `empty` are both `int ! NobodyToShare`: the same [fallible](/docs/learn/fallible) every call gives back, simply not taken apart yet. A fallible is an ordinary value. It sits in a local, travels as a parameter, and is matched whenever it is needed:

```rux
func Describe(outcome: int ! NobodyToShare) {
```

## Matching the sides by type

The sides of a fallible can be matched by type. The typed pattern `each: int` matches the side whose type is `int` and binds the value as a plain `int`; `error: NobodyToShare` matches the error side:

```rux
match outcome {
    .Success(0) => PrintLine("not even one slice each"),
    each: int => PrintLine("{} slices each", each),
    error: NobodyToShare => PrintLine("{} slices and nobody to eat them", error.slices)
}
```

A literal still needs its side named, so the first arm is `.Success(0)`; the typed arms take everything else.

| Pattern                | Matches                      | Binds                      |
| ---------------------- | ---------------------------- | -------------------------- |
| `.Success(0)`          | a success of 0               | nothing                    |
| `each: int`            | any success                  | the value, an `int`        |
| `error: NobodyToShare` | any error                    | the error                  |
| `_: NobodyToShare`     | any error                    | nothing                    |
| `.Failure(pattern)`    | an error the pattern matches | whatever the pattern binds |

Order matters, as in every [match](/docs/learn/match-expression): the first arm that matches wins, so `.Success(0)` comes before `each: int`. Put it after, and the compiler refuses it as unreachable: the typed arm already takes every success, the zero included.

## A success converts, an error is thrown

A success converts to a fallible on its own, the way a value becomes a present optional:

```rux
let promised: int ! NobodyToShare = 2;
Describe(promised);
```

There is no such shortcut for an error. It gets in only through `throw`, so a failure always comes from a call that failed.

## A value per side, and is

A match can also produce a value, one per side, and `is` asks which side a fallible holds:

```rux
let eaten = match party {
    each: int => each * 4,
    _: NobodyToShare => 0
};
PrintLine("eaten at the party: {}", eaten);
PrintLine("the empty party failed: {}", empty is NobodyToShare);
```

Twelve slices shared among four is three each, so four people eat 12. `empty is NobodyToShare` is `true` when `empty` holds an error, and `empty is int` would be `true` for a success. The test only looks: it binds nothing, and the fallible is still there to match afterwards.

```mermaid
flowchart LR
    call["`Share(12, 0)`"] --> kept["`let empty`<br/>an `int ! NobodyToShare`"]
    kept --> pass["passed to `Describe`"]
    kept --> test["`empty is NobodyToShare`<br/>a `bool`"]
    kept --> m["`match empty`<br/>one arm per side"]
```

## When both sides share a type

`ExactShare` fails with the slices left over, so both of its sides are an `int`:

```rux
func ExactShare(slices: int, people: int) -> int ! int {
```

On an `int ! int`, a typed arm such as `each: int` could mean either side, so the compiler refuses it. `.Success(...)` and `.Failure(...)` name the side instead:

```rux
match ExactShare(10, 4) {
    .Success(each) => PrintLine("{} slices each, none left", each),
    .Failure(left) => PrintLine("{} slices left over", left)
}
```

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/Errors/Outcome). Its comments explain every step.

<!-- sync:program:start -->

```rux [Src/Main.rux]
// A call that can fail is usually handled right where it is made, so it leaves nothing to keep.
// Sometimes an outcome has to outlive the call: it is stored in a variable, passed to a function
// and looked at later. Nothing extra is needed for that, because the call's result already is
// the outcome. Keep it:
//
//     let party = Share(12, 4);    // an `int ! NobodyToShare`
//
// A fallible is an ordinary value. It sits in a local, travels as a parameter of type
// `int ! NobodyToShare`, and is matched whenever it is needed.
//
// Its sides can be matched by type. The typed pattern `each: int` matches the side whose type is
// `int` and binds the value as a plain `int`; `error: NobodyToShare` matches the error side. When
// both sides have the same type, a type cannot say which side it means, and `.Success(...)` and
// `.Failure(...)` name the side instead.
import Io::PrintLine;

struct NobodyToShare {
    slices: int;
}

// Shares out pizza slices evenly. It fails when there is nobody to share them with.
func Share(slices: int, people: int) -> int ! NobodyToShare {
    if people == 0 {
        throw NobodyToShare { slices: slices };
    }
    return slices / people;
}

// A stricter share that fails with the slices left over. Both sides are an `int`.
func ExactShare(slices: int, people: int) -> int ! int {
    if slices % people != 0 {
        throw slices % people;
    }
    return slices / people;
}

// A kept outcome arrives as a parameter like any other value. A literal still needs its side
// named, so the first arm is `.Success(0)`; the typed arms take everything else.
func Describe(outcome: int ! NobodyToShare) {
    match outcome {
        .Success(0) => PrintLine("not even one slice each"),
        each: int => PrintLine("{} slices each", each),
        error: NobodyToShare => PrintLine("{} slices and nobody to eat them", error.slices)
    }
}

func Main() -> int {
    // Each call's outcome is stored first and examined afterwards.
    let party = Share(12, 4);
    let empty = Share(12, 0);
    Describe(party);
    Describe(empty);
    Describe(Share(3, 4));

    // A success converts to a fallible on its own, the way a value becomes a present optional.
    // An error gets in only through `throw`, so a failure always comes from a call that failed.
    let promised: int ! NobodyToShare = 2;
    Describe(promised);
    Describe(Share(8, 0));

    // A match can also produce a value, one per side, and `is` asks which side a fallible holds.
    let eaten = match party {
        each: int => each * 4,
        _: NobodyToShare => 0
    };
    PrintLine("eaten at the party: {}", eaten);
    PrintLine("the empty party failed: {}", empty is NobodyToShare);

    // On an `int ! int` a typed arm such as `each: int` could mean either side, so the compiler
    // refuses it: "cannot match 'int ! int' by type, because both sides are 'int'". The sides are
    // named instead.
    match ExactShare(10, 4) {
        .Success(each) => PrintLine("{} slices each, none left", each),
        .Failure(left) => PrintLine("{} slices left over", left)
    }

    // A match on a fallible must cover both sides. Drop the `NobodyToShare` arm in `Describe` and
    // the compiler refuses: "match on 'int ! NobodyToShare' is not exhaustive; missing
    // _: NobodyToShare". A failure can never slip through unnoticed.
    return 0;
}
```

## Common mistakes

::mistake
**Forgetting the error side.**\
Drop the `NobodyToShare` arm from `Describe` and the compiler refuses:

```text
error: match on 'int ! NobodyToShare' is not exhaustive; missing _: NobodyToShare
```

A match on a fallible must cover both sides, so a failure can never slip through unnoticed.
::

::mistake
**Matching an `int ! int` by type.**\
Write `each: int` in the `ExactShare` match and it fails with:

```text
error: cannot match 'int ! int' by type, because both sides are 'int'
help: handle the error with 'catch { ... }', which sees only the error side
```

Name the sides with `.Success(...)` and `.Failure(...)`, as the program does.
::

::mistake
**A bare literal arm.**\
`0 => PrintLine("not even one slice each")` in `Describe` is refused:

```text
error: this pattern cannot match native fallible 'int ! NobodyToShare'
help: match a side by its type, as in 'value: T', or with '.Success(...)' or '.Failure(...)'
```

A literal does not say which side it belongs to. Write `.Success(0)`.
::

::mistake
**Storing an error as a fallible.**\
`let promised: int ! NobodyToShare = NobodyToShare { slices: 2 };` is an error:

```text
error: cannot assign 'NobodyToShare' to 'int ! NobodyToShare'
```

Only a success converts. An error enters a fallible through `throw`, in the function that fails.
::

## Try it yourself

1. Add an arm to `Describe` that prints `"exactly one slice each"`, and call `Describe(Share(4, 4))`. Where in the match must the arm go?
2. Store `Share(7, 2)` in a variable, then use one `match` expression to work out how many slices two people eat, and print it.
3. Change the arms of the `ExactShare` match to `each: int` and `left: int` and read the error.
