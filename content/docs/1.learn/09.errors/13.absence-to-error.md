# Absence to error

::note
<!-- sync:needs:start -->

**You'll need**: [Coalesce](/docs/learn/coalesce), [Fail](/docs/learn/fail)
<!-- sync:needs:end -->

::

An [optional](/docs/learn/optional) says "nothing here" and stops there. `PriceOf(7)` returns `none`, and `none` cannot say which code was missing or why that matters. When absence is a real problem for the caller, turn it into an error that does say so.

## ?? throw

A small price list where an unknown code is simply absent:

```rux
func PriceOf(code: int) -> int? {
    return match code {
        1 => 250,
        2 => 120,
        3 => 75,
        _ => none
    };
}
```

`Total` needs a price, and a missing one is an error worth reporting:

```rux
func Total(code: int, quantity: int) -> int throws UnknownProduct {
    let price = PriceOf(code) ?? throw UnknownProduct { code: code };
    return price * quantity;
}
```

This is the `??` from [Coalesce](/docs/learn/coalesce), with `throw` as its fallback — just as [Coalesce exit](/docs/learn/coalesce-exit) used `return`. When the price is present, `price` is that number. When it is absent, the function throws right there, and the error can carry whatever context is at hand — here, the code that was not found.

```mermaid
flowchart LR
    look["`PriceOf(code)`"] --> q{"Present or `none`?"}
    q -- "present" --> price["`price` is the number;<br/>`Total` carries on"]
    q -- "`none`" --> thrown["`throw UnknownProduct { code }`"]
    thrown --> caller["the caller learns<br/>which code was missing"]
```

`PriceOf` itself cannot throw, so its call needs no `try`. Only `Total` throws, and `Order` handles that with a `try` block and one `catch` arm.

## The error is built only when needed

Like every `??` fallback, the right side runs only when it is needed. For a product that exists, the `UnknownProduct` value is never even built.

## Why not ?

On an optional, [`?`](/docs/learn/optional-propagate) passes the absence on — but only as absence. It works in a function that returns an optional, and `Total` returns an `int` and throws. `?` never invents an error for a missing value; `?? throw` is how you supply one yourself.

| You write                   | When the price is missing, `Total`…               |
| --------------------------- | ------------------------------------------------- |
| `PriceOf(code) ?? 0`        | carries on with 0, so the order costs nothing     |
| `PriceOf(code) ?? return …` | succeeds at once with the value given to `return` |
| `PriceOf(code)?`            | is rejected: `Total` does not return an optional  |
| `PriceOf(code) ?? throw …`  | throws, saying which code it was                  |

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/Errors/AbsenceToError). Its comments explain every step.

<!-- sync:program:start -->

```rux [Src/Main.rux]
// An optional says "nothing here" and stops there. `PriceOf(7)` returns
// `none`, and `none` cannot say which code was missing or why that matters.
// When absence is a real problem for the caller, turn it into an error that
// does say so:
//
//     let price = PriceOf(code) ?? throw UnknownProduct { code: code };
//
// This is the `??` from the optionals part with `throw` as its fallback. When
// the price is present, `price` is that number. When it is absent, the
// function throws right there, and the error can carry whatever context is at
// hand — here, the code that was not found.
//
// Like every `??` fallback, the right side runs only when it is needed, so
// the error is not even built for a product that exists.
import Io::PrintLine;

struct UnknownProduct {
    code: int;
}

// A small price list. An unknown code is simply absent.
func PriceOf(code: int) -> int? {
    return match code {
        1 => 250,
        2 => 120,
        3 => 75,
        _ => none
    };
}

func Total(code: int, quantity: int) -> int throws UnknownProduct {
    let price = PriceOf(code) ?? throw UnknownProduct { code: code };
    return price * quantity;
}

// The caller handles the error at the call: `try` marks the call that can
// throw, and the `catch` arm runs only when it does.
func Order(code: int, quantity: int) {
    try {
        let total = Total(code, quantity);
        PrintLine("{} x product {}: {} cents", quantity, code, total);
    } catch {
        e => PrintLine("{} x product {}: no product has code {}", quantity, code, e.code)
    }
}

func Main() -> int {
    Order(1, 2);
    Order(3, 4);
    Order(7, 1);
    return 0;
}
```

## Common mistakes

::mistake
**Using ? to turn absence into an error.**\
`let price = PriceOf(code)?;` in `Total` is an error:

```text
error: '?' propagates the absence of 'int?', but the enclosing function returns 'int throws UnknownProduct'
help: declare an optional result, as in '-> T?', or supply a fallback with '??'
```

Write `?? throw` with the error you mean.
::

::mistake
**?? throw in a function that does not throw.**\
In `Main`, `PriceOf(1) ?? throw UnknownProduct { code: 1 }` is an error:

```text
error: 'throw' needs a function that throws, but 'Main' returns 'int'
```

::

::mistake
**Comparing without parentheses.**\
`==` binds tighter than `??`, so `PriceOf(1) ?? 0 == 250` means `PriceOf(1) ?? (0 == 250)` and fails with:

```text
error: coalescing fallback has type 'bool8', but the optional payload is 'int'
```

Write `(PriceOf(1) ?? 0) == 250`.
::

## Try it yourself

1. Add product 4 at 990 cents and order three of them.
2. Refuse an order of zero items as well. One error struct no longer fits — try a variant with an `UnknownCode(int)` case and a `NoItems` case.
3. Change `Order(7, 1)` to use `PriceOf(7) ?? 0` directly in `Main` instead of `Total`. What does the customer pay for an unknown product?
