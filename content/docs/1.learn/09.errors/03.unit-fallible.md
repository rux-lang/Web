# Unit fallible

::note
<!-- sync:needs:start -->

**You'll need**: [Fail](/docs/learn/fail), [Mutable reference](/docs/learn/mutable-reference)
<!-- sync:needs:end -->

::

Some operations have no answer to give back. When a withdrawal works, the money is gone from the account and there is nothing more to say. But it can still fail, and the caller still needs to know.

Such a function declares only its error, after the parameters: `func Withdraw(...) throws ShortOfFunds`, with no return type.

## throws E with no return type

The success of such a function carries the _unit_ `()` — the empty [tuple](/docs/learn/tuple), whose only value is also written `()`. It is a success that carries no information beyond "it worked". Writing `-> () throws ShortOfFunds` means the same thing; the short form is what you will see everywhere:

```rux
func Withdraw(account: &var Account, amount: int) throws ShortOfFunds {
```

The account is a [mutable reference](/docs/learn/mutable-reference), so the function changes the caller's account in place. The only thing left to report is whether that happened.

## Three ways out

Because there is no value to return, the function succeeds simply by reaching its end. A bare `return;` succeeds early, and only `throw` makes it fail:

```rux
if amount == 0 {
    // Nothing to do, and that counts as success.
    return;
}
if amount > account.balance {
    throw ShortOfFunds { missing: amount - account.balance };
}
account.balance -= amount;
// Falling off the end: success.
```

| The function…             | The outcome               |
| ------------------------- | ------------------------- |
| reaches its closing brace | success                   |
| runs `return;`            | success, early            |
| runs `throw error;`       | failure, carrying `error` |

## Calling it

No value comes back, but the error still can, so the call is still marked with `try`. In a `try` block, the statement after the call runs only when the withdrawal worked:

```rux
try {
    Withdraw(account, amount);
    PrintLine("take {}: done, {} left", amount, account.balance);
} catch {
    error => PrintLine("take {}: refused, {} short", amount, error.missing)
}
```

There is nothing to bind on success, so there is no `let` — the call is a statement of its own. The single arm `error => ...` binds the `ShortOfFunds` and reads how much was missing.

The output follows the balance as it changes. Taking 0 succeeds without touching anything, 80 is refused while 60 is left, and the next 60 empties the account — so even 1 is refused after that.

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/Errors/UnitFallible). Its comments explain every step.

<!-- sync:program:start -->

```rux [Src/Main.rux]
// Some operations have no answer to give back. When a withdrawal works, the money is gone from
// the account and there is nothing more to say. Such a function declares only its error, after
// the parameters: `func Withdraw(...) throws ShortOfFunds`, with no return type.
//
// The success then carries the unit `()`, the empty tuple — a success that carries no
// information beyond "it worked". Because there is no value to return, the function succeeds
// simply by reaching its end. A bare `return;` succeeds early, and only `throw` makes it fail.
import Io::PrintLine;

struct Account {
    balance: int;
}

struct ShortOfFunds {
    missing: int;
}

// Changes the account in place; the only thing to report is whether that happened.
func Withdraw(account: &var Account, amount: int) throws ShortOfFunds {
    if amount == 0 {
        // Nothing to do, and that counts as success.
        return;
    }
    if amount > account.balance {
        throw ShortOfFunds { missing: amount - account.balance };
    }
    account.balance -= amount;
    // Falling off the end: success.
}

func Attempt(account: &var Account, amount: int) {
    // The call is still marked with `try`: it returns nothing, but it can throw. The statement
    // after it runs only when the withdrawal worked.
    try {
        Withdraw(account, amount);
        PrintLine("take {}: done, {} left", amount, account.balance);
    } catch {
        error => PrintLine("take {}: refused, {} short", amount, error.missing)
    }
}

func Main() -> int {
    var account = Account { balance: 100 };
    Attempt(account, 40);
    Attempt(account, 0);
    Attempt(account, 80);
    Attempt(account, 60);
    Attempt(account, 1);
    return 0;
}
```

## Common mistakes

::mistake
**Calling it as a plain statement.**\
`Withdraw(account, 40);` outside a `try` block is an error:

```text
error: call to 'Withdraw' can throw 'ShortOfFunds' but is not marked with 'try'
help: write 'try' before the expression
```

No value comes back, but the error still does. [Discard](/docs/learn/discard) explains how to ignore it on purpose.
::

::mistake
**Marking a call that cannot throw.**\
`Attempt` handles every error itself and declares no `throws`, so `try Attempt(account, 40);` in `Main` draws a warning:

```text
warning: 'try' has no call that can throw
```

`try` belongs on calls that can throw, and only there — it is how a reader spots every place an error can come from.
::

## Try it yourself

1. Change the signature to the long spelling `-> () throws ShortOfFunds` and check that the program still compiles and prints the same.
2. Add `Deposit(account: &var Account, amount: int) throws TooMuch` that refuses when the balance would pass 1000, and call it from a `try` block.
3. Put a second `Withdraw` call in `Attempt`'s `try` block. What does the program print when the first one is refused?
