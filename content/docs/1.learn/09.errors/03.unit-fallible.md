# Unit fallible

::note
<!-- sync:needs:start -->

**You'll need**: [Fail](/docs/learn/fail), [Mutable reference](/docs/learn/mutable-reference)
<!-- sync:needs:end -->

::

Some operations have no answer to give back. When a withdrawal works, the money is gone from the account and there is nothing more to say. But it can still fail, and the caller still needs to know.

Such a function declares only its error, with nothing before the `!`: `func Withdraw(...) -> !ShortOfFunds`.

## -> !E: only an error

The success of such a function carries the _unit_ `()`, the empty [tuple](/docs/learn/tuple), whose only value is also written `()`. It is a success that carries no information beyond "it worked". Writing `-> () ! ShortOfFunds` means the same thing; the short form is what you will see everywhere:

```rux
func Withdraw(account: &var Account, amount: int) -> !ShortOfFunds {
```

The account is a [mutable reference](/docs/learn/mutable-reference), so the function changes the caller's account in place. The only thing left to report is whether that happened.

## Three ways out

Because there is no value to return, the function succeeds simply by reaching its end. A bare `return;` succeeds early, and only `throw` makes it fail:

```rux
if amount == 0 {
    // Nothing to do, and that counts as success.
    return;
}
if amount > account.balance {
    throw ShortOfFunds { missing: amount - account.balance };
}
account.balance -= amount;
// Falling off the end: success.
```

| The function…             | The outcome               |
| ------------------------- | ------------------------- |
| reaches its closing brace | success                   |
| runs `return;`            | success, early            |
| runs `throw error;`       | failure, carrying `error` |

## Calling it

No value comes back on success, but the error still can, so the call still gives back a fallible, `!ShortOfFunds`. It is matched by side like any other:

```rux
match Withdraw(account, amount) {
    .Success(()) => PrintLine("take {}: done, {} left", amount, account.balance),
    .Failure(error) => PrintLine("take {}: refused, {} short", amount, error.missing)
}
```

The success side holds the unit, matched here as `.Success(())`. That arm runs only when the withdrawal worked, so it can report the new balance. The `.Failure(error)` arm binds the `ShortOfFunds` and reads how much was missing. Inside `Attempt`, `account` is already a mutable reference, so it is passed on as it is; `Main` writes the loan, `Attempt(&var account, 40)`.

The output follows the balance as it changes. Taking 0 succeeds without touching anything, 80 is refused while 60 is left, and the next 60 empties the account, so even 1 is refused after that.

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/Errors/UnitFallible). Its comments explain every step.

<!-- sync:program:start -->

```rux [Src/Main.rux]
// Some operations have no answer to give back. When a withdrawal works, the money is gone from
// the account and there is nothing more to say. Such a function declares only its error, with
// nothing before the `!`: `func Withdraw(...) -> !ShortOfFunds`.
//
// The success then carries the unit `()`, the empty tuple — a success that carries no
// information beyond "it worked". Because there is no value to return, the function succeeds
// simply by reaching its end. A bare `return;` succeeds early, and only `throw` makes it fail.
import Io::PrintLine;

struct Account {
    balance: int;
}

struct ShortOfFunds {
    missing: int;
}

// Changes the account in place; the only thing to report is whether that happened.
func Withdraw(account: &var Account, amount: int) -> !ShortOfFunds {
    if amount == 0 {
        // Nothing to do, and that counts as success.
        return;
    }
    if amount > account.balance {
        throw ShortOfFunds { missing: amount - account.balance };
    }
    account.balance -= amount;
    // Falling off the end: success.
}

func Attempt(account: &var Account, amount: int) {
    // The call still gives back a fallible, `!ShortOfFunds`, and it is matched by side like any
    // other. The success side holds the unit, matched here as `.Success(())`; that arm runs only
    // when the withdrawal worked.
    match Withdraw(account, amount) {
        .Success(()) => PrintLine("take {}: done, {} left", amount, account.balance),
        .Failure(error) => PrintLine("take {}: refused, {} short", amount, error.missing)
    }
}

func Main() -> int {
    var account = Account { balance: 100 };
    Attempt(&var account, 40);
    Attempt(&var account, 0);
    Attempt(&var account, 80);
    Attempt(&var account, 60);
    Attempt(&var account, 1);
    return 0;
}
```

## Common mistakes

::mistake
**Calling it as a plain statement.**\
`Withdraw(account, amount);` on its own line is an error:

```text
error: 'Withdraw' can fail with 'ShortOfFunds', and the result is not used
help: pass the error on with '!', ignore it with '!!;', or handle it with 'catch { ... }'
```

No value comes back, but the error still can. [Discard](/docs/learn/discard) explains how to ignore it on purpose.
::

::mistake
**Returning a value.**\
`return 0;` inside `Withdraw` is refused:

```text
error: 'return' value must have type '!ShortOfFunds', but found 'int'
```

A function declared `-> !E` has no success value to give. A bare `return;` is its early success.
::

::mistake
**Matching only the success.**\
Delete the `.Failure(error)` arm from `Attempt` and the match fails with:

```text
error: match on '!ShortOfFunds' is not exhaustive; missing _: ShortOfFunds
```

A unit success still leaves the error side to cover. The compiler names the missing side by the typed pattern that would take it.
::

## Try it yourself

1. Change the signature to the long spelling `-> () ! ShortOfFunds` and check that the program still compiles and prints the same.
2. Add `Deposit(account: &var Account, amount: int) -> !TooMuch` that refuses when the balance would pass 1000, and call it from `Main` with a match by side.
3. Delete the `if amount == 0` block from `Withdraw`. Does taking 0 still print `done`? Why?
