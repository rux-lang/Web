# Fail

::note
<!-- sync:needs:start -->

**You'll need**: [Fallible](/docs/learn/fallible), [Struct](/docs/learn/struct)
<!-- sync:needs:end -->

::

A function that can fail has two ways out. `return value;` is the success, as the [previous lesson](/docs/learn/fallible) showed. `throw` is the other one: it leaves the function at once through its error side, carrying an error value for the caller.

This lesson is a cash machine. A withdrawal either answers with the new balance or refuses — and when it refuses, it says exactly how much money was missing.

## The error is plain data

An error can be any type you like. Here it is a [struct](/docs/learn/struct), so it can report exactly what went wrong: how much the account held and how much was asked for:

```rux
struct ShortOfFunds {
    balance: int;
    requested: int;
}
```

There is nothing special about the type itself. It becomes an error only because a signature names it after the `!`:

```rux
func Withdraw(balance: int, amount: int) -> int ! ShortOfFunds {
```

## throw leaves at once

`throw ShortOfFunds { ... };` builds that struct and hands it over in one statement. Nothing after a `throw` runs, just as nothing after a `return` does:

```rux
if amount > balance {
    throw ShortOfFunds { balance: balance, requested: amount };
}
// Only reached when the money is there.
return balance - amount;
```

| Statement                     | Leaves through   | The caller gets           |
| ----------------------------- | ---------------- | ------------------------- |
| `return balance - amount;`    | the success side | the new balance, an `int` |
| `throw ShortOfFunds { ... };` | the error side   | a `ShortOfFunds`          |

A throw costs what a return costs: nothing unwinds the stack. The error travels back to the caller the way a returned value does, as the error side of the fallible the call gives back.

## Reading the details with catch

The caller writes `catch` after the call. It hands the error, and only the error, to its arm, which runs only when there is one. On success the arm is skipped and `left` is the `int` itself:

```rux
let left = Withdraw(balance, amount) catch {
    error => {
        PrintLine("take {} from {}: refused, {} short", amount, balance, error.requested - error.balance);
        return;
    }
};
PrintLine("take {} from {}: {} left", amount, balance, left);
```

The arm `error => ...` binds the whole error, and because it is a struct, the arm reads its fields like any other. The arm either produces a value of the success type or leaves; here it prints and returns, so the last line runs only when the money was there. [Catch](/docs/learn/catch) covers `catch` in full, with one arm per case of an error.

```mermaid
flowchart LR
    w["`Withdraw(100, 130)`"] --> q{"Which side?"}
    q -- "success" --> l["`left` is the new balance<br/>the next line prints it"]
    q -- "error" --> a["the arm gets the `ShortOfFunds`<br/>prints the shortfall, returns"]
```

Taking exactly the whole balance is fine: `amount > balance` is false for 100 and 100, so `Report(100, 100)` leaves 0. An empty account refuses even 5.

## Where throw is allowed

`throw` has two rules, and the compiler enforces both. Its value must have the error type named after the `!`: a `ShortOfFunds` here, not a number. And it belongs only in a function that can fail: `Main` returns a plain `int`, so a `throw` there has nowhere to go.

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/Errors/Fail). Its comments explain every step.

<!-- sync:program:start -->

```rux [Src/Main.rux]
// A function that can fail has two ways out. `return value;` is the success, as the previous
// lesson showed. `throw` is the other one: it leaves the function at once through its error side,
// carrying an error value for the caller.
//
// The error can be any type you like. Here it is a struct, so it can report exactly what went
// wrong: how much money the account held and how much was asked for.
// `throw ShortOfFunds { ... };` builds that struct and hands it over in one statement. Nothing
// after a `throw` runs, just as nothing after a `return` does. A throw costs what a return costs:
// nothing unwinds the stack.
import Io::PrintLine;

// The error: plain data describing the problem, nothing special about the type itself.
struct ShortOfFunds {
    balance: int;
    requested: int;
}

// Answers with the new balance, or throws the details of why it could not.
func Withdraw(balance: int, amount: int) -> int ! ShortOfFunds {
    if amount > balance {
        throw ShortOfFunds { balance: balance, requested: amount };
    }
    // Only reached when the money is there.
    return balance - amount;
}

// `catch` after the call hands the error, and only the error, to its arm, which runs only when
// there is one. On success the arm is skipped and `left` is the `int` itself. The arm either
// produces a value of the success type or leaves; here it prints and returns.
func Report(balance: int, amount: int) {
    let left = Withdraw(balance, amount) catch {
        error => {
            PrintLine("take {} from {}: refused, {} short", amount, balance, error.requested - error.balance);
            return;
        }
    };
    PrintLine("take {} from {}: {} left", amount, balance, left);
}

func Main() -> int {
    Report(100, 30);
    Report(100, 100);
    Report(100, 130);
    Report(0, 5);

    // `throw` must carry a value of the error type named after the `!`. `throw 30;` inside
    // `Withdraw` is rejected with "'throw' value must have type 'ShortOfFunds', but found 'int'".
    // And `throw` belongs only in a function that can fail: here in `Main`, which returns a plain
    // `int`, it is an error too: "'throw' needs a function that can fail, but 'Main' returns
    // 'int'".
    return 0;
}
```

## Common mistakes

::mistake
**Throwing the wrong type.**\
`throw 30;` inside `Withdraw` is rejected:

```text
error: 'throw' value must have type 'ShortOfFunds', but found 'int'
```

The error type is part of the signature, and every `throw` must match it.
::

::mistake
**throw in a function that cannot fail.**\
In `Main`, which returns `int`, a `throw` is an error:

```text
error: 'throw' needs a function that can fail, but 'Main' returns 'int'
help: leave 'Main' with an exit status, as in 'return 1;', or move the steps that can fail into a function and handle its error in 'Main', as in 'return Run() !! 1;'
```

`Main` is always `func Main() -> int` and cannot fail. In any other function the help is to declare the error: `declare '-> int ! E' on the function`. [Exit status](/docs/learn/exit-status) shows how `Main` handles an error instead.
::

::mistake
**An arm that neither produces a value nor leaves.**\
Delete the `return;` from the arm in `Report` and the block is refused:

```text
error: this block yields '()' because of the ';'
note: the block must yield a value of type 'int'
help: remove the ';' to yield the last expression
```

The arm stands in for the missing balance, so it must give an `int` or leave the function. Removing the `;` would not help here — `PrintLine` does not give an `int` — so put the `return;` back.
::

## Try it yourself

1. Add `Report(100, 101);` and predict the shortfall it prints.
2. Write `Deposit(balance: int, amount: int) -> int ! TooMuch` that refuses when the new balance would pass 1000, with a `TooMuch` struct that says by how much.
