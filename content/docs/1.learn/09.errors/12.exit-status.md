# Exit status

::note
<!-- sync:needs:start -->

**You'll need**: [Unit fallible](/docs/learn/unit-fallible), [Catch fallback](/docs/learn/catch-fallback), [Propagate](/docs/learn/propagate)
<!-- sync:needs:end -->

::

Every program so far ended with `return 0;` from `func Main() -> int`. That number is the program's _exit status_: 0 says it worked, anything else says it did not. It is for whoever started the program — a script, a build tool or a shell.

`func Main() -> int` is the only signature `Main` may have, and `Main` cannot fail. An error is not an exit status, so the program has to decide which status a failure means. This lesson shows the pattern that does it.

## Main cannot fail

The installer in this lesson reserves disk space for two programs. `Reserve` fails with a `SpaceError` when there is not enough room:

```rux
func Reserve(needed: int, free: int) -> int ! SpaceError {
```

It is tempting to let `Main` fail with the same error and pass each one on with `!`. The compiler refuses the signature: the result of `Main` is the exit status, and a fallible is not a number the operating system can receive.

## The steps that can fail get a function

So the steps that can fail move into a function of their own, `Install`. It returns no value, so it is declared `-> !SpaceError`, like the functions in [Unit fallible](/docs/learn/unit-fallible), and each `Reserve(...)!` passes its error on:

```rux
func Install() -> !SpaceError {
    var free = 100;
    PrintLine("Installing the editor (40 MB of {} MB free)", free);
    free = Reserve(40, free)!;
```

The second reservation asks for 90 MB with only 60 free, so its `!` passes the error out of `Install` — the last `PrintLine` never runs.

## Main decides what a failure means

`Main` calls `Install` and handles its error like any other, with the `!!` from [Catch fallback](/docs/learn/catch-fallback). The fallback here is not a value but a way out:

```rux
func Main() -> int {
    Install() !! return 1;
    return 0;
}
```

```mermaid
flowchart LR
    main["`Main`"] --> install["`Install()`"]
    install -- "success" --> ok["`return 0;`<br/>exit status 0"]
    install -- "error" --> fail["`!! return 1`<br/>exit status 1"]
```

Reaching `return 0;` means everything worked. When the helper works out the status itself, declared `-> int ! E`, `Main` is a single line:

```rux
return Run() !! 1;
```

| The helper is declared | `Main` handles it with   | Exit status on success | on failure |
| ---------------------- | ------------------------ | ---------------------- | ---------- |
| `-> !E`                | `Install() !! return 1;` | the `return` after it  | 1          |
| `-> int ! E`           | `return Run() !! 1;`     | the helper's `int`     | 1          |

Leaving with status 1 is an ordinary `return`, so every `defer` and destructor on the way out runs as usual — unlike a [panic](/docs/learn/panic), which stops at once.

## An error prints nothing

The surprise is what `!! return 1` does _not_ do: it prints nothing. The `SpaceError` value is not shown anywhere, so a user only sees the program stop after the second line.

The exit status is how the program reports to its caller. In a POSIX shell such as bash, `echo $?` shows it right after the program ends; in PowerShell, it is `echo $LASTEXITCODE`. That `1` is the last line of the output below.

If a person should learn _why_ the program stopped, print a message yourself. A [`catch`](/docs/learn/catch) arm in `Main` can do both — print, then leave with the status:

```rux
Install() catch {
    e => {
        PrintLine("Not enough space: {} MB needed, {} MB free", e.needed, e.free);
        return 1;
    }
};
```

The arm `e => ...` binds the whole error, and its block ends by leaving, so it never has to produce a value.

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/Errors/ExitStatus). Its comments explain every step.

<!-- sync:program:start -->

```rux [Src/Main.rux]
// Every program so far ended with `return 0;` from `func Main() -> int`. That number is the
// program's exit status: 0 says it worked, anything else says it did not. It is for whoever
// started the program — a script, a build tool or a shell. In PowerShell, `echo $LASTEXITCODE`
// shows it right after the program ends.
//
// `func Main() -> int` is the only signature `Main` may have, and `Main` cannot fail. An error is
// not an exit status, so the program has to decide which status a failure means. The steps that
// can fail go in a function of their own, and `Main` handles its error like any other:
//
//     Install() !! return 1;    // an error leaves `Main` with status 1
//     return 0;                 // reaching this line means everything worked
//
// When the helper works out the status itself, `-> int ! E`, `Main` is a single line:
// `return Run() !! 1;`.
//
// Leaving with status 1 is an ordinary `return`, so every `defer` and destructor on the way out
// runs as usual. And the error is not printed anywhere: if the user should learn why, print a
// message — a `catch` arm in `Main` can print one and then `return 1`.
//
// This program fails on purpose: the second install does not fit.
import Io::PrintLine;

struct SpaceError {
    needed: int;
    free: int;
}

func Reserve(needed: int, free: int) -> int ! SpaceError {
    if needed > free {
        throw SpaceError { needed: needed, free: free };
    }
    return free - needed;
}

// The steps that can fail, each passing its error on with `!`.
func Install() -> !SpaceError {
    var free = 100;
    PrintLine("Installing the editor (40 MB of {} MB free)", free);
    free = Reserve(40, free)!;

    PrintLine("Installing the compiler (90 MB of {} MB free)", free);
    free = Reserve(90, free)!;

    // Never printed: the `!` above passed the error out of `Install`.
    PrintLine("Everything is installed, {} MB left", free);
}

// `Main` cannot fail, so `func Main() -> !SpaceError` is refused:
//     error: 'Main' must be 'func Main() -> int', but it returns '!SpaceError'
func Main() -> int {
    Install() !! return 1;
    return 0;
}
```

<!-- sync:program:end -->

## Run it

```sh
cd Examples/Errors/ExitStatus
rux run
echo $?
```

The program fails on purpose, so it stops after the second line, and `echo $?` prints its exit status, 1. In PowerShell, use `echo $LASTEXITCODE` instead.

<!-- sync:output:start -->

```
Installing the editor (40 MB of 100 MB free)
Installing the compiler (90 MB of 60 MB free)
1
```

## Common mistakes

::mistake
**Letting Main fail.**\
`func Main() -> !SpaceError` is refused, whatever error it names:

```text
error: 'Main' must be 'func Main() -> int', but it returns '!SpaceError'
help: move the steps that can fail into a function and handle its error in 'Main', as in 'return Run() !! 1;'
```

A `Main` with no result at all is refused the same way, "but it has no result".
::

::mistake
**Passing the error on from Main.**\
`Install()!;` inside `Main` has nowhere to send the error:

```text
error: call to 'Install' can fail with 'SpaceError', but 'Main' cannot fail
```

Handle it with `!!` or `catch` instead, and choose the status yourself.
::

::mistake
**Calling the helper and ignoring it.**\
A bare `Install();` is an error, because a fallible that nothing uses would drop its error unseen:

```text
error: 'Install' can fail with 'SpaceError', and the result is not used
help: pass the error on with '!', ignore it with '!!;', or handle it with 'catch { ... }'
```

::

## Try it yourself

1. Change the compiler's 90 MB to 50 and run again. What does `echo $?` show now?
2. Replace `Install() !! return 1;` with the `catch` above, so the user learns why the install stopped.
3. Write `func Run() -> int ! SpaceError` that calls `Install()!` and returns 2, make `Main` a single `return Run() !! 1;`, and check the exit status both when the install fails and when everything fits.
