# Numeric bound

::note
<!-- sync:needs:start -->

**You'll need**: [Generic bound](/docs/learn/generic-bound), [Give away](/docs/learn/give-away), [Slice](/docs/learn/slice), [Convert](/docs/learn/convert)
<!-- sync:needs:end -->

::

[Generic bound](/docs/learn/generic-bound) bounded `T` by an interface you wrote, so the body could call `Score` on it. Numbers need something an interface cannot list: the **operators**. A function that adds up a slice of `T` needs `+` on every type it might be given, a starting value of type `T`, and a `T` it can copy into a running total. `Core::Arithmetic` has three bounds that promise exactly that — `Integer`, `SignedInteger` and `Float` — and this lesson writes one sum, one range, one magnitude and one average that each work for a whole family of number types.

## Three bounds from Core::Arithmetic

The bounds are imported like any other declaration:

```rux
import Core::Arithmetic::{ Float, Integer, SignedInteger };
```

Each one admits a family of number types and refuses everything else:

| Bound           | Accepts                                                                                       | Refuses, for example       |
| --------------- | --------------------------------------------------------------------------------------------- | -------------------------- |
| `Integer`       | an integer of any width, signed or not: `int8` … `int512`, `uint8` … `uint512`, `int`, `uint` | `float64`, `bool`, `char8` |
| `SignedInteger` | a signed integer of any width: `int8` … `int512`, `int`                                       | `uint64`, and every float  |
| `Float`         | a floating-point number of any width: `float8` … `float512`                                   | `int32`, and every integer |

Nothing implements these interfaces, and no `extend` block could: the compiler decides them from the type itself, and they exist only to be written after a colon. A `SignedInteger` is an `Integer` too, so a function bounded by `SignedInteger` may pass its `T` on to one that asks for `Integer`.

## One sum for every integer

`Sum` takes a [slice](/docs/learn/slice) of any integer type and adds it up:

```rux
func Sum<T: Integer>(values: T[..]) -> T {
    var total = 0 as T;
    for value in values {
        total += value;
    }
    return total;
}
```

`T` is read out of the slice it is given, so `Sum(scores)` is `Sum<int32>` and `Sum(sizes)` is `Sum<uint64>` — two copies of one body, each compiled for its own type.

Two details make the body work for every `T`:

- **The starting value is a `T`.** A bare `0` is an `int`, and an `int` total cannot take a `uint64` or an `int8`. [`as`](/docs/learn/convert) turns the literal into whatever `T` is: `0 as T` is a zero `int32` in one copy and a zero `uint64` in the other.
- **The operators are those of the numbers.** `+=` on two `T` values means the `+=` of `int32` in one copy and of `uint64` in the other, with each type's own overflow check.

## A T that copies

`Range` finds the lowest and highest values in one pass:

```rux
func Range<T: Integer>(values: T[..]) -> (T, T) {
    var low = values[0];
    var high = low;
    for value in values {
        if value < low {
            low = value;
        }
        if value > high {
            high = value;
        }
    }
    return (low, high);
}
```

`var high = low;` looks harmless, but in a generic body it is not. In [Generic bound](/docs/learn/generic-bound) you saw that the body treats an unbounded `T` as a value that might own something, so writing `low` bare gives it away, exactly as in [Give away](/docs/learn/give-away) — and the loop could no longer read it.

A numeric bound settles that. Every number is plain data, so `Integer` makes `T` copyable: `var high = low;` copies, and `low`, `high` and `value` all stay usable as often as the body likes. It is the same promise `Copyable` from `Core::Ownership` makes, which admits any plain data but adds nothing else.

## A narrower bound

Negating only makes sense for a number with a sign, so `Magnitude` asks for `SignedInteger`:

```rux
func Magnitude<T: SignedInteger>(value: T) -> T {
    if value < 0 as T {
        return -value;
    }
    return value;
}
```

On an unsigned type, `-value` would overflow for anything but zero. With the bound, an unsigned argument never gets that far: `Magnitude(sizes[0])` is refused at the call, because `uint64` is not a signed integer.

The call in `Main` writes its type argument out, `Magnitude<int64>(-7)`, which makes `-7` an `int64` rather than an `int` — the [Literal](/docs/learn/literal) rule you met in Generic bound with `Best<int32>(3, 9)`.

## Floating point

`Average` keeps the fraction, so it is bounded by `Float`:

```rux
func Average<T: Float>(values: T[..]) -> T {
    var total = 0.0 as T;
    for value in values {
        total += value;
    }
    return total / (values.length as T);
}
```

It is `Sum` again with two changes: the starting value is `0.0 as T`, and the slice's length is converted to `T` before the division, so that `/` divides two `T` values. Under `Integer` the same `/` would drop the fraction; under `Float` it keeps it.

## Checked at the call

A numeric bound is checked where a type argument meets it — at the call — just like `Scored` was:

```mermaid
flowchart LR
    c["`Sum(temperatures)`"] --> t["`T = float64`"]
    t --> q{"Is `float64`<br/>an `Integer`?"}
    q -- "yes" --> ok["`Sum` is compiled for it,<br/>with its own `+=`"]
    q -- "no" --> err["error at the call:<br/>`'float64' is not an integer`"]
```

The operators themselves are checked once `T` is known, for each copy of the body. That is why the bound matters even for a body that would compile without it: without `: Integer`, `Sum(flags)` on a `bool` array would be reported _inside_ `Sum`, at the `+=` that `bool` lacks. With the bound, the error lands on the line that passed the wrong type, and the signature alone tells a reader which types are welcome.

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/Generics/NumericBound). Its comments explain every step.

<!-- sync:program:start -->

```rux [Src/Main.rux]
// GenericBound bounded `T` by an interface you wrote, so the body could call its methods. Numbers
// need something an interface cannot list: the operators. A body that adds two `T`s needs `+` on
// every type it might be given, and `Core::Arithmetic` has three bounds that promise exactly that:
//
//     Integer         an integer of any width, signed or not
//     SignedInteger   a signed integer, which is an Integer too
//     Float           a floating-point number of any width
//
// Under one of them the body may use the operators of those numbers on a `T`: `+`, `-`, `*`, `/`,
// `<` and the rest. A literal becomes a `T` with `as`, as in `0 as T`. And because every number
// is plain data, each bound makes `T` copyable, so a `T` can be used as often as the body likes.
//
// Nothing implements these interfaces. The compiler decides them from the type, and they exist
// only as bounds. `Copyable`, from `Core::Ownership`, is the same kind of interface: `T: Copyable`
// admits any plain data and lets a `T` be copied, but it adds no operators, and no value ever has
// the type `Copyable`.
import Core::Arithmetic::{ Float, Integer, SignedInteger };
import Io::PrintLine;

// One function for every integer type. `T` is read out of the slice it is given.
func Sum<T: Integer>(values: T[..]) -> T {
    var total = 0 as T;
    for value in values {
        total += value;
    }
    return total;
}

// `high` starts as a copy of `low`. Without a bound a `T` might own something, so
// `var high = low;` would give `low` away and the loop could not read it; under `Integer` the
// value is copied and both stay usable.
func Range<T: Integer>(values: T[..]) -> (T, T) {
    var low = values[0];
    var high = low;
    for value in values {
        if value < low {
            low = value;
        }
        if value > high {
            high = value;
        }
    }
    return (low, high);
}

// Negating needs a sign, so this bound is the narrower `SignedInteger`.
func Magnitude<T: SignedInteger>(value: T) -> T {
    if value < 0 as T {
        return -value;
    }
    return value;
}

// Division that keeps the fraction, so a floating-point bound.
func Average<T: Float>(values: T[..]) -> T {
    var total = 0.0 as T;
    for value in values {
        total += value;
    }
    return total / (values.length as T);
}

func Main() -> int {
    let scores: int32[4] = [12, 7, 30, 1];
    let sizes: uint64[3] = [4096, 512, 1024];
    let temperatures: float64[3] = [18.5, 21.0, 19.0];

    PrintLine("sum of scores    {}", Sum(scores));
    PrintLine("sum of sizes     {}", Sum(sizes));
    let (low, high) = Range(scores);
    PrintLine("range of scores  {} to {}", low, high);
    PrintLine("magnitude of -7  {}", Magnitude<int64>(-7));
    PrintLine("average          {}", Average(temperatures));

    // The bound is checked at the call. `Sum(temperatures)` is refused there, before the body is
    // looked at:
    //
    // error: type argument 'float64' does not satisfy interface bound 'Integer' on type
    //        parameter 'T'
    //   note: 'float64' is not an integer
    //   note: type parameter 'T' of function 'Sum' is bound by 'Integer'
    //   help: pass an integer type, such as 'int' or 'uint'
    //
    // `Magnitude(sizes[0])` is refused the same way, with the note "'uint64' is not a signed
    // integer".
    return 0;
}
```

Besides `Io`, its `Rux.toml` lists `Core` under `[Dependencies]`.

## Common mistakes

::mistake
**Passing a type the bound refuses.**\
`Sum(temperatures)` fails at the call:

```text
error: type argument 'float64' does not satisfy interface bound 'Integer' on type parameter 'T'
  note: 'float64' is not an integer
  note: type parameter 'T' of function 'Sum' is bound by 'Integer'
  help: pass an integer type, such as 'int' or 'uint'
```

`Magnitude(sizes[0])` is refused the same way, with the note `'uint64' is not a signed integer`, and `Average(scores)` with `'int32' is not a floating-point number`.
::

::mistake
**Starting from a bare literal.**\
Write `var total = 0;` in `Sum` and it fails with:

```text
error: operator '+=' produces 'T', which cannot be stored in target type 'int'
```

followed by `'return' value must have type 'T', but found 'int'`. The literal made `total` an `int`. Write `0 as T`, so the total has the type of the values.
::

::mistake
**Copying a `T` without a bound.**\
Drop `: Integer` from `Range` and `var high = low;` gives `low` away:

```text
error: 'low' is used after it was given away
  help: lend it with '&low' where it is only read, or clone it where both uses need a value
```

An unbounded `T` might own something, so it is never copied. A numeric bound, or `Copyable`, makes it plain data.
::

::mistake
**Passing a `T` on to a stricter bound.**\
A `func Mean<T: Float>(values: T[..]) -> T` that returns `Sum(values)` fails with:

```text
error: type argument 'T' does not satisfy interface bound 'Integer' on type parameter 'T'
  help: add the bound to the enclosing declaration, as in 'T: Integer'
```

A `Float` is not an `Integer`. The other way round works: a `T: SignedInteger` may be passed to `Sum`, because every signed integer is an integer.
::

## Try it yourself

1. Write `func Product<T: Integer>(values: T[..]) -> T`, starting from `1 as T`, and print the product of `scores` and of `sizes`.
2. Call `Average(scores)` and read the error. Then declare the scores as `float64` and call it again. Which other calls on `scores` now fail, and why?
3. Replace `Integer` in `Range` with `Copyable`, imported from `Core::Ownership`. Does `Range` still compile, and which calls would it now accept that it refused before?
