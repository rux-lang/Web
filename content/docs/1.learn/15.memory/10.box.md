# Box

::note
<!-- sync:needs:start -->

**You'll need**: [Allocator](/docs/learn/allocator), [Destructor](/docs/learn/destructor), [Move](/docs/learn/move), [Fallible main](/docs/learn/fallible-main)
<!-- sync:needs:end -->

::

The raw lessons kept leaving one job to you: remember to give the memory back, exactly once, and never touch it afterwards. A `Box<T>` takes that job over. It owns one value that lives in allocated memory, and — like any value with a [destructor](/docs/learn/destructor) — it cleans up after itself when its life ends.

## Creating a box

`Box::TryCreate<T>(allocator, value)` asks the allocator for room, moves the value in, and hands back the box:

```rux
let boxed = try Box::TryCreate<Tally>(allocator, Tally { name: name, count: 1 });
```

Asking can fail, so `TryCreate` is declared `-> Self throws AllocError`, and `try` passes a refusal on. From this line on, the box is the value's one owner. Its sibling, `Box<T>(allocator, value)`, does the same but treats running out of memory as fatal, as a `String` does, so it needs no `try`.

## Reaching the value

`Get()` lends the value where it sits, as a `&T?`; `GetMutable()` lends it for writing, as a `&var T?`. Either is `none` only for a box whose value `Take` has moved out, so the program opens the optional with [`is`](/docs/learn/is):

```rux
if apples.GetMutable() is .Some(tally) {
    tally.count += 2;
}
if apples.Get() is .Some(tally) {
    PrintLine("    {} {}", tally.count, tally.name);
}
```

These are [references](/docs/learn/reference), not raw pointers, so no `unsafe` is needed: the compiler checks them. While a reference from the box is in use, the box stays borrowed, and it cannot be moved or destroyed under it.

## The box cleans up

Nobody calls `Deallocate` in this program. When a box's life ends, its destructor destroys the value — which runs `~Tally` and prints a line — and then gives the memory back to the allocator it came from:

```mermaid
flowchart LR
    create["`Box::TryCreate(allocator, value)`"] --> alloc["the allocator gives room,<br/>the value moves in"]
    alloc --> use["`boxed.Get()` — use it"]
    use --> end_["the box's life ends"]
    end_ --> drop["`~Tally` runs"]
    drop --> back["memory goes back to<br/>the same allocator"]
```

You can see the timing in the output. The box in `Count` dies when `Count` returns, so `destroying the pears tally` is printed before `Main` carries on with `a box in Main:`.

## Moving a box

A box cannot be copied: two owners would both release the memory, and the second release would hit memory that was no longer theirs. It can be [moved](/docs/learn/move), which hands the ownership on and retires the old name:

```rux
let storage = if apples.Get() is .Some(tally) { Address(tally) } else { 0 };
let owner = move apples;
let moved = if owner.Get() is .Some(tally) { Address(tally) } else { 0 };
PrintLine("    moved, same storage: {}", moved == storage);
```

`Address` turns where the tally's `count` lives into a plain number. Only the number is kept across the move: holding on to the reference itself would keep `apples` borrowed and forbid the move.

The value itself stays where it was allocated, so the new owner reaches the very same storage — the comparison prints `true`. Only the right to release it has moved. At the end of `Main`, `owner` releases the memory, once, and `apples` releases nothing because it no longer owns anything.

| You write                  | What happens                                          |
| -------------------------- | ----------------------------------------------------- |
| `let owner = move apples;` | ownership moves; `apples` can no longer be used       |
| `let owner = apples;`      | rejected — a box cannot be copied                     |
| `apples.Get()`             | a borrowed `&T?`, keeping the box borrowed while used |

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/Memory/Box). Its comments explain every step.

<!-- sync:program:start -->

```rux [Src/Main.rux]
// A `Box<T>` owns one value that lives in allocated memory. `Box::TryCreate<T>(allocator, value)`
// asks the allocator for room, moves the value in, and hands back the box, or throws an
// `AllocError` if there was no room. (`Box<T>(allocator, value)` does the same but treats running
// out of memory as fatal.) From then on the box is the value's one owner.
//
// That ownership is what the raw lessons were missing. Nobody calls `Deallocate`: when the box's
// life ends, its destructor destroys the value and gives the memory back to the allocator it
// came from. And a box cannot be copied, because two owners would release the memory twice.
// Hand it on with `move`, and the old binding can no longer be used.
//
// `Get()` lends the value where it sits as a `&T?`, and `GetMutable()` as a `&var T?`; either is
// `none` only for a box whose value `Take` moved out. While the reference is in use the box stays
// borrowed, so it cannot be moved or destroyed under it.
import Allocator::{ AllocError, Allocator, Box, SystemAllocator };
import Io::PrintLine;

struct Tally {
    name: char8[..];
    count: int;
}

extend Tally {
    func ~Tally(&var self) {
        PrintLine("    destroying the {} tally", self.name);
    }
}

// The box is created and dies inside this call, so its memory is returned before `Main` resumes.
func Count(allocator: Allocator, name: char8[..]) throws AllocError {
    let boxed = try Box::TryCreate<Tally>(allocator, Tally { name: name, count: 1 });
    if boxed.Get() is .Some(tally) {
        PrintLine("    counted {} {}", tally.count, tally.name);
    }
}

// Where a tally's count lives in memory, which changes only if the tally itself is moved.
func Address(tally: &Tally) -> uint {
    return @tally.count as uint;
}

func Main() throws AllocError {
    var system = SystemAllocator();
    let allocator: Allocator = system;

    PrintLine("a short-lived box:");
    try Count(allocator, "pears");

    PrintLine("a box in Main:");
    var apples = try Box::TryCreate<Tally>(allocator, Tally { name: "apples", count: 3 });
    if apples.GetMutable() is .Some(tally) {
        tally.count += 2;
    }
    if apples.Get() is .Some(tally) {
        PrintLine("    {} {}", tally.count, tally.name);
    }

    // Moving the box moves the ownership. The value itself stays where it was allocated, so the
    // new owner points at the very same storage. Only the address is kept across the move, as a
    // number: a reference would keep `apples` borrowed and forbid the move.
    let storage = if apples.Get() is .Some(tally) { Address(tally) } else { 0 };
    let owner = move apples;
    let moved = if owner.Get() is .Some(tally) { Address(tally) } else { 0 };
    PrintLine("    moved, same storage: {}", moved == storage);

    // Using `apples` from here on is rejected: it was moved out. `owner` releases the memory, once.
    PrintLine("end of Main:");
}
```

Besides `Io`, its `Rux.toml` lists `Allocator` under `[Dependencies]`.

## Common mistakes

::mistake
**Copying a box.**\
`let owner = apples;` fails with:

```text
error: cannot copy 'Box<Tally>', which owns resources
  help: write 'move apples' to transfer it, or 'apples.Clone()' to copy it
```

Move it, or keep using the one box.
::

::mistake
**Using a box after moving it.**\
After `let owner = move apples;`, any use of `apples` fails with:

```text
error: value 'apples' is used after it was moved
```

Use `owner` from then on.
::

::mistake
**Treating `Get()` as the value.**\
`apples.Get().count += 2;` fails with:

```text
error: type '&Tally?' has no field 'count'
```

The box may be empty, so its answer is optional. Open it first, with `if apples.GetMutable() is .Some(tally) { … }`.
::

::mistake
**Moving a box while a reference from it is still in use.**\
`let held = apples.Get();`, then `let owner = move apples;`, then a later use of `held`, fails with:

```text
error: cannot move 'apples' while it is immutably borrowed
```

The reference points into the box's storage, so the box must stay put while it lives. Finish with the reference first, or keep only what you need from it — a number, as `Address` does.
::

## Try it yourself

1. Create a second box, `plums`, in `Main` before `apples`. Predict the order of the two `destroying` lines at the end, then run.
2. Write `func Report(owner: Box<Tally>)` that prints the tally, and call it as `Report(move apples)`. Where does `destroying the apples tally` appear now?
3. Change `Count` to return the box, `-> Box<Tally> throws AllocError`, with `return move boxed;`, and keep it alive in `Main`.
4. Call `apples.Take()` and print the tally it hands back. What does `apples.Get()` answer afterwards?
