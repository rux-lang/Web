# Rc

::note
<!-- sync:needs:start -->

**You'll need**: [Box](/docs/learn/box), [Custom copy](/docs/learn/custom-copy), [Optional pointer](/docs/learn/optional-pointer)
<!-- sync:needs:end -->

::

A [`Box<T>`](/docs/learn/box) knows when to free its value because it is the value's only owner. Some values have no single owner. An editor's colour theme is used by every open window; a loaded image may be shown in three places. The memory should go when the last user is done with it — and no one user knows whether it is the last.

`Rc<T>` — a **reference-counted** handle — answers that by counting:

```rux
import Allocator::{ AllocError, Allocator, Rc, SystemAllocator };
```

## Creating and cloning handles

`Rc::TryCreate<T>(allocator, value)` moves the value into allocated memory beside a count, which starts at one, and returns the first handle. Like `Box::TryCreate`, it throws an `AllocError` when there is no room, so the call is marked with `try`:

```rux
var theme = try Rc::TryCreate<Theme>(allocator, Theme { name: "paper", size: 11 });
```

A handle is move-only, like every value that owns something, so `let other = theme;` is refused. A second handle is made on purpose with `Clone`, the method from [Custom copy](/docs/learn/custom-copy). Cloning a handle does **not** copy the value: it adds one to the count, and the new handle reaches the same value. So every window below holds a handle to the theme, not a theme of its own:

```rux
struct Window {
    title: char8[..];
    theme: Rc<Theme>;
}
```

```rux
let editor = Window { title: "editor", theme: theme.Clone() };
let preview = Window { title: "preview", theme: theme.Clone() };
```

```mermaid
flowchart LR
    m["`theme` in `Main`"] --> v["the paper theme<br/>count: 4"]
    p["`theme` parameter"] --> v
    e["`editor.theme`"] --> v
    w["`preview.theme`"] --> v
```

`Count()` reads the count. A `Window` holds a handle, so it is move-only too, and the program gives it a `Clone` of its own that clones the handle. `Draw` takes its window by value, and is called with `Draw(editor.Clone())` — which is why it sees five handles while the call lasts.

## The last handle frees the value

When a handle's life ends, the count goes down by one. The handle that takes it to zero destroys the value — running its destructor — and gives the memory back. In the program, every handle made in `OpenWindows` ends with the call, and the count returns to one:

| Moment                                 | Handles to the paper theme |
| -------------------------------------- | -------------------------- |
| after `TryCreate`                      | 1                          |
| inside `OpenWindows`, two windows made | 4                          |
| inside `Draw`                          | 5                          |
| `OpenWindows` returned                 | 1                          |
| `Main` ends                            | 0 — `~Theme` runs          |

Nothing in the program says when to free the theme. `the paper theme is destroyed` is printed after `end of Main:` because `Main`'s handle was the last.

## Reading and writing

`Get()` lends the value as a `&Theme`, a read-only [reference](/docs/learn/reference). A shared value is read by everybody, and a change made through one handle would surprise all the others, so there is no way to write through `Get()`.

`GetMutable()` returns `&var Theme?` — a writable reference while this handle is the only one, and `none` while the value is shared:

```rux
match theme.GetMutable() {
    .Some(value) => value.size = 12,
    none => PrintLine("shared, so read-only")
}
```

Right after `TryCreate` there is one handle, so the program may set the size. Inside `OpenWindows`, where another handle is cloned for the purpose, the same question answers `none`. A value that must change while it is shared needs a different design: build a new value and replace the handle, or keep the changing part outside the shared one.

## Same value, or equal value

`SameAs` asks whether two handles reach the **same** value, not whether two values are equal:

```rux
let lookalike = try Rc::TryCreate<Theme>(allocator, Theme { name: "lookalike", size: 12 });
PrintLine("    editor and preview share: {}", editor.theme.SameAs(preview.theme));
PrintLine("    lookalike is shared:      {}", lookalike.SameAs(theme));
```

The lookalike is a separate value with its own count of one, so it is destroyed as soon as its only handle goes, at the end of `OpenWindows`.

::note
**One thread only.**\
An `Rc` keeps its count with plain arithmetic, which is fast but not safe when two threads change it at once. To share a value between threads, the Allocator package has a twin, `Arc<T>`, which counts atomically. It comes with [Arc](/docs/learn/arc) in Part 25.
::

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/Memory/Rc). Its comments explain every step.

<!-- sync:program:start -->

```rux [Src/Main.rux]
// A `Box<T>` has exactly one owner, which is what lets it know when to free its value. Some values
// have no single owner, though: one theme used by every window of an editor, one loaded image
// shown in several places. Whichever user goes last should free it, and none of them knows
// which one that is.
//
// `Rc<T>`, a reference-counted handle, settles it by counting. `Rc::TryCreate` moves the value
// into allocated memory with a count of one. A handle is move-only, like every owner, so a second
// handle is made on purpose with `Clone()`. Cloning a handle does not copy the value: it adds one
// to the count, and both handles reach the same value. When a handle's life ends the count goes
// down by one, and the handle that takes it to zero destroys the value and frees the memory.
//
// Shared values are read-only. `Get()` lends a `&T` for reading. `GetMutable()` lends a
// `&var T` only while a single handle exists, since a change made through one handle would
// otherwise surprise the others; while the value is shared it returns `none`.
//
// An `Rc` counts with plain arithmetic, so its handles must all stay on one thread. Its twin,
// `Arc`, counts atomically for values shared between threads; it comes with the Concurrency part.
import Allocator::{ AllocError, Allocator, Rc, SystemAllocator };
import Io::PrintLine;

struct Theme {
    name: char8[..];
    size: int32;
}

extend Theme {
    func ~Theme(&var self) {
        PrintLine("    the {} theme is destroyed", self.name);
    }
}

// Every window holds a handle to its theme, not a copy of it.
struct Window {
    title: char8[..];
    theme: Rc<Theme>;
}

extend Window {
    // A window is move-only because its handle is. Cloning it clones the handle, so the copy
    // shares the theme rather than duplicating it.
    func Clone(&self) -> Window {
        return Window { title: self.title, theme: self.theme.Clone() };
    }
}

// The window arrives by value, so for the length of the call there is one more handle.
func Draw(window: Window) {
    let theme = window.theme.Get();
    PrintLine("    {} in {} at {}pt, {} handles", window.title, theme.name, theme.size,
        window.theme.Count());
}

func OpenWindows(theme: Rc<Theme>, allocator: Allocator) throws AllocError {
    // Two more handles: the count is now one for `Main`, one for this parameter and one each
    // for the windows.
    let editor = Window { title: "editor", theme: theme.Clone() };
    let preview = Window { title: "preview", theme: theme.Clone() };
    PrintLine("    {} handles", theme.Count());
    Draw(editor.Clone());

    // `GetMutable` needs a `var` handle, so clone one more. Even so, the answer is `none`:
    // while the value is shared, nobody may write to it.
    var mine = theme.Clone();
    PrintLine("    can write: {}", mine.GetMutable() is .Some(_));

    // `SameAs` asks whether two handles reach one value, not whether two values are equal. A
    // second theme with the same fields is still a different value, with its own count.
    let lookalike = try Rc::TryCreate<Theme>(allocator, Theme { name: "lookalike", size: 12 });
    PrintLine("    editor and preview share: {}", editor.theme.SameAs(preview.theme));
    PrintLine("    lookalike is shared:      {}", lookalike.SameAs(theme));

    // Every handle made here ends with the call. The lookalike was the only handle to its
    // value, so that value is destroyed now; the paper theme still has `Main`'s handle.
}

func Main() throws AllocError {
    var system = SystemAllocator();
    let allocator: Allocator = system;

    var theme = try Rc::TryCreate<Theme>(allocator, Theme { name: "paper", size: 11 });
    PrintLine("created, {} handle", theme.Count());

    // A lone handle may write. `GetMutable` returns `&var Theme?`, a reference or `none`.
    match theme.GetMutable() {
        .Some(value) => value.size = 12,
        none => PrintLine("shared, so read-only")
    }

    // `Get()` gives only a `&Theme`, so writing through it is refused:
    //
    //     error: cannot modify data through immutable reference '&Theme'

    PrintLine("opening windows:");
    try OpenWindows(theme.Clone(), allocator);
    PrintLine("windows closed, {} handle", theme.Count());

    // `theme` is the last handle, so the value is destroyed when `Main` ends, and only then.
    PrintLine("end of Main:");
}
```

## Common mistakes

::mistake
**Writing through `Get`.**\
`theme.Get().size = 13;` fails with:

```text
error: cannot modify data through immutable reference '&Theme'
```

Shared values are read-only. Write through `GetMutable()` while the handle is the only one.
::

::mistake
**Copying a handle with `=`.**\
`Window { title: "editor", theme: theme }` fails with:

```text
error: cannot copy 'Rc<Theme>', which owns resources
  help: write 'move theme' to transfer it, or 'theme.Clone()' to copy it
```

`theme.Clone()` makes a second handle to the same value; `move theme` hands this one over and leaves the count as it was.
::

::mistake
**Calling `GetMutable` on a `let` handle.**\
`GetMutable` takes the handle as `&var self`. With `let mine = theme.Clone();` the call fails with:

```text
error: cannot call 'GetMutable' on immutable 'mine'
```

Declare the handle with `var`. And even then, expect `none` whenever another handle exists — including a clone you made a moment ago, or one a struct is holding.
::

::mistake
**Reaching for the fields directly.**\
`theme.size` fails with:

```text
error: struct 'Rc<Theme>' has no field 'size'
```

The handle is not the value. Go through `theme.Get().size`.
::

## Try it yourself

1. Print `window.theme.Count()` inside `Draw` before and after `let copy = window.theme.Clone();`. How much does one more clone add?
2. In `Main`, after `OpenWindows`, try `GetMutable` again and set the size to 14. Does it work now, and why?
3. Make the lookalike a second handle to `theme` instead of a new value. What does `SameAs` say, and what happens to the `the lookalike theme is destroyed` line?
4. Give `Window` a destructor that prints its title, and watch the order in which windows and themes go.
