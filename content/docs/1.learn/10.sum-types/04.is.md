# The is operator

::note
<!-- sync:needs:start -->

**You'll need**: [Subset pattern](/docs/learn/subset-pattern), [For](/docs/learn/for), [Array](/docs/learn/array), [If let](/docs/learn/if-let)
<!-- sync:needs:end -->

::

Sometimes a program only needs to know _which_ member a sum holds, not what is inside it. Is this token a number? Is it an operator? `value is T` answers with a plain `bool`: `true` when the active member is `T`.

A [typed pattern](/docs/learn/typed-pattern) can answer the same question, but it takes a whole `match` with an arm for every member. `is` is the one-line version for when a yes or no is all you want. And when you want the member itself, but only from one of them, [`if let`](/docs/learn/if-let) with a typed pattern tests and binds in one step.

## The tokens

A tokenizer turns the text `price + 2 - discount + 1` into pieces, and each piece is one of four types:

```rux
struct Number {
    value: int32;
}

struct Name {
    text: char8[..];
}

struct Plus {}

struct Minus {}

type Token = Number | Name | Plus | Minus;
```

`Plus` and `Minus` carry no fields at all; for them, the type _is_ the whole message.

The [array](/docs/learn/array) is annotated `Token[7]`, which makes every element a `Token`, so one array holds all four member types side by side:

```rux
let tokens: Token[7] = [
    Name { text: "price" },
    Plus {},
    Number { value: 2 },
    Minus {},
    Name { text: "discount" },
    Plus {},
    Number { value: 1 }
];
```

## Asking which member

Inside the [loop](/docs/learn/for), `is` sorts the tokens without unpacking any of them:

```rux
if token is Number {
    numbers++;
}
if token is (Plus | Minus) {
    operators++;
}
```

`token is Number` is `true` for the two numbers. Put a smaller sum in parentheses, `token is (Plus | Minus)`, and the test is `true` when the active member is any one of them (the three operators here). It is the `is` form of a [subset pattern](/docs/learn/subset-pattern).

The parentheses are required. Without them, `token is Plus | Minus` is refused, and the compiler's help shows the grouped form to write instead.

## Binding with if let

Counting needs only the yes or no. Adding up the numbers needs the `value` inside each one, and that is what [`if let`](/docs/learn/if-let) is for. With a typed pattern it tests the member and binds it in one step:

```rux
if let number: Number = token {
    sum += number.value;
}
```

The body runs only when `token` holds a `Number`, and there `number` _is_ that `Number`: a struct with a `value` field, not the whole sum. Outside the braces `number` does not exist. The pattern is the one a [`match`](/docs/learn/typed-pattern) arm takes, so a subset such as `if let _: Plus | Minus = token` works too. Reach for `if let` when only one member interests you and the others need no arm at all.

## An ordinary bool

The result is a `bool` like any other, so it can be stored, printed or combined with `&&` and `||`:

```rux
let startsWithName = tokens[0] is Name;
PrintLine("starts with a name: {}", startsWithName);
PrintLine("ends with a number: {}", tokens[6] is Number);
```

## What is does not do

`is` only asks. Three things follow from that.

**It does not narrow.** Inside `if token is Number { … }`, `token` is still the whole `Token`, not a `Number`. Reading `token.value` there is rejected, because a `Name`, a `Plus` or a `Minus` has no `value`.

**It does not bind.** `token is number: Number` looks as if it might name the member, but a test never binds anything, and the compiler refuses the name. To use what is inside, bind it with `if let number: Number = token`, or with a typed pattern in a `match`.

**It does not quietly answer `false`.** A test that could never be true is a mistake, and the compiler says so. `token is bool` is refused because `bool` is not a member of `Token`. On a value that is not a sum at all, `is` compares exact types, and a mismatch is an error too.

One kind of value `is` does not take at all: an [optional](/docs/learn/optional). Whether an `int32?` holds a value is not a question about its type, so it is a comparison — `value != none` — and the value itself comes out with `if let n? = value`.

```mermaid
flowchart LR
    q{"Do you need the<br/>value inside?"} -- "no: only which member" --> is["`value is T`<br/>`value is (A | B)`"]
    q -- "yes, from one member" --> il["`if let n: Number = token`"]
    q -- "yes, from every member" --> m["`match` with a typed pattern<br/>`n: Number => n.value`"]
```

| You want                               | Write                            | You get                      |
| -------------------------------------- | -------------------------------- | ---------------------------- |
| to know the member                     | `token is Number`                | a `bool`                     |
| to know if it is one of several        | `token is (Plus \| Minus)`       | a `bool`                     |
| the value inside one member            | `if let n: Number = token { … }` | `n`, a `Number`, in the body |
| a value from whichever member it holds | `match token { n: Number => … }` | `n`, a `Number`, in its arm  |

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/SumTypes/Is). Its comments explain every step.

<!-- sync:program:start -->

```rux [Src/Main.rux]
// Sometimes a program only needs to know *which* member a sum holds, not what is inside it.
// `value is T` answers that with a plain `bool`: true when the active member is `T`. Put a smaller
// sum in parentheses, `value is (Plus | Minus)`, and it is true when the active member is any one
// of them. The parentheses are required: `token is Plus | Minus` is refused with
//       error: a sum type after 'is' must be grouped
//       help: write 'value is (Plus | Minus)'
//
// Three things `is` does not do:
//
// - It does not narrow. Inside `if token is Number { ... }`, `token` is still the whole sum, so
//   `token.value` is rejected:
//       error: type 'Minus | Name | Number | Plus' has no field 'value'
//
// - It does not bind. `token is number: Number` is refused with
//       error: 'is' tests and does not bind 'number'
//   To use what is inside, bind it with `if let number: Number = token { ... }`, or with a typed
//   pattern in a `match`.
//
// - It does not quietly answer `false`. A test that could never be true is a mistake, and the
//   compiler says so. `token is bool` is refused because `bool` is not one of the members:
//       error: type 'bool8' is not a member or subset of sum 'Minus | Name | Number | Plus'
//   On a value that is not a sum at all, `is` compares exact types, and a mismatch is an error
//   too. The counter `numbers` is an `int`, so `numbers is bool` gives
//       error: 'is bool8' can never be true for a value of type 'int'
import Io::PrintLine;

// The pieces of the expression `price + 2 - discount + 1`, as a tokenizer might hand them over.
struct Number {
    value: int32;
}

struct Name {
    text: char8[..];
}

struct Plus {}

struct Minus {}

type Token = Number | Name | Plus | Minus;

func Main() -> int {
    // The annotation makes every element a `Token`, so one array holds all four member types.
    let tokens: Token[7] = [
        Name { text: "price" },
        Plus {},
        Number { value: 2 },
        Minus {},
        Name { text: "discount" },
        Plus {},
        Number { value: 1 }
    ];

    var numbers = 0;
    var operators = 0;
    var sum = 0i32;
    for token in tokens {
        // `is` only asks; the token is untouched and keeps its type.
        if token is Number {
            numbers++;
        }
        if token is (Plus | Minus) {
            operators++;
        }
        // `if let` is the one that binds: `number` is the `Number` inside, here and only here.
        if let number: Number = token {
            sum += number.value;
        }
    }
    PrintLine("{} numbers, {} operators", numbers, operators);
    PrintLine("the numbers add up to {}", sum);

    // The result is an ordinary boolean, so it can be stored and printed like one.
    let startsWithName = tokens[0] is Name;
    PrintLine("starts with a name: {}", startsWithName);
    PrintLine("ends with a number: {}", tokens[6] is Number);
    return 0;
}
```

## Common mistakes

::mistake
**A sum after `is` without parentheses.**\
`token is Plus | Minus` fails with:

```text
error: a sum type after 'is' must be grouped
  help: write 'value is (Plus | Minus)'
```

The sum has to be grouped to be read as one type.
::

::mistake
**Binding a name with `is`.**\
`if token is number: Number { … }` fails with:

```text
error: 'is' tests and does not bind 'number'
  help: bind with 'if let', as in 'if let .Case(name) = subject { ... }', or write '_' to test only
```

Write `if let number: Number = token { … }`, as the program does.
::

::mistake
**Expecting `is` to narrow.**\
`if token is Number { PrintLine("{}", token.value); }` fails with:

```text
error: type 'Minus | Name | Number | Plus' has no field 'value'
```

After the test `token` is still the whole sum. Bind the member with `if let` to reach its fields.
::

::mistake
**Testing a type that is not a member.**\
`token is bool` fails with:

```text
error: type 'bool8' is not a member or subset of sum 'Minus | Name | Number | Plus'
```

A test that can never be true is an error, not a constant `false`.
::

::mistake
**Testing an optional.**\
With `let o: int32? = 3;`, the test `o is int32` fails with:

```text
error: 'is' does not test an optional
  help: compare with '== none' or '!= none', or bind the value with 'if let name? = ...'
```

Presence is not a member type. Write `o != none`, or `if let n? = o` to use the value.
::

## Try it yourself

1. Count the `Name` tokens as well, and print all three counts.
2. Write `func IsOperator(token: Token) -> bool` with `is`, and use it in the loop.
3. Print the text of every `Name` token with `if let`. Then add only the numbers greater than 1 to `sum`, by joining a second condition with `&&`: `if let number: Number = token && number.value > 1`.
