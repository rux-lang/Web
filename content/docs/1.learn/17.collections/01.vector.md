# Vector

::note
<!-- sync:needs:start -->

**You'll need**: [Allocator](/docs/learn/allocator), [Generic type](/docs/learn/generic-type), [Exit status](/docs/learn/exit-status), [Coalesce](/docs/learn/coalesce)
<!-- sync:needs:end -->

::

An inline array has the length its type says, fixed while compiling. Most real data is not like that: lines read from a file, results that pass a test, orders placed today. You do not know how many there will be until they arrive.

The Memory lessons solved that by hand — ask an allocator for a block, keep count, ask for a larger block when it is full. A `Vector<T>`, from the `Collections` package, does that bookkeeping for you. It owns a block, hands out room as values are pushed, and moves to a larger block when the current one is full. It is the container you will reach for most often.

## Making a vector

A vector keeps its values somewhere, so it is given an [allocator](/docs/learn/allocator) when it is made:

```rux
let allocator = SystemAllocator::New();

var numbers = Vector<int>::New(allocator);
```

`Vector<int>` is a [generic type](/docs/learn/generic-type): a vector of `int`. `New` is its [constructor](/docs/learn/constructor), called on the type with `::`, as every collection in this part is made. Making one asks the allocator for nothing yet — an empty vector has no block, and a capacity of zero. The binding is a `var`, because pushing changes the vector.

## Length and capacity

Two numbers describe a vector, and they are worth keeping apart:

| Number   | Method       | Meaning                                           |
| -------- | ------------ | ------------------------------------------------- |
| Length   | `Length()`   | How many values it holds                          |
| Capacity | `Capacity()` | How many would fit before it needs a larger block |

Pushing raises the length by one every time; the capacity only jumps now and then. The program pushes nine values and prints a line whenever the capacity changes:

```rux
for i in 1..=9 {
    let before = numbers.Capacity();
    numbers.Push(i * 10);
    if numbers.Capacity() != before {
        PrintLine("push {}      length {}  capacity {}  (grew)", i, numbers.Length(),
            numbers.Capacity());
    }
}
```

```
push 1      length 1  capacity 4  (grew)
push 5      length 5  capacity 8  (grew)
push 9      length 9  capacity 16  (grew)
```

Nine pushes, three moves. The capacity grows **ahead** of the length on purpose: each time the vector moves it takes twice the room, so the pushes that follow cost nothing. The vector moves house a handful of times, not once per value.

```mermaid
flowchart LR
    push["`Push(value)`"] --> room{"Is length below<br/>capacity?"}
    room -- "yes" --> write["Write the value<br/>into the next slot"]
    room -- "no" --> grow["Ask the allocator<br/>for a larger block"]
    grow --> copy["Move the values across,<br/>give the old block back"]
    copy --> write
    grow -- "no memory" --> fail["`Push` stops the program;<br/>`TryPush` fails with `AllocError`"]
```

## When memory runs out

That last arrow is rare, but real: a push may need a larger block, and the allocator may have none to give. `Push` then stops the program, as every allocation in a collection does. Most programs have no better answer to running out of memory, so `Push` returns nothing to check, and `Main` is the plain `-> int` it always is:

```rux
func Main() -> int {
```

A program that does have a better answer — a server that can turn one request away and carry on — calls `TryPush` instead. Its result is [fallible](/docs/learn/fallible), `!AllocError`, so the call must say what happens to a failure: pass it on with [`!`](/docs/learn/propagate), or handle it on the spot with [`catch`](/docs/learn/catch):

```rux
numbers.TryPush(10) catch { e => PrintLine("out of memory: {}", e) };
```

A failed push leaves the vector exactly as it was — no value half-added. `Reserve` has a `TryReserve` twin for the same reason.

## Reserving room up front

When the final size is known, `Reserve` makes the room in one step:

```rux
numbers.Reserve(100);
```

At least 100 more values will now fit, so the pushes that follow never need to grow. The program prints a capacity of `128`: the vector rounded the request up.

## Reading the values

A vector is a container a `for` loop can walk, in the order the values went in:

```rux
for value in &numbers {
    Print(" {}", value);
}
```

The `&` matters. `&numbers` lends the vector to the loop, which reads each value and leaves the vector where it was. A bare `for value in numbers` would [give the vector away](/docs/learn/give-away) to the loop instead, and the loop would destroy it when done — the `Get` calls below would then have no vector to ask.

To read one value, use `Get`. It is bounds-checked: it returns `int?`, an [optional](/docs/learn/optional), with `none` past the end:

```rux
PrintLine("index 2     {}", numbers.Get(2) ?? -1);
PrintLine("index 50    {}", numbers.Get(50) ?? -1);
```

Index 2 is `30`; index 50 does not exist, and the [`??`](/docs/learn/coalesce) fallback gives `-1`.

Nothing in the program frees anything. The vector's destructor gives its block back to the allocator when `numbers` goes out of scope.

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/Collections/Vector). Its comments explain every step.

<!-- sync:program:start -->

```rux [Src/Main.rux]
// The Memory lessons asked for a block of a fixed size and kept count by hand. A `Vector<T>` does
// that bookkeeping for you: it owns a block, hands out room as values are pushed, and moves to a
// larger block when the current one is full.
//
// Two numbers describe a vector, and they are worth keeping apart. Its length is how many values
// it holds. Its capacity is how many would fit before it needs a larger block. Pushing raises the
// length by one every time; the capacity only jumps now and then.
import Allocator::SystemAllocator;
import Collections::Vector;
import Io::{ Print, PrintLine };

func Main() -> int {
    let allocator = SystemAllocator::New();

    // A vector keeps its storage somewhere, so it is given an allocator. Making one asks for
    // nothing yet: an empty vector has a capacity of zero.
    var numbers = Vector<int>::New(allocator);
    PrintLine("empty       length {}  capacity {}", numbers.Length(), numbers.Capacity());

    // A push may need a larger block, and the allocator may have none to give. `Push` then stops
    // the program, as every allocation in a collection does; `TryPush` fails with an `AllocError`
    // instead, for code that has a better answer to running out of memory.
    for i in 1..=9 {
        let before = numbers.Capacity();
        numbers.Push(i * 10);
        if numbers.Capacity() != before {
            PrintLine("push {}      length {}  capacity {}  (grew)", i, numbers.Length(),
                numbers.Capacity());
        }
    }
    PrintLine("after 9     length {}  capacity {}", numbers.Length(), numbers.Capacity());

    // The capacity grows ahead of the length on purpose. Taking more room than needed means the
    // next pushes cost nothing, so the vector moves house a handful of times, not once a value.

    // When the final size is known up front, `Reserve` makes the room in one step: at least 100
    // more values will now fit, so the pushes that follow never need to grow.
    numbers.Reserve(100);
    PrintLine("reserved    length {}  capacity {}", numbers.Length(), numbers.Capacity());

    // A vector is a container a `for` loop can walk, in the order the values went in. `&numbers`
    // lends it to the loop; a bare `numbers` would hand the vector over, and the loop would
    // destroy it when done.
    Print("contents   ");
    for value in &numbers {
        Print(" {}", value);
    }
    PrintLine();

    // `Get` is bounds-checked: it returns `int?`, and `none` past the end.
    PrintLine("index 2     {}", numbers.Get(2) ?? -1);
    PrintLine("index 50    {}", numbers.Get(50) ?? -1);

    // Nothing here frees anything. The vector's destructor gives its block back to the allocator
    // when `numbers` goes out of scope.
    return 0;
}
```

Besides `Io`, its `Rux.toml` lists `Allocator` and `Collections` under `[Dependencies]`.

## Common mistakes

::mistake
**Calling the type instead of its constructor.**\
`var numbers = Vector<int>(allocator);` fails with:

```text
error: 'Vector<int>' is a type, not a function
help: call a constructor by its name, as in 'Vector<int>::New(...)'
```

Write `Vector<int>::New(allocator)`.
::

::mistake
**Passing on an error a push does not have.**\
`Push` cannot fail — it stops the program when memory runs out — so `numbers.Push(10)!;` fails with:

```text
error: '!' passes an error on, and '()' has none
```

Leave the `!` off, or call `TryPush` when the program should handle running out of memory itself.
::

::mistake
**Ignoring what `TryPush` returns.**\
`numbers.TryPush(10);` on its own fails with:

```text
error: 'TryPush' can fail with 'AllocError', and the result is not used
help: pass the error on with '!', ignore it with '!!;', or handle it with 'catch { ... }'
```

`Main` returns only an `int`, so it has nowhere to pass the error on to. Handle it on the spot with `catch`, or put the pushes in a helper that returns `!AllocError` and end `Main` with `Helper() !! return 1;`, as in [Exit status](/docs/learn/exit-status).
::

::mistake
**Walking the vector without lending it.**\
`for value in numbers { … }` gives the vector to the loop, so a later `numbers.Length()` fails with:

```text
error: 'numbers' is used after it was given away
help: lend it with '&numbers' where it is only read, or clone it where both uses need a value
```

Write `for value in &numbers`.
::

::mistake
**A vector bound with `let`.**\
`Push` changes the vector. With `let numbers = …`, it fails with:

```text
error: cannot call 'Push' on immutable 'numbers'
```

Bind it with `var`.
::

::mistake
**Indexing with square brackets.**\
`numbers[0]` fails with:

```text
error: type 'Vector<int>' cannot be indexed
```

Use `numbers.Get(0)`, which returns an optional — or `numbers.AsSlice()` to get a slice you can index.
::

## Try it yourself

1. Push 1000 values and count how many times the capacity grew.
2. Make the vector with `Vector<int>::WithCapacity(allocator, 100)` instead. What are its length and capacity before the first push?
3. Remove the first value with `RemoveAt(0)`, which returns an optional, and print what is left.
4. Add up the values with a `for value in &numbers` loop, then again by indexing `numbers.AsSlice()`.
