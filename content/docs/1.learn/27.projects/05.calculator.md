# Calculator

A pocket calculator shows "E" when something goes wrong and leaves you guessing. This one works on 32-bit integers and says exactly **why** it cannot give an answer: you divided by zero, pressed a key that is not an operator, or asked for a result too large for an `int32`.

It is the checkpoint for [Part 9: Errors](/docs/learn/errors), and it uses each of the main tools from that part in the place where it fits best: `throw` to raise an error, plain `try` to pass one on, a `try { } catch { }` block to handle one, `match` to take one apart, and `try ... catch` to recover and carry on.

## How it is put together

Every way a sum can go wrong is a case of one error variant, and each case carries the detail that explains it:

```rux
variant CalcError {
    DivisionByZero,
    UnknownOperator(char),
    Overflow(int64)
}
```

Four small functions share the work with `Main`, plus `PrintTape`, which only echoes a tape. Arrows show who calls whom, and what travels back:

```mermaid
flowchart LR
    main(["`Main`"]) -- "`try { } catch { }`" --> apply["`Apply`<br/>one sum"]
    main -- "`try { } catch { }`" --> run["`Run`<br/>a whole tape"]
    run -- "each step, with `try`" --> apply
    apply -- "the answer, with `try`" --> narrow["`Narrow`<br/>`int64` → `int32`"]
    main -- "the error" --> explain["`Explain`<br/>one line per case"]
```

| Function  | What it does with an error                     | Lessons it uses                                                                                                |
| --------- | ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `Narrow`  | Throws `Overflow` when the answer does not fit | [Fail](/docs/learn/fail), [Convert](/docs/learn/convert)                                                       |
| `Apply`   | Throws the other two, passes `Narrow`'s on     | [Fail](/docs/learn/fail), [Match expression](/docs/learn/match-expression), [Propagate](/docs/learn/propagate) |
| `Run`     | Passes the first failure of a tape on          | [Propagate](/docs/learn/propagate), [Tuple](/docs/learn/tuple), [Destructure](/docs/learn/destructure)         |
| `Explain` | Turns each case into a sentence                | [Error variant](/docs/learn/error-variant), [Variant match](/docs/learn/variant-match)                         |
| `Main`    | Handles each sum's error, skips bad steps      | [Catch](/docs/learn/catch), [Catch fallback](/docs/learn/catch-fallback)                                       |

## Overflow is checked in a wider type

Adding or multiplying two `int32`s can overflow `int32`, but no sum, difference or product of two `int32`s can overflow `int64`. So `Apply` widens both operands, does the arithmetic there, and `Narrow` checks the answer on its way back down:

```rux
func Narrow(wide: int64) -> int32 throws CalcError {
    if wide > 2147483647 || wide < -2147483648 {
        throw CalcError::Overflow(wide);
    }
    return wide as int32;
}
```

That catches the case everyone expects, `2147483647 + 1`, and one people usually miss: `-2147483648 / -1`. The answer, 2147483648, is one more than an `int32` can hold, because the negative range reaches one further than the positive one.

## A match arm that throws

Inside `Apply`, a `match` expression picks the operation. Its last arm does not produce a value at all — it leaves the function by throwing:

```rux
let wide = match op {
    '+' => a + b,
    '-' => a - b,
    '*' => a * b,
    '/' => a / b,
    '%' => a % b,
    _ => throw CalcError::UnknownOperator(op)
};
return try Narrow(wide);
```

Division by zero is tested before the `match`, so `/` and `%` are never reached with a zero divisor. And `return try Narrow(wide);` passes an overflow straight to `Apply`'s caller: plain `try` keeps the answer and lets any error go on unchanged, which `Apply` may do because it is declared `throws CalcError` too.

## A tape stops at the first bad key

A tape is a run of key presses, each applied to the answer so far — like a real pocket calculator, strictly left to right, with no precedence. `Run` walks it, and one `try` is all it takes to make the first failure end the whole run:

```rux
for step in tape {
    let (op, operand) = step;
    total = try Apply(total, op, operand);
}
```

Each step is a tuple `(char, int32)`, and `let (op, operand) = step;` unpacks it. The bad tape fails at its second key, `/ 0`, so the `x` key after it is never even looked at.

## Handling the error once

`Main` does not throw, so the errors stop there. Each sum, and each tape, is printed inside a `try` block: every call in the block is covered, and the `catch` arm takes whatever error any of them threw:

```rux
try {
    PrintLine("{}", Run(0, bad));
} catch {
    error => Explain(error)
}
```

`Explain` then takes the error apart with a `match` that has one arm per case of `CalcError`, each with the detail its case carries — the key that is not an operator, or the answer that did not fit.

## Forgiving instead of failing

The end of `Main` runs the same bad tape a second time, but with `catch { _ => total }` instead of plain `try`. A step that fails leaves `total` as it was, and the tape carries on:

```rux
total = try Apply(total, op, operand) catch { _ => total };
```

`/ 0` and `x 2` are skipped, so the tape computes `(0 + 10) * 7 - 6`, which is 64. Which behaviour is right — stop at the first error or skip it — is a design decision, and the two loops show how little separates them: a `catch` after the `try`, or none.

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/Projects/Calculator). Its comments explain every step.

<!-- sync:program:start -->

```rux [Src/Main.rux]
// Calculator: a pocket calculator that works on 32-bit integers and says exactly why when it
// cannot give an answer.
//
// A real calculator shows "E" and leaves you guessing. This one has an error variant with one case
// for each way a sum can go wrong, carrying whatever detail explains it: dividing by zero, a key
// that is not an operator, and an answer too large for an `int32`.
//
// The arithmetic happens in `int64`, where no two `int32` values can overflow, and the answer is
// then checked on its way back down. That catches the cases people expect, such as 2147483647 + 1,
// and one they usually do not: -2147483648 / -1, whose answer is one more than an `int32` holds.
//
// The program uses each of the main tools from the Errors part. `Apply` raises one with
// `throw`. `Run` passes one on with `try`, so a tape of key presses stops at the first bad step.
// `Main` handles one with a `try { } catch { }` block, and `Explain` takes it apart with `match`.
// And the forgiving calculator at the end uses `try ... catch` to skip a bad step and carry on.
import Io::{ Print, PrintLine };

variant CalcError {
    DivisionByZero,
    UnknownOperator(char),
    Overflow(int64)
}

// Brings a wide answer back to `int32`, or fails if it does not fit.
func Narrow(wide: int64) -> int32 throws CalcError {
    if wide > 2147483647 || wide < -2147483648 {
        throw CalcError::Overflow(wide);
    }
    return wide as int32;
}

func Apply(left: int32, op: char, right: int32) -> int32 throws CalcError {
    if (op == '/' || op == '%') && right == 0 {
        throw CalcError::DivisionByZero;
    }
    let a = left as int64;
    let b = right as int64;
    // An arm may throw instead of producing a value: an unknown key ends the function right there.
    let wide = match op {
        '+' => a + b,
        '-' => a - b,
        '*' => a * b,
        '/' => a / b,
        '%' => a % b,
        _ => throw CalcError::UnknownOperator(op)
    };
    return try Narrow(wide);
}

// Presses the keys of a tape one after another, starting from `start`. The first step that fails
// fails the whole run, and `try` is all it takes to say so.
func Run(start: int32, tape: (char, int32)[..]) -> int32 throws CalcError {
    var total = start;
    for step in tape {
        let (op, operand) = step;
        total = try Apply(total, op, operand);
    }
    return total;
}

func Explain(error: CalcError) {
    match error {
        .DivisionByZero => PrintLine("error: division by zero"),
        .UnknownOperator(op) => PrintLine("error: '{}' is not an operator", op),
        .Overflow(wide) => PrintLine("error: {} does not fit in an int32", wide)
    }
}

func PrintTape(start: int32, tape: (char, int32)[..]) {
    Print("{}", start);
    for step in tape {
        let (op, operand) = step;
        Print(" {} {}", op, operand);
    }
    Print(" = ");
}

func Main() -> int {
    let sums: (int32, char, int32)[9] = [
        (12, '+', 30),
        (7, '*', 6),
        (17, '%', 5),
        (7, '/', 0),
        (7, '%', 0),
        (2, '^', 8),
        (2147483647, '+', 1),
        (-2147483648, '/', -1),
        (65536, '*', 65536)
    ];
    for sum in sums {
        let (left, op, right) = sum;
        Print("{} {} {} = ", left, op, right);
        try {
            PrintLine("{}", Apply(left, op, right));
        } catch {
            error => Explain(error)
        }
    }
    PrintLine();

    // A tape is a run of key presses, each applied to the answer so far. Like a pocket calculator,
    // it works strictly left to right, with no precedence: 1 + 2 * 3 is 9 on a tape, not 7.
    let good: (char, int32)[4] = [('+', 10), ('*', 7), ('-', 6), ('/', 8)];
    let bad: (char, int32)[5] = [('+', 10), ('/', 0), ('*', 7), ('x', 2), ('-', 6)];
    // A `try` block covers every call in it, and its arms handle whatever error they throw.
    PrintTape(0, good);
    try {
        PrintLine("{}", Run(0, good));
    } catch {
        error => Explain(error)
    }
    PrintTape(0, bad);
    try {
        PrintLine("{}", Run(0, bad));
    } catch {
        error => Explain(error)
    }

    // A forgiving calculator ignores a key it cannot use. `catch { _ => total }` keeps the
    // answer it already had, whatever went wrong, and the tape carries on past the bad steps.
    var total: int32 = 0;
    for step in bad {
        let (op, operand) = step;
        total = try Apply(total, op, operand) catch { _ => total };
    }
    PrintLine("skipping the bad keys instead: {}", total);
    return 0;
}
```

## Common mistakes

::mistake
**Forgetting the `try` in `Run`.**\
Without it, `total = Apply(total, op, operand);` is refused:

```text
error: call to 'Apply' can throw 'CalcError' but is not marked with 'try'
help: write 'try' before the expression
```

Every call that can throw is marked where it is made, so a reader sees each place the run can stop — see [Discard](/docs/learn/discard).
::

::mistake
**Plain `try` in a `Main` that does not throw.**\
Replacing the `try` block around a sum with `PrintLine("{}", try Apply(left, op, right));` has nowhere to send the error:

```text
error: call to 'Apply' can throw 'CalcError', but 'Main' does not throw
help: handle the error with 'try ... catch', or declare 'throws CalcError' on 'Main'
```

Plain `try` passes an error on, so it only works in a function declared to throw it. In `Main` the error is handled instead.
::

::mistake
**A match that misses a case.**\
Delete the `.DivisionByZero` arm from `Explain` and the compiler names what is missing:

```text
error: match on 'CalcError' is not exhaustive; missing CalcError::DivisionByZero
help: add arms for the missing cases, or a '_' arm
```

Adding a case to `CalcError` later makes every such `match` point at itself, which is exactly what you want.
::

::mistake
**`try` in the middle of an expression.**\
`return 0 + try Narrow(wide);` is refused:

```text
error: 'try' cannot appear to the right of an operator
help: write 'try' at the start of the whole expression, as in 'try x + F()'
```

One `try` at the front covers every call in the expression after it.
::

## Try it yourself

1. Add a `^` key for powers, with `2 ^ 8` giving 256. Compute it with a loop in `int64` and let `Narrow` catch a power that is too large. What should a negative exponent do — and does it need a new case in `CalcError`?
2. Add a case `NegativeRoot` and an `r` key that takes an integer square root, failing for a negative operand. The compiler will show you every `match` that needs a new arm.
3. Make the forgiving calculator report what it skipped. Give the `catch` an arm that names the error, `error => { Explain(error); total }`, so `total` stays as it was and the reason is printed.
4. Change `Run` so that it returns the number of the step that failed along with the error. Hint: a new error type that carries a `uint` and a `CalcError`, and [Error mapping](/docs/learn/error-mapping) to build it.
