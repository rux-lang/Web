A to-do list is only useful if it is still there tomorrow. This program keeps one as JSON in a file: it saves a list, loads it back as if it were a new session, adds a note, saves again, and then deals with the two things that go wrong with real files: one that someone damaged by hand, and one that is not there at all.

It is the checkpoint for [Part 21: Data formats](/docs/learn/data-formats), and it brings together files from [Part 19](/docs/learn/files), JSON from Part 21, and the error handling of [Part 9](/docs/learn/errors) at full strength: five different error types meet in one function.

## How it is put together

Each note is a small JSON object, `{"title": "...", "done": false}`, and the list is a JSON array of them. Saving turns the tree of `JsonValue`s into text and writes it; loading reads the text and parses it back into a tree:

```mermaid
flowchart LR
    tree["`JsonValue` tree<br/>in memory"] -- "`Encode`<br/>`WriteValue`, pretty" --> text["JSON text<br/>`String`"]
    text -- "`Save`<br/>`WriteAtomically`" --> file[("`Bin/notes.json`")]
    file -- "`Load`<br/>`Open`, `Size`, `ReadExact`" --> bytes["bytes"]
    bytes -- "`Parse`" --> tree
```

| Function     | Its job                                      | Can fail with               | Lessons it uses                                                                                |
| ------------ | -------------------------------------------- | --------------------------- | ---------------------------------------------------------------------------------------------- |
| `Note`       | Builds one note object                       | `TextError`, `JsonError`    | [Writing JSON](/docs/learn/json-write), [Give away](/docs/learn/give-away)                     |
| `Encode`     | Turns the tree into indented text            | `FormatError`               | [Writing JSON](/docs/learn/json-write), [String builder](/docs/learn/string-builder)           |
| `Save`       | Replaces the file in one step                | `IoError`                   | [Atomic file](/docs/learn/atomic-file)                                                         |
| `Load`       | Reads the whole file and parses it           | `IoError`, `JsonParseError` | [File](/docs/learn/file), [Dynamic array](/docs/learn/dynamic-array), [JSON](/docs/learn/json) |
| `PrintNotes` | Prints the list, tolerating missing members  | nothing                     | [JSON](/docs/learn/json), [Presence](/docs/learn/presence)                                     |
| `KeepNotes`  | Two sessions, a damaged file, a missing file | all five                    | [Error sum](/docs/learn/error-sum), [Typed pattern](/docs/learn/typed-pattern)                 |
| `Main`       | Turns any failure into exit status 1         | nothing                     | [Exit status](/docs/learn/exit-status)                                                         |

## Building a note

A note is an object with two members. Building it can fail in two ways — `String::FromBytes` and `JsonValue::Text` fail with a `TextError` when the bytes are not valid text, and `Insert` fails with a `JsonError` when the value is not an object — so the function can fail with the sum of the two, and every call that can fail is followed by `!`:

```rux
func Note(allocator: Allocator, title: char8[..], done: bool) -> JsonValue ! TextError | JsonError {
    var note = JsonValue::Object(allocator);
    note.Insert(String::FromBytes(allocator, "title")!, JsonValue::Text(allocator, title)!)!;
    note.Insert(String::FromBytes(allocator, "done")!, JsonValue::Boolean(allocator, done))!;
    return note;
}
```

A `!` belongs to one call, so the first line has three: one for each argument, which must be a `String` and a `JsonValue` before `Insert` can take them, and one for `Insert` itself. `JsonValue::Boolean` cannot fail and needs none. A `JsonValue` owns the memory of everything inside it, so it cannot be copied; `return note;` gives it away to the caller.

## Saving whole or not at all

`Save` is one call, and the call is the point:

```rux
func Save(allocator: Allocator, path: Path, text: char8[..]) -> !IoError {
    WriteAtomically(allocator, path, text)!;
}
```

`-> !IoError` says that `Save` gives back nothing, or fails with an `IoError`. `WriteAtomically` writes the new text beside the old file and swaps it in only once it is complete. If the program crashes halfway through a save, the old list is still there, whole. Writing over the file directly would risk leaving half a list behind, the one outcome a notes file must never have.

## Loading, step by step

`Load` asks the file how big it is, reads exactly that many bytes into an array of that size, and parses them:

```rux
func Load(allocator: Allocator, path: Path)
    -> JsonValue ! IoError | JsonParseError {
    var file = File::Open(allocator, path, OpenOptions::Reading())!;
    let size = file.Size()!;
    var bytes = Array::Filled<char8>(allocator, size as uint, c8' ');
    ReadExact(&var file, bytes.AsMutableSlice())!;
    file.Close()!;
    return Parse(allocator, bytes.AsSlice())!;
}
```

Opening, sizing, reading and closing can each fail with an `IoError`, and parsing with a `JsonParseError`. The result type names both as a sum, and every `!` passes its error through unchanged. Making the array is the one step without a `!`: running out of memory is not an error a caller handles, so `Array::Filled` cannot fail. `ReadExact` reads through the file, which changes its position, so it takes the file as a written loan, `&var file`.

## Reading what may not be there

A file read from disk may have been edited by hand, so `PrintNotes` does not assume a note has both members. `Find` returns an optional reference, `none` when the member is missing, and `AsBoolean` returns `bool?`, `none` when the member is not a boolean:

```rux
let note = notes.At(i) ?? continue;
var done = false;
if let flag? = note.Find(StringView::FromValidated("done")) {
    done = flag.AsBoolean() ?? false;
}
```

`if let flag? = ...` runs its block only when the member is there, with `flag` bound to it, and `?? false` covers a member of the wrong kind. The title is read the same way, so a note with no title prints as `(untitled)`.

## Expected failures, and the rest

`Main` must be `func Main() -> int`, so it cannot fail itself. The work that can fail lives in `KeepNotes`, declared `-> !IoError | TextError | FormatError | JsonError | JsonParseError`, so a `!` anywhere in it can pass any of the five on. `Main` turns a failure into exit status 1 in one line:

```rux
func Main() -> int {
    KeepNotes() !! return 1;
    return 0;
}
```

But two failures are **expected**, and those are handled where they happen. `Load` is called without a `!`, so its whole outcome (a `JsonValue`, or an `IoError | JsonParseError`) goes to a `match` that takes it apart. A damaged file is a `JsonParseError`, which knows the byte where the text stopped making sense:

```rux
match Load(allocator, path) {
    _: JsonValue => PrintLine("the damaged file loaded?"),
    error: JsonParseError => PrintLine("damaged file refused at byte {}: {}", error.Offset(), error),
    .Failure(error) => throw error
}
```

The typed pattern `_: JsonValue` takes the success, and `error: JsonParseError` picks one member out of the error sum. A missing file is an `IoError` of kind `NotFound`, picked out with a typed pattern **and** a guard. In a real program, that arm is where "start a new, empty list" would go:

```rux
error: IoError if error.kind == IoErrorKind::NotFound =>
    PrintLine("no notes file any more: starting a new list would begin here"),
.Failure(error) => throw error
```

In both matches the last arm, `.Failure(error)`, takes every failure the arms above it left, with `error` bound to the error as the whole sum, `IoError | JsonParseError`. `throw error` passes it out of `KeepNotes`, and `Main` ends the program with status 1.

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/Projects/Notes). Its comments explain every step.

<!-- sync:program:start -->

```rux [Src/Main.rux]
// Notes: a to-do list that outlives the program, kept as JSON in a file.
//
// Each note is a small JSON object, `{"title": "...", "done": false}`, and the list is an array
// of them. Saving turns the tree of `JsonValue`s into text and writes it to disk; loading reads
// the text back and parses it into a tree again. Between the two, the program could stop and
// start a hundred times, which is the whole point of a file.
//
// A file is also where things go wrong. It may be missing, or it may hold something that is not
// JSON, perhaps because someone edited it by hand. Every step that touches the disk or parses
// text can fail, and the program handles the two failures it expects (a damaged file and a
// missing one), while `!` passes anything stranger on, and `Main` then ends with status 1.
//
// The file lives in this package's `Bin/` folder, and the program deletes it at the end.
import Allocator::{ Allocator, SystemAllocator };
import Collections::Array;
import FileSystem::{ DeleteFile, File, OpenOptions, WriteAtomically };
import Io::{ IoError, IoErrorKind, PrintLine, ReadExact };
import Json::{ JsonError, JsonParseError, JsonStyle, JsonValue, Parse, WriteValue };
import Path::{ OsString, Path };
import Text::{ String, StringBuilder, StringView, TextError, TextWriter };
import Text::Formatting::FormatError;

func Note(allocator: Allocator, title: char8[..], done: bool) -> JsonValue ! TextError | JsonError {
    var note = JsonValue::Object(allocator);
    note.Insert(String::FromBytes(allocator, "title")!, JsonValue::Text(allocator, title)!)!;
    note.Insert(String::FromBytes(allocator, "done")!, JsonValue::Boolean(allocator, done))!;
    return note;
}

// Turns the notes into indented JSON text, ready to be written or shown.
func Encode(allocator: Allocator, notes: &JsonValue) -> String ! FormatError {
    var builder = StringBuilder::New(allocator);
    let sink: &var TextWriter = builder;
    WriteValue(sink, notes, JsonStyle::Pretty())!;
    return builder.TakeString();
}

// Writing atomically means the old file is replaced only once the new one is complete, so a
// crash halfway through a save can never leave half a list behind.
func Save(allocator: Allocator, path: Path, text: char8[..]) -> !IoError {
    WriteAtomically(allocator, path, text)!;
}

// Asks the file how big it is, reads exactly that many bytes, and parses them.
func Load(allocator: Allocator, path: Path)
    -> JsonValue ! IoError | JsonParseError {
    var file = File::Open(allocator, path, OpenOptions::Reading())!;
    let size = file.Size()!;
    var bytes = Array::Filled<char8>(allocator, size as uint, c8' ');
    ReadExact(&var file, bytes.AsMutableSlice())!;
    file.Close()!;
    return Parse(allocator, bytes.AsSlice())!;
}

// A note read from a file might lack a member, or hold one of the wrong kind, so each lookup
// gives an optional that is checked before it is read.
func PrintNotes(notes: &JsonValue) {
    for i in 0..(notes.Length() ?? 0) {
        let note = notes.At(i) ?? continue;
        var done = false;
        if let flag? = note.Find(StringView::FromValidated("done")) {
            done = flag.AsBoolean() ?? false;
        }
        let mark = if done { "x" } else { " " };
        var title = StringView::FromValidated("(untitled)");
        if let member? = note.Find(StringView::FromValidated("title")) {
            title = member.AsText() ?? title;
        }
        PrintLine("  [{}] {}", mark, title);
    }
}

func KeepNotes() -> !IoError | TextError | FormatError | JsonError | JsonParseError {
    let allocator = SystemAllocator::New();

    var holder = OsString::FromText(allocator, "Bin/notes.json");
    let path = Path::FromView(holder.View());

    // The first session: start a list and save it.
    var notes = JsonValue::Array(allocator);
    notes.Push(Note(allocator, "buy milk", true)!)!;
    notes.Push(Note(allocator, "water the plants", false)!)!;
    let first = Encode(allocator, &notes)!;
    Save(allocator, path, first.View().Bytes())!;
    PrintLine("saved {} notes to {}", notes.Length() ?? 0, path);

    // The next session knows nothing but the file: load it, add a note, save it again.
    var loaded = Load(allocator, path)!;
    loaded.Push(Note(allocator, "write a Rux program", false)!)!;
    let second = Encode(allocator, &loaded)!;
    Save(allocator, path, second.View().Bytes())!;
    PrintLine("added a note; the file now reads:");
    PrintLine("{}", second.View());

    // And one more time, to read the list as a person would.
    let final = Load(allocator, path)!;
    PrintLine("{} notes:", final.Length() ?? 0);
    PrintNotes(&final);

    // Someone edits the file by hand and cuts it short. Loading now fails as a parse error, which
    // says where the text stopped making sense.
    Save(allocator, path, "[{\"title\": \"half a note\"")!;
    match Load(allocator, path) {
        _: JsonValue => PrintLine("the damaged file loaded?"),
        error: JsonParseError => PrintLine("damaged file refused at byte {}: {}", error.Offset(), error),
        .Failure(error) => throw error
    }

    // Clean up, then show that a missing file is told apart from every other I/O failure.
    DeleteFile(allocator, path)!;
    match Load(allocator, path) {
        _: JsonValue => PrintLine("the deleted file loaded?"),
        error: IoError if error.kind == IoErrorKind::NotFound =>
            PrintLine("no notes file any more: starting a new list would begin here"),
        .Failure(error) => throw error
    }
}

func Main() -> int {
    KeepNotes() !! return 1;
    return 0;
}
```

Besides `Io`, its `Rux.toml` lists `Allocator`, `Collections`, `FileSystem`, `Json`, `Path` and `Text` under `[Dependencies]`.

## Common mistakes

::mistake
**One `!` for a whole line.**\
A `!` passes on the error of the one call it follows. Leave it off the inner `String::FromBytes` and `Insert` is handed the whole outcome instead of a `String`:

```text
error: argument 1 to 'Insert' has type 'String ! TextError', but parameter 'name' requires 'String'
```

Every call that can fail needs its own `!` — here three on one line.
::

::mistake
**Lending a `JsonValue` without writing the loan.**\
`Encode` takes `&JsonValue`, and a `JsonValue` owns memory, so `Encode(allocator, notes)` is refused:

```text
error: 'Encode' borrows its argument, and 'JsonValue' owns resources, so the loan must be written
help: write '&notes'
```

Write `Encode(allocator, &notes)`, so the reader sees that `notes` is only lent.
::

::mistake
**Handling only the failure you were thinking of.**\
Drop the `.Failure(error)` arm from the damaged-file `match` and the compiler names what is left:

```text
error: match on 'JsonValue ! IoError | JsonParseError' is not exhaustive; missing _: IoError
```

One `.Failure(error) => throw error` arm passes the rest on. A plain `error =>` arm will not do: a bare name takes the whole outcome, success included, and `throw` refuses it:

```text
error: 'throw' value must have type 'FormatError | IoError | JsonError | JsonParseError | TextError', but found 'JsonValue ! IoError | JsonParseError'
```

::

::mistake
**A `!` the function's type does not allow.**\
If `Load` is declared `-> JsonValue ! IoError`, the parse at its end stops compiling:

```text
error: call to 'Parse' can fail with 'JsonParseError', but 'Load' fails with 'IoError'
note: an error passes on only as itself, as a member of a sum, or as part of a larger sum; it is never converted
help: handle the error with 'catch { ... }', or add 'JsonParseError' to the error of 'Load'
```

The sum must name every error its `!`s can pass on.
::

## Try it yourself

1. Mark a note as done: load the list, find "water the plants", set its `done` member to `true`, and save it again.
2. Turn the missing-file arm into real behaviour: when the file is not there, start with an empty array instead of failing.
3. Make the program a tiny command-line tool: read one line from the input with [Input](/docs/learn/input), add it as a note, save, and print the list. Remove the `DeleteFile` call so the notes survive between runs.
4. Damage the file differently (a missing comma, a stray `}`) and see what offset and message the parser reports for each.
