# Intrinsic

::note
<!-- sync:needs:start -->

**You'll need**: [Dependency](/docs/learn/dependency), [Target](/docs/learn/target), [Assert](/docs/learn/assert), [Exit status](/docs/learn/exit-status)
<!-- sync:needs:end -->

::

`int8::Max`, `#target` and `Assert` have come from `Core` in every lesson so far, so it is easy to think of them as part of the language itself. They are not. The type `int8` is built into the compiler, but its constants come from an **extension**, and `#target` and `Assert` from **declarations** of what the compiler implements — the fields of `#target`, the code an `Assert` turns into. `Core` is simply the package that usually provides both.

An `intrinsic` declaration names something the compiler supplies and gives its type, with no body. This lesson writes a few of them in `Basis`, a small provider package of its own, binds it in place of `Core`, and runs a program that takes everything from `Basis`. The names work exactly as they would from `Core`; the one thing the program loses is `Core` itself, and every package built on it.

## An extension and three kinds of intrinsic

Open `Basis/Src/Basis.rux` in the code tree below. It is a handful of lines, and each part provides something different.

**Constants on a built-in type**. `int8`, like every primitive type, is built into the compiler, so nothing declares it. The constants on it are ordinary source in an extension, so the provider decides which ones to offer:

```rux
extend int8 {
    pub const Min: int8 = -128i8;
    pub const Max: int8 = 127i8;
}
```

A **constant** whose value no literal can spell. There is no way to write infinity in source, so the compiler supplies it:

```rux
extend float64 {
    pub intrinsic const Infinity: float64;
}
```

A **compile-time value**. `#target` is declared as an ordinary struct plus one intrinsic line that says "the compiler fills this in". The provider lists only the fields it wants to expose:

```rux
pub struct Target {
    pub pointerBits: uint;
}

pub intrinsic #target: Target;
```

A **function** the compiler emits inline. The provider writes the signature, which must be the one the compiler expects:

```rux
pub intrinsic func Assert(condition: bool, message: char8[..]);
```

`Core` declares all of these in exactly the same way — its own `Assert` is that same line, word for word. The package gets no special powers from being called `Core`; what it has is the role of the build's **intrinsics package**, which the next section hands to `Basis`.

| Kind              | The compiler supplies       | The provider writes                    |
| ----------------- | --------------------------- | -------------------------------------- |
| `extend int8`     | the type and its operations | constants and methods, as plain source |
| `intrinsic const` | the value                   | the name and the type                  |
| `intrinsic #name` | each field's value          | the struct, with the fields it exposes |
| `intrinsic func`  | the code at every call      | the signature the compiler expects     |

## Taking them from a provider

Exactly one package in a build may declare intrinsics, so that every name the compiler supplies is declared once. That package is `Core` unless the root manifest names another, and this lesson's `Rux.toml` does, in its `[Package]` table:

```toml
Intrinsics = "Basis"
```

`Basis` is a [source library](/docs/learn/source-library) in a folder beside the program, and the same manifest names it with a path [dependency](/docs/learn/dependency): `Basis = { Path = "Basis" }`. There is no `Core` in that manifest at all. The program imports from `Basis` the same names it would otherwise import from `Core`; importing `int8` and `float64` imports `Basis`'s extensions of them:

```rux
import Basis::{ #target, Assert, float64, int8 };
```

```mermaid
flowchart LR
    c(["The compiler implements<br/>`int8`, `Infinity`, `#target`, `Assert`"]) --> core["`Core` declares them<br/>(the usual provider)"]
    c --> basis["`Basis` declares them<br/>(this lesson's provider)"]
    core -.->|"every other lesson"| p["`Main.rux` imports<br/>the declarations"]
    basis -->|"this lesson"| p
```

Since only `Basis` is imported, only what `Basis` declares is available. The type `int16` still exists, but `int16::Max` does not: no provider in this program offers it, and `import Basis::int16;` is refused because `Basis` does not extend it.

## A program without `Core`

The price of a provider of your own is that `Core` cannot be part of the build — its declarations would now be refused — and neither can any package built on it. That includes `Io`, so this program has no `PrintLine`. It checks what it gets instead, and answers with its [exit status](/docs/learn/exit-status): 0 when every check holds, and the number of the check that failed otherwise:

```rux
// A value the compiler fills in for the target. Every supported target has 64-bit pointers.
if #target.pointerBits != 64 {
    return 3;
}
```

`rux run` prints nothing about the status, so ask the shell for it with `echo $?` straight after: a quiet run that ends in `0` is a pass.

## Only real intrinsics

`intrinsic` cannot invent new features. Every declaration is checked against what the compiler really implements, and anything else is refused: a function called `Square`, a `wordSize` field on `Target`, an `Assert` whose condition is an `int`. A type cannot be declared at all, since every primitive is built in. Writing a provider is a way to replace `Core`, not a way to extend the language.

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/CompileTime/Intrinsic). Its comments explain every step.

::code-tree{defaultValue="Src/Main.rux"}

```toml [Rux.toml]
[Manifest]
Version = 1
MinRux = "0.4.0"

[Package]
Name = "Intrinsic"
Version = "0.1.0"
Type = "Executable"
Description = "Declaring compiler-provided constants and values in a provider package of your own"
Authors = ["Rux Contributors <info@rux-lang.dev>"]
Intrinsics = "Basis"

[Dependencies]
Basis = { Path = "Basis" }
```

```toml [Basis/Rux.toml]
[Manifest]
Version = 1
MinRux = "0.4.0"

[Package]
Name = "Basis"
Version = "0.1.0"
Type = "SourceLibrary"
Description = "A small provider of primitive extensions and intrinsic declarations, standing in for part of Core"
Authors = ["Rux Contributors <info@rux-lang.dev>"]
```

```rux [Src/Main.rux]
// `int8::Max`, `#target` and `Assert` have always come from `Core`, so they can look like part of
// the language. They are not. The type `int8` is built in, but its constants come from an
// extension, and `#target` and `Assert` from *declarations*; `Core` is simply the package that
// usually provides both. An `intrinsic` declaration names something the compiler supplies and
// gives its type, with no body.
//
// Exactly one package in a build may declare intrinsics, so that every name the compiler supplies
// is declared once. That package is `Core` unless the root manifest names another, and this
// lesson's `Rux.toml` does: `Intrinsics = "Basis"` takes the declarations from `Basis`, a small
// provider package beside this one. Open `Basis/Src/Basis.rux`: it is a handful of lines.
//
// The price is that `Core` cannot be part of the build, and neither can any package built on it,
// such as `Io`: its declarations would be refused with "'intrinsic' is allowed only in the
// intrinsics package". So this program prints nothing. Its answer is its exit status: 0 when
// every check below holds, and the number of the check that failed otherwise.
//
// Only real intrinsics can be declared this way. An `intrinsic func` the compiler does not
// implement "is not a supported intrinsic function", and a type cannot be declared at all: every
// primitive is built in, so `intrinsic type int7` is refused because "intrinsic type declarations
// have been removed". Writing a provider is a way to replace `Core`, not a way to invent new
// language features.
import Basis::{ #target, Assert, float64, int8 };

func Main() -> int {
    // Constants from an extension, written as ordinary source in `Basis`.
    if int8::Min != -128i8 || int8::Max != 127i8 {
        return 1;
    }

    // A constant whose value the compiler supplies, since no literal can spell it.
    if !(float64::Infinity > 1.0e308) {
        return 2;
    }

    // A value the compiler fills in for the target. Every supported target has 64-bit pointers.
    if #target.pointerBits != 64 {
        return 3;
    }

    // A function the compiler emits inline. Raise `level` to 127 and the program stops with
    // "Assertion failed: the level must leave room to grow".
    let level: int8 = 100;
    Assert(level < int8::Max, "the level must leave room to grow");
    return 0;
}
```

```rux [Basis/Src/Basis.rux]
// Everything here is either an extension of a built-in type or a declaration the compiler already
// knows how to implement. `intrinsic` says "the compiler supplies this; here is its name and its
// type", and gives it no body. The package gets no special powers from this: Core declares the
// same things in exactly the same way. It may declare them only because the program's `Rux.toml`
// binds it with `Intrinsics = "Basis"`; any other package of the build would be refused.

// The one-byte signed integer is built into the compiler, so nothing declares it. Its constants
// are ordinary source in an extension, so the provider chooses which ones to offer.
extend int8 {
    pub const Min: int8 = -128i8;
    pub const Max: int8 = 127i8;
}

// Infinity cannot be written as a literal, so the compiler supplies its value.
extend float64 {
    pub intrinsic const Infinity: float64;
}

// A compile-time value. The provider declares only the fields it wants to expose, and only ones
// the compiler fills in: a `wordSize` field is refused as "not one the compiler supplies for
// '#target'".
pub struct Target {
    pub pointerBits: uint;
}

pub intrinsic #target: Target;

// A function the compiler emits inline. The signature must be the one the compiler expects:
// declared with `condition: int`, it is refused with "intrinsic 'Assert' must be declared as
// 'func Assert(condition: bool, message: char8[..])'".
pub intrinsic func Assert(condition: bool, message: char8[..]);
```

## Common mistakes

::mistake
**Declaring intrinsics without the binding.**\
Take `Intrinsics = "Basis"` out of `Rux.toml` and `Core` is the intrinsics package again, so every declaration in `Basis` fails with:

```text
error: 'intrinsic' is allowed only in the intrinsics package
help: give the declaration a body, or bind 'Basis' with 'Intrinsics' in [Package]
```

Adding `Io` to the program's dependencies brings `Core` back into the build, and its declarations fail the same way.
::

::mistake
**Declaring a type.**\
Every primitive type is built in, so `pub intrinsic type int7;` fails with:

```text
error: intrinsic type declarations have been removed; primitive types are built in
```

Likewise, an `intrinsic func` the compiler does not implement fails with:

```text
error: 'Square' is not a supported intrinsic function
```

::

::mistake
**Adding a field the compiler does not fill in.**\
A `wordSize` field on `Target` fails with:

```text
error: field 'wordSize' of 'Target' is not one the compiler supplies for '#target'
```

Every field of an intrinsic struct must be one the compiler knows.
::

::mistake
**Getting an intrinsic signature wrong.**\
Declared with `condition: int`, `Assert` fails with:

```text
error: intrinsic 'Assert' must be declared as 'func Assert(condition: bool, message: char8[..])'
```

The message tells you the one signature it accepts.
::

::mistake
**Using a constant the provider does not offer.**\
Only what `Basis` declares is in scope. `int16::Max` fails with:

```text
error: 'Max' not found in extend for type 'int16'
```

That is because `Basis` declares no constants for `int16`.
::

## Try it yourself

1. Add `pub triple: char8[..];` to the `Target` struct in `Basis`, and add a fourth check to `Main` that returns 4 when `#target.triple` is empty. What status does the program end with?
2. Change `level` to `127` and run. Which line stops the program, and with what message?
3. Add `pub intrinsic type int8;` to `Basis`, read the error and its help, and take it out again.
4. Add a check on `int16::Max` to `Main`. Then add the constants to `Basis`, the way `int8` has them, until it builds.
