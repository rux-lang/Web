# Streaming JSON

::note
<!-- sync:needs:start -->

**You'll need**: [JSON](/docs/learn/json), [Interface value](/docs/learn/interface-value), [Destructor](/docs/learn/destructor), [Catch](/docs/learn/catch), [Variant match](/docs/learn/variant-match), [Optional](/docs/learn/optional)
<!-- sync:needs:end -->

::

`Parse` builds the whole tree before your program sees any of it. For a settings file that is ideal. For a log of a million records it is not: the tree costs several times the document's size in memory, and a program that only wants one field from each record pays for all of them.

`JsonEventReader` reads the same text as a **stream of events** instead — an object opened, a name, a text value, an array closed — pulling bytes from a source as it needs them and keeping only the token it is on. The program keeps whatever it wants and lets the rest go by. This lesson prints the title of every book in a catalogue without ever building a tree.

```rux
import Io::{ IoError, IoErrorKind, PrintLine, Reader };
import Json::{ JsonEvent, JsonEventReader, JsonLimits, JsonReadError };
```

## A source of bytes

The event reader reads from any `Reader` — the interface that files and network connections implement. The lesson stands one in with `TextSource`, which serves a string at most 8 bytes per read, so tokens arrive split across reads just as they would from a real stream:

```rux
struct TextSource {
    text: char8[..];
    offset: uint;
}
```

Its `Read` method copies up to 8 bytes into the buffer it is given and returns how many, or fails with an `IoError` of kind `EndOfStream` when nothing is left:

```rux
extend TextSource : Reader {
    func Read(&var self, into: var char8[..]) -> uint ! IoError {
        let remaining = self.text.length - self.offset;
        if remaining == 0 {
            throw IoError::Of(IoErrorKind::EndOfStream);
        }
        var count: uint = 8;
        if remaining < count { count = remaining; }
        if into.length < count { count = into.length; }
        for i in 0..count {
            into[i] = self.text[self.offset + i];
        }
        self.offset += count;
        return count;
    }
}
```

Inside `Titles`, the reader is built on the source. The reader keeps it for as long as it lives, so it holds a `Reader` [handle](/docs/learn/interface-value) made from the source's address, `@source`: the handle copies nothing, it only points. Taking an address needs no special block, but nothing checks that the address stays good, so by convention a `// Safety:` comment above the line says why it does — here, because `source` is declared first and so outlives the reader:

```rux
var source = TextSource { text: document, offset: 0 };
// Safety: `source` is a local declared before `reader`, so it outlives it, and is never given
// away.
var reader = JsonEventReader::New(allocator, @source as Reader, JsonLimits::Default());
```

`JsonEventReader::New` allocates the reader's buffer. `JsonLimits::Default()` sets the limits a document must stay within — its size, the length of one string, how deeply it nests — generous for ordinary documents and well short of what would exhaust the machine.

## Events

Each call to `Next()` returns the next `JsonEvent`, and `Depth()` says how many arrays and objects are open. The first book of the catalogue produces:

| Token     | Event         | `Depth()` | `Text()` |
| --------- | ------------- | --------- | -------- |
| `[`       | `ArrayStart`  | 1         |          |
| `{`       | `ObjectStart` | 2         |          |
| `"title"` | `Name`        | 2         | `title`  |
| `"Dune"`  | `Text`        | 2         | `Dune`   |
| `"year"`  | `Name`        | 2         | `year`   |
| `1965`    | `Number`      | 2         | `1965`   |
| `}`       | `ObjectEnd`   | 1         |          |

…and at the very end, `ArrayEnd`. Commas and colons produce no events, and `True`, `False` and `Null` complete the set. There is no event for the end of the document and none for a mistake. `Next` is declared:

```
Next(&var self) -> JsonEvent? ! JsonReadError
```

It answers `none` once the document is over, and [fails](/docs/learn/fallible) when the document goes wrong.

## The loop

`Titles` asks for events until there are none, counts each object one level inside the top-level array as a book, and prints the text that follows a `title` name:

```rux
var books: uint = 0;
var wantTitle = false;
// `!` passes a failure on to the caller; the loop ends when `Next()` answers `none`.
while let event? = reader.Next()! {
    // Each book is an object one level inside the top-level array.
    if event == JsonEvent::ObjectStart && reader.Depth() == 2 {
        books += 1;
    }
    // Print the title now: its text is gone once `Next()` is called again.
    if event == JsonEvent::Text && wantTitle {
        PrintLine("  title: {}", reader.Text());
    }
    wantTitle = event == JsonEvent::Name && IsTitle(reader.Text());
}
return books;
```

The loop condition does three jobs. The `!` right after the call [passes](/docs/learn/propagate) a failure on to the caller of `Titles`, leaving a `JsonEvent?`; [`while let event?`](/docs/learn/if-let) binds the event for the body; and when `Next()` answers `none`, the pattern does not match and the loop ends. `!` is a tight postfix that belongs to the call before it, so no parentheses are needed.

Order inside a book does not matter: Emma's `year` comes before its `title`, and the title is still found, because the program reacts to whatever name it meets.

## Two jobs that move onto the program

Streaming saves memory by keeping almost nothing, and that hands two jobs to the program.

**Lifetimes.** `Text()` borrows the reader's buffer, and the next `Next()` reuses it. So the text of an event must be used — or copied — before asking for another. That is why the title is printed the moment it arrives, and why `wantTitle` remembers only a `bool`, not the name's text. The buffer itself belongs to the reader, and the reader's [destructor](/docs/learn/destructor) gives it back however `Titles` ends: at the `return`, or with an error passed on from `Next()`.

**Errors arrive late.** A stream cannot know that the end of a document is wrong until it gets there. When it does, `Next()` fails, and the error says why and at which byte of the whole document — however it was split into reads. By then the earlier events have already been delivered:

```mermaid
flowchart LR
    n["`Next()`"] --> e{"Answer?"}
    e -- "`ObjectStart`, `Name`,<br/>`Text`, …" --> use["use it now"] --> n
    e -- "`none`" --> ok(["`books`"])
    e -- "fails" --> f(["`JsonReadError`"])
```

In the output, both broken catalogues print their titles _before_ being refused. A program that streams must be ready to discover, late, that its input was bad — and must not have committed anything it cannot take back.

## Two kinds of failure

`Titles` is declared `-> uint ! JsonReadError`, and `JsonReadError` is a [variant](/docs/learn/error-variant) with one case per way reading can stop:

| `JsonReadError`             | Means                                                                    |
| --------------------------- | ------------------------------------------------------------------------ |
| `Malformed(JsonParseError)` | the document is not JSON; the parse error says why and at which byte     |
| `Source(IoError, uint)`     | the source failed with something other than its end, after so many bytes |

`Report` [matches the outcome](/docs/learn/outcome) of `Titles`. `.Success(books)` takes the count, and a `.Failure(...)` arm takes apart each case of the error, [as a variant](/docs/learn/variant-match) is taken apart:

```rux
match Titles(allocator, document) {
    .Success(books) => PrintLine("  {} books", books),
    .Failure(.Malformed(reason)) => PrintLine("  refused at byte {}: {}", reason.Offset(), reason),
    .Failure(.Source(_, read)) => PrintLine("  the source failed after {} bytes", read)
}
```

The `Malformed` case carries the same `JsonParseError`, with the same offsets, that `Parse` would report for the same text.

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/DataFormats/JsonStream). Its comments explain every step.

<!-- sync:program:start -->

```rux [Src/Main.rux]
// `Parse` builds the whole tree before a program sees any of it, so a large document costs its
// size several times over in memory. `JsonEventReader` reads the same text as a stream of
// events instead — an object opened, a name, a text value, an array closed — pulling bytes from
// a `Reader` as it needs them and keeping only the token it is on. The program keeps whatever it
// wants and lets the rest go by.
//
// Streaming moves two jobs onto the program:
//
//   - Lifetimes. `Text()` borrows the reader's buffer, which the next `Next()` reuses, so the text
//     of an event must be used or copied before asking for another. The reader owns that buffer,
//     and its destructor gives it back however the function holding it ends.
//   - Errors. `Next()` answers `none` at the end of the document and fails with a `JsonReadError`
//     when the document goes wrong. Its `Malformed` case holds the `JsonParseError` that says why
//     and at which byte of the whole document, however it was split into reads; a source that
//     fails is its `Source` case, with the source's own `IoError` and how far it got. Events
//     before the mistake were already delivered, so a program must be ready to find out late
//     that its input was bad.
import Allocator::{ Allocator, SystemAllocator };
import Io::{ IoError, IoErrorKind, PrintLine, Reader };
import Json::{ JsonEvent, JsonEventReader, JsonLimits, JsonReadError };
import Text::StringView;

// Stands in for a file or a socket: serves its text at most 8 bytes per read, so tokens arrive
// split across reads, as they would from a real stream.
struct TextSource {
    text: char8[..];
    offset: uint;
}

extend TextSource : Reader {
    func Read(&var self, into: var char8[..]) -> uint ! IoError {
        let remaining = self.text.length - self.offset;
        if remaining == 0 {
            throw IoError::Of(IoErrorKind::EndOfStream);
        }
        var count: uint = 8;
        if remaining < count { count = remaining; }
        if into.length < count { count = into.length; }
        for i in 0..count {
            into[i] = self.text[self.offset + i];
        }
        self.offset += count;
        return count;
    }
}

func IsTitle(text: char8[..]) -> bool {
    let title = StringView::FromValidated("title");
    return StringView::FromValidated(text).Equals(title);
}

// Prints the title of every book and counts the books, without ever building a tree.
func Titles(allocator: Allocator, document: char8[..]) -> uint ! JsonReadError {
    var source = TextSource { text: document, offset: 0 };
    // The reader keeps a `Reader` handle that addresses `source`, so `source` has to outlive it.
    // The reader's buffer lives as long as `reader` does. Whether this function ends at the
    // `return` or with an error passed on from `Next()`, the destructor frees it on the way out.
    // Safety: `source` is a local declared before `reader`, so it outlives it, and is never given
    // away.
    var reader = JsonEventReader::New(allocator, @source as Reader, JsonLimits::Default());
    var books: uint = 0;
    var wantTitle = false;
    // `!` passes a failure on to the caller; the loop ends when `Next()` answers `none`.
    while let event? = reader.Next()! {
        // Each book is an object one level inside the top-level array.
        if event == JsonEvent::ObjectStart && reader.Depth() == 2 {
            books += 1;
        }
        // Print the title now: its text is gone once `Next()` is called again.
        if event == JsonEvent::Text && wantTitle {
            PrintLine("  title: {}", reader.Text());
        }
        wantTitle = event == JsonEvent::Name && IsTitle(reader.Text());
    }
    return books;
}

func Report(allocator: Allocator, document: char8[..]) {
    PrintLine("{}", document);
    // The outcome is matched: `.Success` takes the count, and `.Failure` each case of the error.
    match Titles(allocator, document) {
        .Success(books) => PrintLine("  {} books", books),
        .Failure(.Malformed(reason)) => PrintLine("  refused at byte {}: {}", reason.Offset(), reason),
        .Failure(.Source(_, read)) => PrintLine("  the source failed after {} bytes", read)
    }
}

func Main() -> int {
    let allocator = SystemAllocator::New();
    let catalog = "[{\"title\": \"Dune\", \"year\": 1965}, {\"year\": 1815, \"title\": \"Emma\"}]";
    Report(allocator, catalog);

    // Two broken documents. In both, titles were printed before the mistake was found: a
    // stream cannot know the end is wrong until it gets there.
    Report(allocator, "[{\"title\": \"Dune\"}, {\"title\": \"Emma\"]");
    Report(allocator, "[{\"title\": \"Dune\"}, {\"title\":");
    return 0;
}
```

Besides `Io`, its `Rux.toml` lists `Allocator`, `Json` and `Text` under `[Dependencies]`.

## Common mistakes

::mistake
**Binding the event without `!`.**\
`Next()` answers a fallible optional, `JsonEvent? ! JsonReadError`, and the optional is only reached once the error side has been dealt with. `while let event? = reader.Next()` fails with:

```text
error: '.Some(...)' matches a native optional, but the matched value has type 'JsonEvent? ! JsonReadError'
```

Write `reader.Next()!`, so the pattern sees the `JsonEvent?`.
::

::mistake
**Keeping an event's text.**\
The `char8[..]` from `Text()` points into the reader's buffer, which the next `Next()` overwrites. Use it straight away, or copy it into a `String` you own.
::

::mistake
**A reader declared with `let`.**\
Reading advances the reader, so `Next()` needs it mutable. With `let reader = …` the call fails with:

```text
error: cannot call 'Next' on immutable 'reader'
help: declare 'reader' with 'var' to make it mutable
```

::

::mistake
**Passing the source itself.**\
A `Reader` handle copies nothing, so a struct with state does not convert to one. `JsonEventReader::New(allocator, source, JsonLimits::Default())` fails with:

```text
error: argument 2 to 'JsonEventReader::New' has type 'TextSource', but parameter 'source' requires 'Reader'
help: borrow it as '&Reader', bound a generic parameter by 'Reader', or make a handle from a pointer to it
```

Make the handle from the source's address: `@source as Reader`.
::

::mistake
**Handling only the error you expect.**\
The `match` must cover every case of `JsonReadError`. Without the `.Source` arm it fails with:

```text
error: match on 'uint ! JsonReadError' is not exhaustive; missing JsonReadError::Source(_, _)
```

::

## Try it yourself

1. Print each book's year as well: react to a `Number` event that follows a `year` name.
2. Change `TextSource` to serve one byte per read. Does any line of the output change — including the byte offsets?
3. Add a third book that has no title. Does the count still include it?
4. Count how many events the first catalogue produces in all.
