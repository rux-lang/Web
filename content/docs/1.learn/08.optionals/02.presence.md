# Presence

::note
<!-- sync:needs:start -->

**You'll need**: [Optional](/docs/learn/optional), [Variant match](/docs/learn/variant-match), [Guard](/docs/learn/guard)
<!-- sync:needs:end -->

::

An `int?` holds either an `int` or nothing, and the program cannot do sums with it until it knows which. `match` is how you find out. It opens the optional and hands you what is inside — but only in the arm where something is actually there. Everything you learnt about patterns in [Part 7](/docs/learn/patterns) carries over, and when only the presence matters, `== none` and `!= none` answer without opening anything.

## Two arms

The lesson's `ScoreOf` looks up the player wearing a number and returns their score, or `none` when nobody wears it. Opening its answer takes two arms:

```rux
match ScoreOf(players, number) {
    score? => PrintLine("#{} scored {}", number, score),
    none => PrintLine("#{} is not on the team", number)
}
```

| Arm         | Taken when              | Inside the arm                      |
| ----------- | ----------------------- | ----------------------------------- |
| `score? =>` | the optional is present | `score` is the plain `int` it holds |
| `none =>`   | the optional is absent  | there is nothing to bind            |

`score?` is a pattern, not an expression. Read the `?` as "a present …": "a present value, called `score`". The name before the `?` becomes an ordinary `int`, but only inside its own arm — there is no way to reach a `score` in the `none` arm, because there is none to reach.

## Any pattern can be present

The `?` goes after any pattern, so a literal and a [guard](/docs/learn/guard) work as usual:

```rux
func Rating(players: Player[..], number: int) -> char8[..] {
    return match ScoreOf(players, number) {
        0? => "has not scored yet",
        score? if score >= 20 => "is the top scorer",
        _? => "is a regular",
        none => "is not on the team"
    };
}
```

`0?` is "a present 0", and `_?` is "present, whatever it holds". The arms are tried from the top, so the general `_?` arm comes after the specific ones, exactly as in [Exhaustive](/docs/learn/exhaustive).

```mermaid
flowchart LR
    r["`ScoreOf(…)`"] --> q{"Present?"}
    q -- "no" --> n["`none`<br/>is not on the team"]
    q -- "yes" --> z{"Is it 0?"}
    z -- "yes" --> a["`0?`<br/>has not scored yet"]
    z -- "no" --> t{"`score >= 20?`"}
    t -- "yes" --> b["`score? if …`<br/>is the top scorer"]
    t -- "no" --> c["`_?`<br/>is a regular"]
```

| Pattern       | Matches                             |
| ------------- | ----------------------------------- |
| `score?`      | any present value, bound to `score` |
| `0?`          | a present 0                         |
| `_?`          | any present value, bound to nothing |
| `score? if …` | a present value the guard accepts   |
| `none`        | absence                             |

## Only whether it is there

Sometimes the value inside does not matter at all — only whether there is one. Compare the optional with `none`:

```rux
PrintLine("#10 is on the team: {}", ScoreOf(players, 10) != none);
```

`== none` and `!= none` give a plain `bool` and never look inside. An optional also compares with a plain value of its type: `ScoreOf(players, 4) == 0` is `true` only for a present 0.

`is`, which tests a variant's case, is not the tool here: an optional is not a variant, so `is` refuses it. When you want the value as well as the answer, an `if` can open the optional directly — that is the [next lesson](/docs/learn/if-let).

## none cannot be forgotten

A match on an optional must be exhaustive, like a match on a variant — even when it is a statement. The `none` arm is required, because absence is the case the optional exists to make you handle, and so is an arm that takes every present value, such as `score?` or `_?` without a guard.

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/Optionals/Presence). Its comments explain every step.

<!-- sync:program:start -->

```rux [Src/Main.rux]
// An `int?` holds either an `int` or nothing, and the program cannot do sums
// with it until it knows which. `match` is how you find out. It opens the
// optional and hands you what is inside, but only in the arm where something
// is actually there.
//
// There are two arms to write:
//
//     score? => ...    present: `score` is the `int` inside
//     none => ...      absent: there is nothing to bind
//
// `score?` is a pattern, not an expression. Read it as "a present ...". The
// name before the `?` becomes an ordinary `int`, but only inside its arm.
import Io::PrintLine;

struct Player {
    number: int;
    score: int;
}

// The score of the player wearing `number`, or `none` when nobody does.
func ScoreOf(players: Player[..], number: int) -> int? {
    for player in players {
        if player.number == number {
            return player.score;
        }
    }
    return none;
}

func Report(players: Player[..], number: int) {
    match ScoreOf(players, number) {
        score? => PrintLine("#{} scored {}", number, score),
        none => PrintLine("#{} is not on the team", number)
    }
}

// The `?` goes after any pattern, so a literal and a guard work as usual:
// `0?` is a present zero, and `_?` is present with any value. The arms are
// tried from the top, so the general `score?` arm comes after the specific
// ones.
func Rating(players: Player[..], number: int) -> char8[..] {
    return match ScoreOf(players, number) {
        0? => "has not scored yet",
        score? if score >= 20 => "is the top scorer",
        _? => "is a regular",
        none => "is not on the team"
    };
}

func Main() -> int {
    let players = [
        Player { number: 4, score: 0 },
        Player { number: 7, score: 12 },
        Player { number: 10, score: 25 }
    ];

    Report(players, 7);
    Report(players, 9);

    // When only the presence matters, compare with `none`. `== none` and
    // `!= none` give a plain `bool` and never look inside. `is` is not the
    // tool here: `ScoreOf(players, 10) is none` is refused with "'is' does not
    // test an optional". Opening the value inside an `if` is the next lesson.
    PrintLine("#10 is on the team: {}", ScoreOf(players, 10) != none);

    for number in [ 4, 7, 10, 9 ] {
        let rating = Rating(players, number);
        PrintLine("#{} {}", number, rating);
    }

    // Watch out: the `none` arm is required. If you leave it out, the
    // compiler stops with "match on 'int?' is not exhaustive; missing none",
    // because that is the case the optional exists to make you handle.
    return 0;
}
```

## Common mistakes

::mistake
**Leaving out the `none` arm.**\
Without it the compiler stops with:

```text
error: match on 'int?' is not exhaustive; missing none
```

That happens even for a match used as a statement.
::

::mistake
**Only specific present arms.**\
`0?` and a guarded `score? if …` do not cover every present value. Delete the `_?` arm from `Rating` and it fails with:

```text
error: match on 'int?' is not exhaustive; missing _?
```

::

::mistake
**Matching a present value as `.Some(score)`.**\
An optional has no named cases, so `.Some(score) => …` is refused:

```text
error: an optional has no case '.Some'
help: match a present value with 'name?', as in 'value? => ...'
```

A present value is matched by its pattern with a `?` after it, `score?`.
::

::mistake
**Testing an optional with `is`.**\
`ScoreOf(players, 10) is none` fails with:

```text
error: 'is' does not test an optional
help: compare with '== none' or '!= none', or bind the value with 'if let name? = ...'
```

`is` tests the case of a variant. For an optional, compare with `none`.
::

## Try it yourself

1. Delete the `none` arm from `Report` and read the error.
2. Give `Rating` an arm for players who scored exactly 1, reading `"has scored once"`. Where does it go?
3. Write `Bench(players: Player[..], number: int) -> bool` that is `true` for a player with no goals and `false` otherwise — including for numbers nobody wears. Try it once with `match` and once with `==`.
