# Wrapping arithmetic

::note
<!-- sync:needs:start -->

**You'll need**: [Checked arithmetic](/docs/learn/checked-arithmetic), [String literal](/docs/learn/string-literal)
<!-- sync:needs:end -->

::

[Checked arithmetic](/docs/learn/checked-arithmetic) treats overflow as a problem to report. Sometimes it is not a problem but the plan, and the only question is what the result should be. Rux names the two useful answers, at every integer width:

- **Wrapping** — go round, like a car's odometer rolling from 999999 back to 000000. The operators `+%`, `-%` and `*%`.
- **Saturating** — stop at the type's limit and stay there, like a volume knob turned all the way up. The methods `SaturatingAdd`, `SaturatingSub` and `SaturatingMul`.

## Wrapping, on purpose

Plain `+`, `-` and `*` stop the program when a result overflows. The wrapping operators keep the low bits instead:

```rux
let high: uint8 = 250;
let low: uint8 = 5;
let middle: uint8 = 200;
PrintLine("wrapping     250 + 10 = {}", high +% 10);
PrintLine("wrapping     5 - 10   = {}", low -% 10);
PrintLine("wrapping     200 * 2  = {}", middle *% 2);
```

A `uint8` counts 0 to 255 and then starts again, so 250 + 10 is 260 − 256 = `4`, and 5 − 10 goes below zero and comes round to `251`.

The point of the `%` is the **reader**. `a +% b` says "this wraps on purpose", so nobody mistakes the overflow for a bug — or "fixes" it. Hashes, checksums, random number generators and clock counters all want it.

The program ends with one: a tiny multiplicative hash, where overflow is what mixes the bits together:

```rux
let text = "Hello, World!";
var hash: uint32 = 17;
for i in 0..text.length {
    hash = (hash *% 31) +% (text[i] as uint32);
}
```

Before the text is half done, the product outgrows 32 bits and wraps — as it is meant to. The final value, `1494227876`, is a fingerprint of the text: change a letter and the fingerprint changes.

## Saturating, at the limit

`SaturatingAdd`, `SaturatingSub` and `SaturatingMul`, methods on every integer type, stop at the nearest limit instead:

```rux
PrintLine("saturating   250 + 10 = {}", high.SaturatingAdd(10));
PrintLine("saturating   5 - 10   = {}", low.SaturatingSub(10));
PrintLine("saturating   200 * 2  = {}", middle.SaturatingMul(2));
```

They give `255`, `0` and `255`. That suits a quantity with a natural ceiling and floor — a volume, a brightness, a health bar. Adding to the maximum keeps it at the maximum, and taking from zero leaves zero, instead of jumping to the other end of the range.

A signed type saturates at whichever end it ran past:

```rux
let cold: int8 = -100;
let warm: int8 = 100;
```

| Operation on `int8` | Wrapping | Saturating |
| ------------------- | -------- | ---------- |
| −100 − 100          | 56       | −128       |
| 100 + 100           | −56      | 127        |

## Choosing a policy

Every integer operation that might overflow has four ways to go. The plain operators are the default, and stop the program; pick another when it says what you mean:

```mermaid
flowchart LR
    q{"If this result<br/>overflows…"} -- "it is a bug:<br/>stop the program" --> plain["`+ - *`"]
    q -- "the program<br/>should decide" --> checked["`CheckedAdd` …<br/>an optional"]
    q -- "it should go round" --> wrap["`+% -% *%`"]
    q -- "it should stop<br/>at the limit" --> sat["`SaturatingAdd` …"]
```

## Literals take the operand's type

In `high +% 10` and `high.SaturatingAdd(10)` the `10` takes the type of the `uint8` beside it, so the sum is worked out in eight bits. With two plain literals there is no `uint8` to follow: both are `int`, and `250 +% 10` is a plain `260`.

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/Numbers/WrappingArithmetic). Its comments explain every step.

<!-- sync:program:start -->

```rux [Src/Main.rux]
// Sometimes overflow is not a mistake but the plan, and the only question is what it should
// produce. Rux names the two useful answers, at every integer width:
//
//     +%, -%, *%                                     wrap around, like a car's odometer
//     SaturatingAdd, SaturatingSub, SaturatingMul    stop at the type's limit and stay there
//
// Plain `+`, `-` and `*` stop the program when a result overflows. The wrapping operators keep
// the low bits instead, and the point of the `%` is the reader: `a +% b` says "this wraps on
// purpose", so nobody mistakes it for a bug or "fixes" it. Hashes, checksums and clock
// arithmetic all want it.
//
// Saturating suits quantities with a natural ceiling and floor, such as a volume control, a
// brightness or a health bar: adding to the maximum keeps it at the maximum, and taking from zero
// leaves zero, instead of jumping to the other end of the range.
import Io::PrintLine;

func Main() -> int {
    // The same three uint8 sums, answered both ways. Unsuffixed literals take the type of the
    // `uint8` beside them.
    let high: uint8 = 250;
    let low: uint8 = 5;
    let middle: uint8 = 200;
    PrintLine("wrapping     250 + 10 = {}", high +% 10);
    PrintLine("wrapping     5 - 10   = {}", low -% 10);
    PrintLine("wrapping     200 * 2  = {}", middle *% 2);
    PrintLine("saturating   250 + 10 = {}", high.SaturatingAdd(10));
    PrintLine("saturating   5 - 10   = {}", low.SaturatingSub(10));
    PrintLine("saturating   200 * 2  = {}", middle.SaturatingMul(2));
    PrintLine("");

    // A signed type saturates at whichever end it ran past.
    let cold: int8 = -100;
    let warm: int8 = 100;
    PrintLine("int8  -100 - 100  wraps to {}, saturates at {}", cold -% 100,
        cold.SaturatingSub(100));
    PrintLine("int8   100 + 100  wraps to {}, saturates at {}", warm +% 100,
        warm.SaturatingAdd(100));
    PrintLine("");

    // Wrapping on purpose: a tiny multiplicative hash, where overflow mixes the bits.
    let text = "Hello, World!";
    var hash: uint32 = 17;
    for i in 0..text.length {
        hash = (hash *% 31) +% (text[i] as uint32);
    }
    PrintLine("hash of {}  {}", text, hash);
    return 0;
}
```

## Common mistakes

::mistake
**Wrapping two plain literals.**\
`250 +% 10` is worked out at `int`, where nothing wraps, and gives `260`. Give one operand the type you mean, as the program does with `high`, `low` and `middle`.
::

::mistake
**Mixing a character into the hash.**\
`text[i]` is a `char8`, not a number, so `(hash *% 31) +% text[i]` fails with:

```text
error: operator '+%' requires integer operands, but found 'uint32' and 'char8'
```

Convert it first, as the program does: `text[i] as uint32`.
::

::mistake
**Expecting your own limit.**\
Saturation stops at the **type's** limits, not at the range your program has in mind. A `uint8` volume that should stop at 100 still goes up to 255 under `SaturatingAdd`. Use it for the floor at zero, and compare with your own maximum before adding.
::

::mistake
**Wrapping where you meant modulo.**\
Wrapping goes round at the width of the type — 256 for a `uint8`, not 24 or 60. For clock hours, use `%`: `(hours + 5) % 24`.
::

## Try it yourself

1. A health bar is a `uint8`. Take 30 damage from 20 health with `-%` and then with `SaturatingSub`. Which result would a game want?
2. Change the hash to start at 0 instead of 17, and hash `"ab"` and `"ba"`. Do they still differ?
3. Find the first `n` for which `*%` and `SaturatingMul` disagree on `n * n` in a `uint8`.
