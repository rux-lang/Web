# File

<!-- sync:needs:end -->

A file is where a program's data outlives the program. Writing one and reading it back takes only a handful of calls, but every one of them can fail for reasons outside the program: the disk is full, the name is taken, permission is refused, the file is not there. So every step declares `! IoError`, and this lesson accounts for each call. Most of them end in [`!`](/docs/learn/propagate), which passes the error on; two handle it on the spot.

`Main` cannot fail, so the steps live in `WriteAndRead`, declared `-> !IoError`, and `Main` turns any error that reaches it into exit status 1, as in [Exit status](/docs/learn/exit-status):

```rux
func Main() -> int {
    WriteAndRead() !! return 1;
    return 0;
}
```

Turning the text into a path, with `OsString::FromText`, cannot fail, so it needs no `!`.

## Opening a file

`File::Open` takes an allocator, a [path](/docs/learn/path) and an `OpenOptions` saying what you mean to do. It returns a `File ! IoError`, and the `!` keeps the `File`:

```rux
var writing = File::Open(allocator, path, OpenOptions::Writing())!;
```

The options decide both what the handle may do and what happens to the file itself:

| Options                    | The handle may   | If the file is missing | If it exists             |
| -------------------------- | ---------------- | ---------------------- | ------------------------ |
| `OpenOptions::Reading()`   | read             | fails with `NotFound`  | opened as it is          |
| `OpenOptions::Writing()`   | write            | created                | emptied first            |
| `OpenOptions::Appending()` | write at the end | created                | kept; writes go after it |

The open file is a `File`, and it must be `var`: writing, reading and closing all change it.

## Writing, and closing

```rux
WriteAll(&var writing, "first line\nsecond line\n")!;
// Closing can report a failure that was delayed until now, so it can fail too.
writing.Close()!;
```

`File::Write` is a single attempt: it may move fewer bytes than asked, and the count it returns says how many. `Io::WriteAll` keeps calling `Write` until every byte is out, which is almost always what you want. It writes through the file, so the call lends it for writing with [`&var writing`](/docs/learn/mutable-reference).

`Close` can fail as well. The system may have delayed reporting a failed write until now, so a close that is not checked can lose an error that happened earlier. A file that is never closed is closed by its destructor when it goes out of scope, but the destructor has nowhere to report a failure, so it discards it.

## Reading until the end

`File::Read` fills as much of a buffer as it can in one attempt and returns how many bytes it put there. The lesson's buffer is only eight bytes, so the 23 bytes of the file take several reads:

```rux
var buffer: char8[8];
var reads = 0;
var total: uint = 0;
loop {
    let filled = reading.Read(buffer[..8]) catch {
        error if error.IsEnd() => break,
        error => throw error
    };
    Print("{}", buffer[..filled]);
    reads += 1;
    total += filled;
}
```

The surprise is how the end arrives. It is not a count of zero: it is an **error**, an `IoError` whose `IsEnd()` is true. So the read is handled with [`catch`](/docs/learn/catch) and two arms, separated by a [guard](/docs/learn/guard): the end of the file breaks out of the loop, and any other error is a real failure, passed on with `throw error`. The arms must cover every `IoError`, which is why the last one binds them all.

```mermaid
flowchart LR
    r["`reading.Read(buffer[..8])`"] --> q{"what came back?"}
    q -- "a count" --> use["print `buffer[..filled]`,<br/>add it up, read again"]
    use --> r
    q -- "an `IoError`,<br/>`IsEnd()` `true`" --> done["break: the file is read"]
    q -- "any other<br/>`IoError`" --> fail["`throw error`:<br/>`Main` returns `1`"]
```

Only the first `filled` bytes are new. The rest of the buffer still holds whatever the previous read left there, which is why the loop prints `buffer[..filled]`, never the whole buffer.

| Read | Bytes | Buffer holds                             |
| ---- | ----- | ---------------------------------------- |
| 1    | 8     | `first li`                               |
| 2    | 8     | `ne`, a newline, `secon`                 |
| 3    | 7     | `d line` and a newline, plus a stale `n` |
| 4    | —     | the end of the file: `break`             |

## Handling an error instead of passing it on

Not every error should end the program. After `DeleteFile` the file is gone, so opening it again must fail, and here that is the expected outcome. Without a `!`, `File::Open` hands back its whole [outcome](/docs/learn/outcome), a `File ! IoError`, and a `match` [takes it apart by side](/docs/lang/errors/fallible-values#matching-by-side):

```rux
match File::Open(allocator, path, OpenOptions::Reading()) {
    _: File => PrintLine("still there?"),
    error: IoError if error.kind == IoErrorKind::NotFound => PrintLine("deleted, as expected"),
    error: IoError => throw error
}
```

A typed pattern picks the side: `_: File` is the success, and the two `IoError` arms share out the errors. `error.kind` is an `IoErrorKind`, an enum that names what went wrong in the same way on every platform: `NotFound`, `PermissionDenied`, `AlreadyExists`, `StorageFull` and more. The guard picks out the one error this code expects; anything else is still thrown on to the caller. A file that did open would be closed by its destructor, since nothing keeps it.

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/Files/File). Its comments explain every step.

<!-- sync:program:start -->

```rux [Src/Main.rux]
// Writing a text file and reading it back, with every failure accounted for.
//
// Each step can fail for reasons outside the program: the disk is full, the name is taken,
// permission is refused. So each one declares `! IoError`, and every call to one is marked with
// `!`, which passes an error on. `Main` cannot fail, so the steps live in `WriteAndRead`, which
// declares `-> !IoError` too, and `Main` turns any error it passes on into exit status 1.
//
// Two surprises are worth knowing before the code.
//
// - `File::Write` and `File::Read` are single attempts. Each may move fewer bytes than asked,
//   and the count it returns says how many. `Io::WriteAll` keeps calling `Write` until every
//   byte is out, and a reader loops in the same way.
// - The end of a file is not a count of zero. It is an error, an `IoError` whose `IsEnd()` is
//   true, so the read loop's `catch` treats it as "done" and throws any other error on.
//
// The file lives in this package's `Bin/` folder, and the program deletes it at the end.
import Allocator::SystemAllocator;
import FileSystem::{ DeleteFile, File, OpenOptions };
import Io::{ IoError, IoErrorKind, Print, PrintLine, WriteAll };
import Path::{ OsString, Path };

func WriteAndRead() -> !IoError {
    let allocator = SystemAllocator::New();

    var holder = OsString::FromText(allocator, "Bin/notes.txt");
    let path = Path::FromView(holder.View());

    // `Writing` creates the file, or empties it if it already exists.
    var writing = File::Open(allocator, path, OpenOptions::Writing())!;
    WriteAll(&var writing, "first line\nsecond line\n")!;
    // Closing can report a failure that was delayed until now, so it can fail too.
    writing.Close()!;
    PrintLine("wrote {}", path);

    // `Reading` requires the file to exist. A small buffer makes the loop take several reads.
    var reading = File::Open(allocator, path, OpenOptions::Reading())!;
    var buffer: char8[8];
    var reads = 0;
    var total: uint = 0;
    loop {
        let filled = reading.Read(buffer[..8]) catch {
            error if error.IsEnd() => break,
            error => throw error
        };
        // Only the first `filled` bytes are new. The rest of the buffer is left over.
        Print("{}", buffer[..filled]);
        reads += 1;
        total += filled;
    }
    reading.Close()!;
    PrintLine("read {} bytes in {} reads", total, reads);

    DeleteFile(allocator, path)!;

    // Handling an error instead of passing it on: the file is gone, so opening it fails. A
    // `match` takes the outcome apart: the success is a `File`, and a guarded arm picks out the
    // expected kind of error, while any other error is thrown on to the caller.
    match File::Open(allocator, path, OpenOptions::Reading()) {
        _: File => PrintLine("still there?"),
        error: IoError if error.kind == IoErrorKind::NotFound => PrintLine("deleted, as expected"),
        error: IoError => throw error
    }
}

func Main() -> int {
    WriteAndRead() !! return 1;
    return 0;
}
```

Besides `Io`, its `Rux.toml` lists `Allocator`, `FileSystem` and `Path` under `[Dependencies]`.

## Common mistakes

::mistake
**Leaving `Close` unchecked.**\
`writing.Close();` fails with:

```text
error: 'Close' can fail with 'IoError', and the result is not used
help: pass the error on with '!', ignore it with '!!;', or handle it with 'catch { ... }'
```

Close can report a failure that was delayed until then, so check it like any other step.
::

::mistake
**Treating the end of the file as an error.**\
Replace the `catch` with a plain `!` — `let filled = reading.Read(buffer[..8])!;` — and the program compiles, prints the file, and then ends with exit status 1 and no message, because the end arrives as an `IoError` and `!` passes it on. It never reaches `DeleteFile`, so `Bin/notes.txt` is left behind. Catch the end with `IsEnd()`.
::

::mistake
**A `catch` that misses an error.**\
Drop the last arm, keeping only `error if error.IsEnd() => break`, and the read fails with:

```text
error: 'catch' arms do not cover every error of type 'IoError'
help: add a '_' arm, or bind the whole error, as in 'e => ...'
```

A guarded arm covers only the errors its guard accepts. End with an arm that takes the rest. The `match` at the end follows the same rule: leave out its last arm and it fails with `match on 'File ! IoError' is not exhaustive; missing _: IoError`.
::

::mistake
**Printing the whole buffer.**\
`Print("{}", buffer[..])` prints the stale bytes too: the output gains a stray `n` after `second line`, left over from the second read. Print `buffer[..filled]`.
::

::mistake
**Lending the file without `&var`.**\
`WriteAll(writing, …)` fails with:

```text
error: 'WriteAll' writes its argument 'writing', so the loan must be written
help: write '&var writing'
```

A call that writes through a value says so where it is made.
::

::mistake
**Opening a file with `let`.**\
`let writing = File::Open(…)!;` makes the later calls fail:

```text
error: '&var' lends for writing, but this place is immutable
error: cannot call 'Close' on immutable 'writing'
```

An open file changes as you use it; declare it `var`.
::

::mistake
**Passing text as the path.**\
`File::Open(allocator, "Bin/notes.txt", …)` fails with:

```text
error: argument 2 to 'File::Open' has type 'char8[..]', but parameter 'path' requires 'Path'
```

Convert the text with `OsString::FromText` and take a `Path` of it, as at the top of `WriteAndRead`.
::

## Try it yourself

1. Change the buffer to 4 bytes, and then to 64. How many reads does the file take each time?
2. Open the file a second time with `OpenOptions::Appending()`, add a third line, and read the whole file back.
3. Open a file that does not exist with `OpenOptions::Reading()` and let a plain `!` pass the error on. Check the exit status with `echo $?`.
4. Count the lines as you read, by counting the newline characters in each `buffer[..filled]`.
