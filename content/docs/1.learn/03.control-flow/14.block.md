# Block

::note
<!-- sync:needs:start -->

**You'll need**: [Ternary](/docs/learn/ternary), [Match expression](/docs/learn/match-expression)
<!-- sync:needs:end -->

::

A block, `{ ... }`, has followed every `if`, `while` and `for` so far. It can also stand on its own, and then it does two jobs. It is a **scope**: the names declared inside it end at its `}`. And it is a **value**: like an `if` branch in [Ternary](/docs/learn/ternary) or an arm in [Match expression](/docs/learn/match-expression), it can yield the expression it ends with. Put together, the two jobs let a few working names exist just long enough to compute one value, and no longer.

## A scope of its own

A block written where a statement goes opens a scope. A name declared inside it exists only between its braces:

```rux
var total = 0;
{
    let step = 5;
    total += step * 2;
    PrintLine("inside: step {}, total {}", step, total);
}
PrintLine("after:  total {}", total);
```

```
inside: step 5, total 10
after:  total 10
```

`step` is a working value: it is needed for one calculation, and after the `}` it is gone. `total` was declared before the block, so it lives on, and the change the block made to it survives, just as a change made in an `if` block does. Naming `step` after the block is an error, because there is no `step` there any more.

That is the same rule [If](/docs/learn/if) showed for the block of an `if`. A plain block simply applies it without a condition: it marks off a stretch of the program whose names do not leak into the rest.

## A block as a value

Written where a value is expected, a block yields its **last expression**, provided it is written **without** a `;`:

```rux
let area = {
    let width = 3;
    let height = 4;
    width * height
};
```

The statements run in order, then `width * height` becomes the value of the whole block, and `area` is 12. `width` and `height` end with the block; only the area they produced is kept. The `;` after the closing brace belongs to the `let` statement, as it does after an `if` value or a `match` expression.

```mermaid
flowchart LR
    open(["`{`"]) --> w["`let width = 3;`"]
    w --> h["`let height = 4;`"]
    h --> last["`width * height`<br/>no `;`: the value"]
    last --> close(["`}`: `width` and<br/>`height` end"])
    close --> area["`area` = 12"]
```

The `;` decides what the block yields:

| The block ends with          | It yields             |
| ---------------------------- | --------------------- |
| `width * height` (no `;`)    | that value, an `int`  |
| `width * height;` (with `;`) | `()`, the empty value |
| nothing after its last `;`   | `()`, the empty value |

So a block that must produce a value ends with an expression and no `;`, and a block that stands as a statement does the opposite: every line inside it ends with a `;`, because its value would have nowhere to go.

Like any value, a block can be passed straight to a call or stand inside arithmetic:

```rux
PrintLine("{}", { let a = 6; a * 7 });
```

That is legal, but a block value reads best on its own line, initialising a `let`. When it grows past a few lines, the work deserves a name of its own: a function, the subject of [Part 4](/docs/learn/functions).

## A block in a condition

After `if`, `while`, `match` and `for … in`, a `{` opens the body. So a block used as the condition itself has to be put in parentheses, or the compiler would take its `{` for the start of the body:

```rux
var side = 1;
while ({ let square = side * side; square < area }) {
    side += 1;
}
```

The condition is worked out afresh before every pass, block and all: each time, `square` is computed from the current `side`, compared with `area`, and gone again. The loop stops at the first side whose square holds at least `area` cells: 1, 4 and 9 are too small, 16 is enough, so `side` ends at 4.

| Where the block stands                                   | Write     |
| -------------------------------------------------------- | --------- |
| initialising a `let`, as an argument, inside arithmetic  | `{ … }`   |
| the condition of `if` or `while`, the subject of `match` | `({ … })` |
| the range of `for … in`                                  | `({ … })` |
| on its own, as a statement                               | `{ … }`   |

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/ControlFlow/Block). Its comments explain every step.

<!-- sync:program:start -->

```rux [Src/Main.rux]
// A block, `{ ... }`, has followed every `if`, `while` and `for` so far. It can also stand on its
// own, and then it does two jobs.
//
// It is a scope of its own: a name declared inside it ends at its `}`, so a working value lives
// only as long as the work that needs it. Using the name after the block is an error:
//
//     { let note = "inside"; }
//     PrintLine("{}", note);
//         error: name 'note' is not defined in this scope
//
// And it is a value, like an `if` value or a `match` arm: a block whose last expression is
// written without a `;` yields that expression. With a `;` the last expression is a statement
// like the others, and the block yields `()`, the empty value:
//
//     let area: int = { let width = 3; let height = 4; width * height; };
//         error: this block yields '()' because of the ';'
import Io::PrintLine;

func Main() -> int {
    // A scope of its own: `step` exists only between the braces, while `total` lives on.
    var total = 0;
    {
        let step = 5;
        total += step * 2;
        PrintLine("inside: step {}, total {}", step, total);
    }
    PrintLine("after:  total {}", total);

    // A block as a value. `width` and `height` end with the block, and only the area they
    // produced is kept.
    let area = {
        let width = 3;
        let height = 4;
        width * height
    };
    PrintLine("area {}", area);

    // A block in an `if` or `while` condition must be put in parentheses, or its `{` would be
    // read as the start of the body:
    //
    //     if { let limit = 10; area > limit } { ... }
    //         error: expected an expression after 'if' before '{'
    var side = 1;
    while ({ let square = side * side; square < area }) {
        side += 1;
    }
    PrintLine("a square of side {} holds at least {} cells", side, area);
    return 0;
}
```

## Common mistakes

::mistake
**Using a block's name after the block.**\
`{ let note = "inside"; }` followed by `PrintLine("{}", note);` fails with:

```text
error: name 'note' is not defined in this scope
```

A name declared inside a block ends at its `}`. Declare it before the block if the rest of the program needs it.
::

::mistake
**Ending a value block with `;`.**\
`let area: int = { let width = 3; let height = 4; width * height; };` fails with:

```text
error: this block yields '()' because of the ';'
help: remove the ';' to yield the last expression
```

The last expression is the block's value only when no `;` follows it.
::

::mistake
**Leaving a value in a statement block.**\
A block on its own, `{ let width = 3; width * 2 }`, has nowhere to put its value:

```text
error: this block yields a value of type 'int' that is not used
help: add ';' or use the value
```

Either end the line with `;`, or give the value a home: `let doubled = { … };`.
::

::mistake
**A block in a condition without parentheses.**\
`if { let limit = 10; area > limit } { … }` fails with:

```text
error: expected an expression after 'if' before '{'
```

The `{` after `if` opens the body. Write the condition as `({ … })`.
::

::mistake
**Forgetting the `;` after the closing brace.**\
A block that initialises a `let` is part of the `let` statement, which ends with `};`. Leave out the `;` and the compiler stops at the next statement:

```text
error: expected ';' after the binding declaration before 'PrintLine'
```

::

## Try it yourself

1. Print `step` after the first block and read the error. Then move `let step = 5;` above the block and run it again.
2. Add `let depth = 2;` to the area block and make it yield a volume instead.
3. Write the `while` condition without a block, as `side * side < area`. Which version reads better here, and when would the block be worth it?
4. Put a `;` after `width * height` and read the error.
5. Pass a block straight to a call: `PrintLine("{}", { let a = 6; a * 7 });`.
