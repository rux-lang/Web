# Part 18: Algorithms

From here on the course tours the standard packages, and it starts with the one every program reaches for sooner or later. The `Algorithms` package is a set of generic functions over slices: sort them, search them, find their extremes, fold them into one answer. Because every function takes a slice, one function serves an array of any length, part of an array, or the contents of a collection — and none of them ever allocates memory. The last two lessons go a step further: lazy adaptors, which change any iterator item by item, and scans, which keep every step of a fold.

The package groups its functions into modules by the job they do, and each lesson imports from the one it needs: `Algorithms::Sorting` for the sorts and the searches of sorted data, `Algorithms::Query` for linear searches and extremes, `Algorithms::Numeric` for folds and scans, and `Algorithms::Adaptors` for the adaptors.

## What you will learn

- Sorting a slice in place through a writable view, by the element's own `<` or by an order function of yours.
- Searching any slice from the front, and handling the `none` that "not found" is.
- Searching sorted data in logarithmic time, and the promise that comes with it.
- The smaller of two values, and the position of the smallest in a slice — which may not exist.
- Collapsing a slice into one answer with `Fold` and a step function.
- Chaining lazy adaptors such as `Map`, `Filter` and `Take` over any iterator, computing each item only when it is asked for.
- Running totals and other scans, counting sequences with `Iota`, and a `Midpoint` that cannot overflow.

## Which function?

| From a slice, you want…                | Use                                            | Lesson |
| -------------------------------------- | ---------------------------------------------- | ------ |
| to put it in order                     | `Sort`, `SortDescending`, `SortBy`             | 18.1   |
| to find a value, not sorted            | `IndexOf`, `LastIndexOf`, `Contains`           | 18.2   |
| to find a value, sorted                | `BinarySearch`, `LowerBound`, `UpperBound`     | 18.3   |
| its smallest or largest element        | `MinIndex`, `MaxIndex`                         | 18.4   |
| one answer from every element          | `Fold`, `FoldRight`                            | 18.5   |
| a changed sequence, item by item       | `Map`, `Filter`, `Take`, …                     | 18.6   |
| the running answer after every element | `PartialSum`, `InclusiveScan`, `ExclusiveScan` | 18.7   |

The functions share a few habits, and knowing them makes the rest of the package predictable:

| Habit                                               | Functions in this part                                                           |
| --------------------------------------------------- | -------------------------------------------------------------------------------- |
| Take a writable view, `var T[..]`, and change it    | `Sort`, `SortDescending`, `SortBy`, the scans, `Iota`                            |
| Answer with `uint?`, `none` when there is no answer | `IndexOf`, `LastIndexOf`, `BinarySearch`, `MinIndex`, `MaxIndex`                 |
| Always have an answer                               | `Contains`, `LowerBound`, `UpperBound`, `Min`, `Max`, `Fold`, `Midpoint`         |
| Take a named function for the part that varies      | `SortBy`, `Fold`, `FoldRight`, `InclusiveScan`, `ExclusiveScan`, `Map`, `Filter` |

## Before you start

The lessons lean on [Slice](/docs/learn/slice) and [Writable slice](/docs/learn/writable-slice) from Part 5, [Callback](/docs/learn/callback) and [Generic](/docs/learn/generic) from Part 4, [Presence](/docs/learn/presence) and [Coalesce](/docs/learn/coalesce) from [Part 8: Optionals](/docs/learn/optionals), [Comparable](/docs/learn/comparable), [Iterator](/docs/learn/iterator) and [Iterable](/docs/learn/iterable) from Part 12, and [Wrapping arithmetic](/docs/learn/wrapping-arithmetic) from Part 16. Each lesson's package is in the Examples repository's `Algorithms/` folder:

```sh
cd Examples/Algorithms/Sort
rux run
```

## After this part

The checkpoint project [Statistics](/docs/learn/statistics) puts the whole part to work: it sorts, finds extremes and folds slices of numbers into a count, a mean, a variance and a median, including the awkward cases of one value and none. Then [Part 19: Files](/docs/learn/files) leaves memory behind and reads and writes the disk.
