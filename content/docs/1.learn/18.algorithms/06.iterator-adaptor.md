# Iterator adaptors

::note
<!-- sync:needs:start -->

**You'll need**: [Iterator](/docs/learn/iterator), [Iterable](/docs/learn/iterable), [Callback](/docs/learn/callback)
<!-- sync:needs:end -->

::

The [Iterator](/docs/learn/iterator) lesson built a type whose `Next` hands out one item at a time, and `for` walked it. Very often the walk you want is a small change to one you already have: the same scores, curved; only the passes; the second page of results; each item with its position. Writing a new iterator type for every such change would be tedious.

An **adaptor** is an iterator that wraps another one and changes what comes out. Core provides seven, and because each adaptor is an iterator too, they nest:

```rux
import Core::{ Chain, Enumerate, Filter, Indexed, Map, Skip, Take, Walk, Zip };
```

## Cursors and `Walk`

An adaptor takes anything whose `Next` returns `T?`. Core calls that shape a `Cursor<T>`, and these all have it:

- a container's iterator, such as a [vector](/docs/learn/vector)'s `Iterate()`;
- an iterator type of your own, like the program's `Counter`;
- another adaptor.

A slice does not: `for` walks a slice directly, but it has no `Next`. `Walk` wraps one in a cursor, so a chain over a slice starts there:

```rux
for score in Map(Walk(scores[..]), Curve) {
    Print(" {}", score);
}
```

## The seven adaptors

| Adaptor           | Hands out                                              | Item type        |
| ----------------- | ------------------------------------------------------ | ---------------- |
| `Map(c, f)`       | `f(item)` for each item                                | what `f` returns |
| `Filter(c, keep)` | the items for which `keep(item)` is `true`             | same as `c`      |
| `Take(c, n)`      | the first `n` items, then stops                        | same as `c`      |
| `Skip(c, n)`      | everything after the first `n` items                   | same as `c`      |
| `Enumerate(c)`    | each item with its position, counting from 0           | `Indexed<T>`     |
| `Zip(a, b)`       | an item from each, side by side, until either runs out | `Pair<A, B>`     |
| `Chain(a, b)`     | every item of `a`, then every item of `b`              | same as both     |

`Map` and `Filter` take a named function, as a [callback](/docs/learn/callback). `Indexed<T>` has the fields `index` and `item`; `Pair<A, B>` has `first` and `second`.

No type arguments are written anywhere. Each adaptor works its item type out from the cursor it wraps, and from the function's return type for `Map`.

## Reading a chain

A chain reads from the inside out. The innermost call is the source; each call around it is one more step:

```rux
for score in Filter(Map(Walk(scores[..]), Curve), Passed) {
    Print(" {}", score);
}
```

Walk the scores, curve each, keep the passes. The order matters: filtering before curving would test the raw scores, and fail the 45 and 49 that the curve lifts to 50 and 54. In the same way, `Enumerate` before `Filter` keeps the original positions — the program reports the failures at 1, 3 and 5 — where `Enumerate` after `Filter` would number the survivors 0, 1, 2.

## Lazy

Building a chain computes nothing. When `for` asks the outermost adaptor for an item, it asks the one inside it, and so on down to the source, one item at a time:

```mermaid
flowchart TD
    f["`for` wants an item"] --> t["`Take`: fewer than 3 handed out?<br/>Then ask `Filter`"]
    t --> fi["`Filter`: ask `Map` again<br/>until an item is even"]
    fi --> m["`Map`: ask `Counter`,<br/>square the answer"]
    m --> c["`Counter`: hand out<br/>the next number"]
```

So no list of intermediate results is ever built, and a chain can draw on a source that never ends. The program's `Counter` counts up for ever, and prints each time it is asked:

```rux
for value in Take(Filter(Map(Counter { next: 1 }, Square), IsEven), 3) {
    Print(" -> {}", value);
}
```

The output shows each number asked for just before the result it leads to, and the asking stops at 6: after the third even square, `Take` stops asking.

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/Algorithms/IteratorAdaptor). Its comments explain every step.

<!-- sync:program:start -->

```rux [Src/Main.rux]
// An iterator hands out one item each time its `Next` is called. An adaptor is an iterator that
// wraps another one and changes what comes out: `Map` passes each item through a function,
// `Filter` drops the items that fail a test, `Take` stops after a number of them, and so on.
// Core provides seven, and because each is an iterator itself they nest, each one wrapping the
// next:
//
//     Take(Filter(Map(source, Square), IsEven), 3)
//
// Read that from the inside out: square each item, keep the even squares, stop after three.
//
// Adaptors are lazy. Building the chain computes nothing; each adaptor asks the one inside it
// for an item only when it is itself asked for one. So no list of results is ever built, and a
// chain can even draw from a source that never ends, as long as something stops asking.
//
// An adaptor takes anything whose `Next` returns `T?` — Core calls that a `Cursor<T>`. That is
// a container's iterator, another adaptor, or a slice turned into one by `Walk`.
import Core::{ Chain, Enumerate, Filter, Indexed, Map, Skip, Take, Walk, Zip };
import Io::{ Print, PrintLine };

// Counts up from a number, for ever, and says each time it is asked.
struct Counter {
    next: int32;
}

extend Counter {
    func Next(self: &var Counter) -> int32? {
        Print(" (asked: {})", self.next);
        self.next = self.next + 1;
        return self.next - 1;
    }
}

func Curve(score: int32) -> int32 {
    return score + 5;
}

func Passed(score: int32) -> bool {
    return score >= 50;
}

func Failed(entry: Indexed<int32>) -> bool {
    return entry.item < 50;
}

func Square(value: int32) -> int32 {
    return value * value;
}

func IsEven(value: int32) -> bool {
    return value % 2 == 0;
}

func Main() -> int {
    let names: char8[..][6] = ["ada", "ben", "cai", "dee", "eve", "fay"];
    let scores: int32[6] = [72, 45, 90, 38, 66, 49];

    // A slice is not an iterator; `Walk` makes one. `Map` then hands out each score curved.
    // Leave out the `Walk` and the slice fails the bound:
    //
    //     for score in Map(scores[..], Curve) { ... }
    //         error: type argument 'int32[..]' does not satisfy interface bound 'Cursor' on type
    //                parameter 'I'
    Print("curved:   ");
    for score in Map(Walk(scores[..]), Curve) {
        Print(" {}", score);
    }
    PrintLine();

    // Adaptors nest: curve every score, then keep the passes.
    Print("passed:   ");
    for score in Filter(Map(Walk(scores[..]), Curve), Passed) {
        Print(" {}", score);
    }
    PrintLine();

    // `Skip` and `Take` cut out a window: the second page of two.
    Print("page 2:   ");
    for score in Take(Skip(Walk(scores[..]), 2), 2) {
        Print(" {}", score);
    }
    PrintLine();

    // `Enumerate` pairs each item with its position, as an `Indexed<int32>`, so a filter after
    // it still knows where each item stood.
    Print("failed at:");
    for entry in Filter(Enumerate(Walk(scores[..])), Failed) {
        Print(" {}", entry.index);
    }
    PrintLine();

    // `Zip` walks two sources side by side, as a `Pair`, and stops when either runs out.
    for pair in Take(Zip(Walk(names[..]), Walk(scores[..])), 3) {
        PrintLine("{}  {}", pair.first, pair.second);
    }

    // `Chain` reads one source to its end, then the other.
    let late: int32[2] = [81, 57];
    Print("all:      ");
    for score in Chain(Walk(scores[..]), Walk(late[..])) {
        Print(" {}", score);
    }
    PrintLine();

    // Laziness: the counter never ends, yet it is asked for only six numbers, one at a time as
    // each result is wanted, because `Take` stops asking once it has handed out three.
    Print("lazy:     ");
    for value in Take(Filter(Map(Counter { next: 1 }, Square), IsEven), 3) {
        Print(" -> {}", value);
    }
    PrintLine();
    return 0;
}
```

## Common mistakes

::mistake
**Passing a slice straight in.**\
`Map(scores[..], Curve)` fails with:

```text
error: type argument 'int32[..]' does not satisfy interface bound 'Cursor' on type parameter 'I'
```

A slice has no `Next`. Wrap it: `Map(Walk(scores[..]), Curve)`.
::

::mistake
**A function of the wrong shape.**\
`Filter` wants a test, `func(T) -> bool`. Give it `Curve`, which returns `int32`, and the call fails — but the message points at the first argument:

```text
error: argument 1 to 'Filter' has type 'SliceCursor<int32>', but parameter 'source' requires 'I'
```

When an adaptor call is refused like this, check the function's parameter and return types against the table above.
::

::mistake
**Expecting the cursor you passed in to move.**\
An adaptor works on its own copy. After `for score in Take(cursor, 2) { … }`, `cursor.Next()` still returns the first score, `72`. Make the cursor inside the call, or move it in with `<-cursor`, so nobody is tempted to use it afterwards.
::

::mistake
**An endless source with nothing to stop it.**\
`for value in Map(Counter { next: 1 }, Square) { … }` never ends: nothing in the chain ever says `none`. Over an endless source, put a `Take` in the chain, or `break` out of the loop.
::

## Try it yourself

1. Print the names of the students who passed after the curve: `Zip` the names with the curved scores, then `Filter` the pairs.
2. Print the scores with a rank, starting from 1, using `Enumerate` and `entry.index + 1`.
3. `Chain` `scores` and `late`, `Skip` the first five and `Take` two. Predict the output before you run it.
4. Write a cursor `Repeat` that hands out the same value for ever, and `Zip` it with the scores.
