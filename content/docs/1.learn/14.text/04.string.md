# String

::note
<!-- sync:needs:start -->

**You'll need**: [String view](/docs/learn/string-view), [Exit status](/docs/learn/exit-status), [Destructor](/docs/learn/destructor), [Interface value](/docs/learn/interface-value)
<!-- sync:needs:end -->

A [view](/docs/learn/string-view) borrows, so it can never outlive the bytes it looks at. Text that a function builds and hands back, or that must be kept after its source is gone, needs an **owner**. That is `String`: it keeps its own copy of the bytes, in memory it asked an allocator for, and gives that memory back in its [destructor](/docs/learn/destructor) when the value's life ends.

## Borrowed or owned

|                  | `StringView`                           | `String`                               |
| ---------------- | -------------------------------------- | -------------------------------------- |
| Holds            | a view of someone else's bytes         | its own copy of the bytes              |
| Making one       | free: no copy, no allocation           | copies the bytes into allocated memory |
| From bytes       | `FromBytes` answers `none` if not text | `FromBytes` fails with `TextError`     |
| Copied with `=`? | yes: it is a small borrowed view       | no: `=` gives it away; call `Clone`    |
| Lives            | no longer than the bytes it views      | as long as the `String` itself         |
| Cleans up        | nothing to clean up                    | its destructor frees the memory        |

## Where the memory comes from

A `String` needs an allocator to ask for memory. `Spell` makes the system's allocator with its named constructor and passes it on, and the `String` keeps it as an `Allocator`:

```rux
let allocator = SystemAllocator::New();
```

The allocator itself is the subject of the [Memory](/docs/learn/memory) part. For now it is simply where a String's bytes come from.

## Returning text a function made

`Reversed` builds its letters in a local array, which is gone once the function returns. A view of that array would be left pointing at nothing, so the function returns a `String` that owns a copy:

```rux
func Reversed(allocator: Allocator, word: char8[..]) -> String ! TextError {
    var letters: char8[16];
    for i in 0..word.length {
        letters[i] = word[word.length - 1 - i];
    }
    return String::FromBytes(allocator, letters[..word.length]);
}
```

`FromBytes` checks that the bytes are text before copying them, so it is [fallible](/docs/learn/fallible): it returns `String ! TextError`, a `String` or the `TextError` that says why there is none. `Reversed` has the same result type, so it can return the call as it is, error and all:

| `TextError` case | When                                                       |
| ---------------- | ---------------------------------------------------------- |
| `InvalidUtf8`    | `FromBytes` was given bytes that are not text              |
| `NotABoundary`   | a position fell inside a character rather than between two |

Running out of memory is not on the list. A `String` that cannot get its storage ends the program, as every allocation in a string or a collection does.

The UTF-8 check is not a formality here. Reversed byte by byte, `né` puts the two bytes of `é` in the wrong order, and `FromBytes` fails with `TextError::InvalidUtf8` rather than make a `String` that is not text.

The work happens in `Spell`, a function that returns nothing on success, `-> !TextError`. A postfix [`!`](/docs/learn/propagate) after each call that can fail keeps the success and passes any error on:

```rux
var word = Reversed(allocator, "stressed")!;
PrintLine("word   {}, {} bytes", word.View(), word.Length());
```

A `String` is printed through its view, `word.View()`.

`Main` cannot fail (it is always `func Main() -> int`), so it turns an error from `Spell` into the [exit status](/docs/learn/exit-status):

```rux
func Main() -> int {
    Spell() !! return 1;
    return 0;
}
```

## Copying with Clone

A `String` owns its memory, so `=` never copies one: two owners would release the same bytes. `let copy = saved;` [gives the one value away](/docs/learn/give-away) instead, and `saved` cannot be used after it. Copying is always the visible call to `Clone`, which makes an independent copy with storage of its own:

```rux
let saved = word.Clone();
word.ReplaceWith(Reversed(allocator, "drawer")!);
```

`ReplaceWith` gives `word` new text and frees its old bytes. `saved` has its own copy, so it is untouched: `word` is now `reward`, `saved` is still `desserts`. The `!` belongs to `Reversed`, the call inside that can fail.

`Clone` cannot fail: like every allocation in a `String`, it ends the program if memory runs out. Where that must be handled, `TryClone` fails with the allocator's `AllocError` instead.

## Lending a view

Whenever borrowed text is enough, a `String` lends out a view without copying anything:

```rux
let view = saved.View();
PrintLine("view   {}, {} characters", view, view.ScalarCount());
```

The view is valid as long as `saved` is. No cleanup is written anywhere: `word` and `saved` each release their own memory at the end of `Spell`, as the destructor lesson promised.

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/Text/String). Its comments explain every step.

<!-- sync:program:start -->

```rux [Src/Main.rux]
// A view borrows, so it can never outlive the bytes it looks at. Text that a function builds
// and hands back, or that must be kept after its source is gone, needs an owner. That is
// `String`: it keeps its own copy of the bytes, in memory it asked an allocator for, and gives
// that memory back in its destructor when the value's life ends.
//
// Checking that bytes are UTF-8 can fail, so the calls that make a `String` from bytes declare
// `-> Self ! TextError`. `Spell` can fail too, and `!` passes any such error on to `Main`. The
// allocator itself is the subject of the Memory part; for now it is simply where a String's
// bytes come from.
import Allocator::{ Allocator, SystemAllocator };
import Io::PrintLine;
import Text::{ String, TextError };

// The reversed letters exist only in this function's array, which is gone once it returns. A
// view of them would be left pointing at nothing, so the function returns a String that owns
// a copy. `FromBytes` checks the bytes are text before copying them, and that check matters
// here: reversed byte by byte, "né" puts the two bytes of `é` in the wrong order, and the
// call fails with `TextError::InvalidUtf8`. The array has room for words of up to 16 bytes.
func Reversed(allocator: Allocator, word: char8[..]) -> String ! TextError {
    var letters: char8[16];
    for i in 0..word.length {
        letters[i] = word[word.length - 1 - i];
    }
    return String::FromBytes(allocator, letters[..word.length]);
}

func Spell() -> !TextError {
    let allocator = SystemAllocator::New();

    var word = Reversed(allocator, "stressed")!;
    PrintLine("word   {}, {} bytes", word.View(), word.Length());

    // `Clone` makes an independent copy with storage of its own. Replacing the original's text
    // afterwards leaves the clone exactly as it was.
    let saved = word.Clone();
    word.ReplaceWith(Reversed(allocator, "drawer")!);
    PrintLine("word   {}", word.View());
    PrintLine("saved  {}", saved.View());

    // A String owns its memory, so `=` never copies one: two owners would release the same
    // bytes. `=` gives the one value away instead, and the old name cannot be used after it.
    // Copying is always the visible call to `Clone`:
    //
    //     let copy = saved;
    //     PrintLine("saved  {}", saved.View());
    //         error: 'saved' is used after it was given away
    //
    // `Clone` ends the program if memory runs out, as every allocation in a String does.
    // `TryClone` fails with an `AllocError` instead, for code where that must be handled.

    // A String lends out a view whenever borrowed text is enough, without copying anything.
    let view = saved.View();
    PrintLine("view   {}, {} characters", view, view.ScalarCount());

    // No cleanup is written: `word` and `saved` each release their own memory at the end of
    // `Spell`, as the Destructor lesson promised.
}

func Main() -> int {
    Spell() !! return 1;
    return 0;
}
```

Besides `Io`, its `Rux.toml` lists `Allocator` and `Text` under `[Dependencies]`.

## Common mistakes

::mistake
**Forgetting the `!`.**\
`var word = Reversed(allocator, "stressed");` keeps the whole fallible value, a `String ! TextError`, and the first use of it as a `String` fails with:

```text
error: 'View' is a member of 'String', but the value is the fallible 'String ! TextError'
help: handle the error first: pass it on with '!' before the '.', replace it with '!!', or handle it with 'catch { ... }'
```

Write `!` after the call to pass the error on and keep the `String`, or handle it with `catch` or `!!`.
::

::mistake
**Using a `String` after `=` gave it away.**\
`let copy = saved;` followed by `saved.View()` fails with:

```text
error: 'saved' is used after it was given away
help: lend it with '&saved' where it is only read, or clone it where both uses need a value
```

Where the text is only read, lend it (`&saved`) or print its view, `saved.View()`. Call `Clone` only when two copies are really needed.
::

::mistake
**Marking `Clone` with `!`.**\
`let saved = word.Clone()!;` fails with:

```text
error: '!' passes an error on, and 'String' has none
```

`Clone` cannot fail. Leave the mark off, or use `TryClone` when running out of memory must be handled.
::

## Try it yourself

1. Reverse `"né"` and handle the error with `catch` instead of passing it on, printing a message of your own.
2. Make a `String` from a view with `String::FromView(allocator, view)`.
3. Use `Substring(start, end)` to copy the first four bytes of `saved` into a new `String`. It can fail with `TextError::NotABoundary`, so it needs a `!` too.
4. Compare `word` and `saved` with `word.Equals(&saved)`, before and after `ReplaceWith`.
