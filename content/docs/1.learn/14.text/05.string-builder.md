# String builder

::note
<!-- sync:needs:start -->

**You'll need**: [String](/docs/learn/string), [Mutable reference](/docs/learn/mutable-reference), [Unit fallible](/docs/learn/unit-fallible), [Propagate](/docs/learn/propagate)
<!-- sync:needs:end -->

::

A [`String`](/docs/learn/string) has no way to add to its text — it can be cleared or replaced whole, but never appended to. Building text a piece at a time out of Strings alone would mean making a new String at every step and copying everything built so far into it — the longer the text, the more each step costs. `StringBuilder` is the tool for that job. It keeps one growing buffer, appends into it, and asks the allocator for a larger one only when the room runs out. When the text is finished, it hands the buffer over as a `String`.

## Length and capacity

A builder tracks two numbers: `Length`, the text so far, and `Capacity`, the room for it. A new builder has allocated nothing yet; its buffer appears with the first append.

```rux
var builder = StringBuilder(allocator);
```

`Join` appends the colours one at a time and reports both numbers after each:

```rux
func Join(builder: &var StringBuilder, words: char8[..][..]) {
    for i in 0..words.length {
        if i > 0 {
            let separator = if i == words.length - 1 { " and " } else { ", " };
            builder.Append(separator);
        }
        builder.Append(words[i]);
        PrintLine("added {}: {} bytes, room for {}", words[i], builder.Length(),
            builder.Capacity());
    }
}
```

| After adding | Length | Capacity | What happened                   |
| ------------ | ------ | -------- | ------------------------------- |
| `red`        | 3      | 16       | the first buffer is allocated   |
| `orange`     | 11     | 16       | fits; only the new bytes copied |
| `yellow`     | 19     | 32       | out of room: the buffer doubles |
| `green`      | 26     | 32       | fits                            |
| `blue`       | 35     | 64       | doubles again                   |

The room doubles each time it runs out, so most appends copy just the bytes being added, and the rare move to a bigger buffer gets rarer as the text grows.

The builder is passed as `&var StringBuilder` — a [mutable reference](/docs/learn/mutable-reference) — so `Join` grows the caller's builder rather than a copy of it.

## Which appends can throw

Appending text cannot fail. The text was checked when it was made, and a builder that cannot grow ends the program, as every allocation in a `String` does — so `Join` needs no `throws` and no `try` at all. Appending a single character is different: a `char32` may hold a value that is no character at all, so `AppendScalar` declares `throws TextError`, and its call is marked with `try`, which [passes the error on](/docs/learn/propagate) to `Main`.

| Method              | Appends                                       | Throws?                           |
| ------------------- | --------------------------------------------- | --------------------------------- |
| `Append(text)`      | a `char8[..]` or a `StringView`               | no                                |
| `AppendScalar(c)`   | one character, any `char32`, encoded as UTF-8 | `TextError`, for a non-character  |
| `AppendAscii(byte)` | one ASCII `char8`                             | `TextError`, for a non-ASCII byte |

```rux
builder.Append(" ");
try builder.AppendScalar('✓');
```

The check mark is one character but three UTF-8 bytes, which is why the finished text is 39 bytes, not 37.

## Taking the text out

`View` looks at the text so far without taking it — a [string view](/docs/learn/string-view) of the builder's buffer. `TakeString` hands the buffer itself to a `String`, without copying a byte, and leaves the builder empty, ready to build something else:

```rux
PrintLine("view    {}", builder.View());

let sentence = builder.TakeString();
PrintLine("string  {}", sentence.View());
PrintLine("builder now holds {} bytes", builder.Length());
```

```mermaid
flowchart LR
    b["`StringBuilder`<br/>buffer: 39 bytes"] -- "`View()`<br/>borrow, no copy" --> v["`StringView`"]
    b -- "`TakeString()`<br/>hand over the buffer;<br/>builder left empty" --> s["`String`<br/>owns the 39 bytes"]
    b -- "`ToString()`<br/>copy the bytes" --> c["`String`<br/>a copy; builder keeps its text"]
```

| Method         | Returns      | Copies? | Builder afterwards |
| -------------- | ------------ | ------- | ------------------ |
| `View()`       | `StringView` | no      | unchanged          |
| `TakeString()` | `String`     | no      | empty              |
| `ToString()`   | `String`     | yes     | unchanged          |

None of the three throws. `TakeString` allocates nothing; `ToString` allocates the copy, and like every allocation in a `String` ends the program if memory runs out.

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/Text/StringBuilder). Its comments explain every step.

<!-- sync:program:start -->

```rux [Src/Main.rux]
// A `String` cannot grow: it can be cleared or replaced whole, but never appended to, so building
// text a piece at a time out of Strings alone would copy everything built so far at every step.
// `StringBuilder` is the tool for that job. It keeps one growing buffer, appends into it, and asks
// the allocator for a larger one only when the room runs out. `Length` is the text so far and
// `Capacity` the room for it. The room doubles each time it runs out, so most appends copy just
// the bytes being added, and the rare move to a bigger buffer gets rarer as the text grows.
//
// Appending text cannot fail: text was checked when it was made, and a builder that cannot grow
// ends the program, as every allocation in a String does. Appending a single character can, since
// a `char32` may hold a value that is no character at all, so `AppendScalar` declares
// `throws TextError`. When the text is finished, `TakeString` hands the buffer over as a String
// without copying it.
import Allocator::SystemAllocator;
import Io::PrintLine;
import Text::{ StringBuilder, TextError };

// Joins words into a list a person would write: "a, b and c". The builder is borrowed `&var`,
// so the caller's builder is the one that grows. Watch the room: 16, then 32, then 64.
func Join(builder: &var StringBuilder, words: char8[..][..]) {
    for i in 0..words.length {
        if i > 0 {
            let separator = if i == words.length - 1 { " and " } else { ", " };
            builder.Append(separator);
        }
        builder.Append(words[i]);
        PrintLine("added {}: {} bytes, room for {}", words[i], builder.Length(),
            builder.Capacity());
    }
}

func Main() throws TextError {
    let allocator = SystemAllocator();

    // A new builder has allocated nothing yet. Its buffer appears with the first append.
    var builder = StringBuilder(allocator);
    let colours: char8[..][5] = ["red", "orange", "yellow", "green", "blue"];
    Join(builder, colours);

    // Single characters go in with `AppendScalar`, which encodes any character as UTF-8 and
    // refuses a value that is not one.
    builder.Append(" ");
    try builder.AppendScalar('✓');

    // `View` looks at the text so far without taking it.
    PrintLine("view    {}", builder.View());

    // `TakeString` hands the buffer itself to a String. The builder is left empty, ready to
    // build something else.
    let sentence = builder.TakeString();
    PrintLine("string  {}", sentence.View());
    PrintLine("builder now holds {} bytes", builder.Length());
}
```

Besides `Io`, its `Rux.toml` lists `Allocator` and `Text` under `[Dependencies]`.

## Common mistakes

::mistake
**Leaving the `try` off `AppendScalar`.**\
`builder.AppendScalar('✓');` on its own fails with:

```text
error: call to 'AppendScalar' can throw 'TextError' but is not marked with 'try'
  help: write 'try' before the expression
```

Add `try` to pass the error on, or handle it with `try … catch`. The other way round is a warning: `try builder.Append(" ");` reports `warning: 'try' has no call that can throw`, because appending text never throws.
::

::mistake
**A builder declared with `let`.**\
Appending changes the builder, so it must be a `var`. With `let builder`, the call `Join(builder, colours)` fails with:

```text
error: argument 1 to 'Join' cannot borrow immutable 'builder' as '&var StringBuilder'
```

Each `builder.Append` fails with:

```text
error: cannot call 'Append' on immutable 'builder'
```

::

::mistake
**Appending a character with `Append`.**\
`builder.Append('✓')` fails with:

```text
error: no matching overload for method 'Append' on type 'StringBuilder' with argument types (char32)
```

`Append` takes text. A single character goes in with `AppendScalar`.
::

## Try it yourself

1. Replace `TakeString` with `ToString()` and see what the last line prints now.
2. Make the builder with `StringBuilder::WithCapacity(allocator, 64)` instead. How do the `room for` numbers change?
3. Write `Repeat(builder: &var StringBuilder, text: char8[..], count: int)` and use it to build a line of 40 dashes. Does it need `throws`?
4. After `TakeString`, build a second sentence in the same builder.
