# Input

Every program so far has only talked. This one listens. Reading what a person types needs somewhere to put text that does not exist yet — a job for a [`StringBuilder`](/docs/learn/string-builder). `ReadLine`, from the Io package, appends the next line of standard input to one:

```rux
ReadLine(builder: &var StringBuilder) throws IoError
```

A return means a line arrived, without its line ending; an empty line is still a line. And reaching the end of the input is not a special return value. It is an error like any other, so a reading loop handles it in the same `catch` as a real error — and stops.

## One builder for every line

`Main` makes one builder and reuses it. `Clear` empties it before each line but keeps its memory, so after the first few lines the builder rarely needs to grow:

```rux
var builder = StringBuilder(allocator);
var count = 0;
PrintLine("Type some lines, then end the input.");
while true {
    builder.Clear();
    try ReadLine(builder) catch {
```

After a read that returns, `builder.View()` is the line, as a [string view](/docs/learn/string-view):

```rux
count += 1;
let line = builder.View();
if line.IsEmpty() {
    PrintLine("line {} is empty", count);
} else {
    PrintLine("line {} is \"{}\", {} bytes", count, line, line.Length());
}
```

## Telling the errors apart

An `IoError` carries a `kind`, an `IoErrorKind`. Two kinds matter to a reading loop, and [guards](/docs/learn/guard) on the `catch` arms pick them out:

```rux
try ReadLine(builder) catch {
    error if error.kind == IoErrorKind::EndOfStream => break,
    error if error.kind == IoErrorKind::InvalidText => {
        count += 1;
        PrintLine("line {} is not UTF-8 text", count);
        continue;
    },
    _ => {
        PrintLine("the input could not be read");
        return 1;
    }
};
```

Each arm leaves the loop body — with `break`, `continue` or `return` — so the code after the `catch` runs only when `ReadLine` returned a line. The `_` arm makes the `catch` exhaustive: guarded arms alone never cover every error.

| Outcome            | Means                                       | The loop   |
| ------------------ | ------------------------------------------- | ---------- |
| `ReadLine` returns | a line is in the builder                    | prints it  |
| `EndOfStream`      | there is no more input                      | `break`    |
| `InvalidText`      | the line was not UTF-8; it has been skipped | `continue` |
| any other error    | the input really could not be read          | `return 1` |

```mermaid
flowchart LR
    c["`builder.Clear()`"] --> r["`ReadLine(builder)`"]
    r -- "returns" --> p["print the line"] --> c
    r -- "`InvalidText`" --> s["report it"] --> c
    r -- "`EndOfStream`" --> e["`break`: report<br/>how many lines"]
    r -- "anything else" --> x["`return 1`"]
```

A line that is not valid UTF-8 throws `InvalidText`, but only after the rest of it has been read. So the next call starts cleanly on the next line, and the loop can carry on as if the bad line had been a comment.

## Ending the input

Typing at a terminal, nothing ends the input until you say so: **Ctrl+Z** then **Enter** on Windows, **Ctrl+D** elsewhere. Input piped in from another program or a file ends by itself, and an empty pipe ends at once — the very first `ReadLine` throws `EndOfStream`, and the program reports 0 lines.

The line ending is not part of the line, whether it was a Unix `\n` or a Windows `\r\n`, so `"Ada"` is three bytes on every system. A last line with no line ending at all still arrives as a line.

`ReadLine` reads from standard input. `ReadLineFrom` reads the same way from any other source of bytes.

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/Text/Input). Its comments explain every step.

<!-- sync:program:start -->

```rux [Src/Main.rux]
// Reading what a person types needs somewhere to put text that does not exist yet, and that is
// a job for a `StringBuilder`. `ReadLine` from the Io package appends the next line to one:
//
//     ReadLine(builder: &var StringBuilder) throws IoError
//
// A return means a line arrived, without its line ending; an empty line is still a line.
// Running out of input is not a special return value. It is an error like any other, an
// `IoError` whose `kind` is `IoErrorKind::EndOfStream`, so a reading loop handles it in the same
// `catch` as a real error, and stops.
//
// A line is UTF-8 text, so "héllo" arrives as six bytes. A line that is not valid UTF-8 fails
// with the kind `IoErrorKind::InvalidText`, but only after the rest of it has been read, so the
// next call starts cleanly on the next line and the loop can carry on. `ReadLineFrom` reads the
// same way from any other source of bytes.
//
// Interactively, end the input with Ctrl+Z and Enter on Windows, or Ctrl+D elsewhere. Piped
// input ends by itself.
import Allocator::SystemAllocator;
import Io::{ IoErrorKind, PrintLine, ReadLine };
import Text::StringBuilder;

func Main() -> int {
    let allocator = SystemAllocator();

    // One builder serves every line. `Clear` empties it but keeps its memory for the next one.
    var builder = StringBuilder(allocator);
    var count = 0;
    PrintLine("Type some lines, then end the input.");
    while true {
        builder.Clear();
        try ReadLine(builder) catch {
            error if error.kind == IoErrorKind::EndOfStream => break,
            error if error.kind == IoErrorKind::InvalidText => {
                count += 1;
                PrintLine("line {} is not UTF-8 text", count);
                continue;
            },
            _ => {
                PrintLine("the input could not be read");
                return 1;
            }
        };

        count += 1;
        let line = builder.View();
        if line.IsEmpty() {
            PrintLine("line {} is empty", count);
        } else {
            PrintLine("line {} is \"{}\", {} bytes", count, line, line.Length());
        }
    }
    PrintLine("end of input after {} line(s)", count);
    return 0;
}
```

Besides `Io`, its `Rux.toml` lists `Allocator` and `Text` under `[Dependencies]`.

## Common mistakes

::mistake
**Calling `ReadLine` without `try`.**\
`ReadLine(builder);` on its own fails with:

```text
error: call to 'ReadLine' can throw 'IoError' but is not marked with 'try'
```

The end of the input is one of the errors, so a loop that ignored it would never stop. `try? ReadLine(builder);` would compile — it drops the error on purpose — and loop forever at the end of the input.
::

::mistake
**Forgetting to clear the builder.**\
`ReadLine` adds to whatever the builder already holds. Without `builder.Clear()` at the top of the loop, each line is added to the ones before it: type `Ada`, an empty line and `Grace`, and the third line reads `"AdaGrace"`.
::

::mistake
**A `catch` with only guarded arms.**\
Leave out the `_` arm and the loop fails with:

```text
error: 'catch' arms do not cover every error of type 'IoError'
  help: add a '_' arm, or bind the whole error, as in 'e => ...'
```

A guard may be false, so guarded arms never cover every error. `EndOfStream` is how every reading loop is meant to end: catch it first, with its own guard, and `break` — and let a last `_` arm handle the errors that are real problems.
::

## Try it yourself

1. Stop the loop early when the line is `quit`. Make `let quit = StringView::FromValidated("quit");` (import `Text::StringView`) and compare with `line.Equals(quit)`.
2. Add up numbers typed one per line with `ParseInt32(line)`, skipping lines that are not numbers, and print the total at the end. `ParseInt32` comes from the Format package, so add `Format` to `[Dependencies]`.
3. Count the words on each line with `line.Split(…)`.
4. Pipe a file into the program: `Get-Content notes.txt | rux run` in PowerShell, or `rux run < notes.txt` in a POSIX shell.
