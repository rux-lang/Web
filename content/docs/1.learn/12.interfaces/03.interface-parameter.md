# Interface parameter

::note
<!-- sync:needs:start -->

**You'll need**: [Interface value](/docs/learn/interface-value), [Mutable reference](/docs/learn/mutable-reference), [Mutating method](/docs/learn/mutating-method)
<!-- sync:needs:end -->

::

The [Interface value](/docs/learn/interface-value) lesson read shapes through `&Shape` views. Often a function also has to change the caller's _own_ value, whatever its type, as long as it keeps a promise. A parameter written `&Gauge` or `&var Gauge` does exactly that. It borrows, as `&T` and `&var T` did in [Reference](/docs/learn/reference) and [Mutable reference](/docs/learn/mutable-reference), and it accepts any type that implements `Gauge`.

## A function for any gauge

```rux
// Only reads, so a shared borrow is enough.
func Show(gauge: &Gauge) {
    PrintLine("the {} reads {}", gauge.Label(), gauge.Read());
}
```

`Show` never learns whether it was handed a thermostat or a volume knob. It calls `Label` and `Read`, and dynamic dispatch runs the right type's code. The caller passes its own variable, with no conversion; the conversion to the interface happens at the call:

```rux
Show(heating);
Show(music);
```

Nothing is copied: `Show` sees the caller's value as it is right now. A thermostat is plain data that `Show` only reads, so the call writes it bare, just as a plain value is passed to any `&` parameter.

## Requirements that write

Turning a gauge up changes it, and the interface has to say so:

```rux
interface Gauge {
    func Label() -> char8[..];
    func Read() -> int32;
    func Adjust(&var self, amount: int32);
}
```

A requirement with no receiver, or with `&self`, only reads the value. One that changes it declares the receiver `&var self`, which borrows whichever type implements the interface for writing. Each implementation then takes `&var self` too, as in [Mutating method](/docs/learn/mutating-method):

```rux
// A volume knob stops at 10, however far it is turned.
func Adjust(&var self, amount: int32) {
    self.level += amount;
    if self.level > 10 {
        self.level = 10;
    }
}
```

| Requirement in `Gauge`                   | Implementation's receiver | Callable through          |
| ---------------------------------------- | ------------------------- | ------------------------- |
| `func Read() -> int32;`                  | `&self`                   | `&Gauge` and `&var Gauge` |
| `func Adjust(&var self, amount: int32);` | `&var self`               | `&var Gauge` only         |

## Changes reach the caller

To call `Adjust`, the parameter must be a writable borrow:

```rux
func TurnUp(gauge: &var Gauge, amount: int32) {
    gauge.Adjust(amount);
}
```

A function that writes its argument changes the caller's variable, so the caller has to say so. It writes the loan, `&var heating`, and anyone reading the call sees that it changes:

```rux
// Each type's own `Adjust` runs: the knob stops at 10, the thermostat does not. Leave out the
// `&var` and the call is refused: "'TurnUp' writes its argument 'heating', so the loan must
// be written".
TurnUp(&var heating, 5);
TurnUp(&var music, 5);
```

```mermaid
flowchart LR
    caller["`var heating`<br/>(a `Thermostat`)"] -- "`TurnUp(&var heating, 5)`<br/>lent as `&var Gauge`" --> invoke["`gauge.Adjust(5)`"]
    invoke -- "dispatch" --> impl["`Thermostat`'s `Adjust`"]
    impl -- "writes through the borrow" --> caller
```

Each type's own `Adjust` runs: the thermostat goes from 19 to 24, while the knob, turned from 7 by 5, stops at 10. And the last line, `heating.degrees is now 24`, proves the change landed on the caller's variable itself, not on a copy.

Side by side:

| Parameter           | The caller writes                     | Can it change the original? |
| ------------------- | ------------------------------------- | --------------------------- |
| `gauge: &Gauge`     | `Show(heating)`: plain data goes bare | no                          |
| `gauge: &var Gauge` | `TurnUp(&var heating, 5)`             | yes                         |

## The program

The whole lesson is one package in the [Examples repository](https://github.com/rux-lang/Examples/tree/main/Interfaces/InterfaceParameter). Its comments explain every step.

<!-- sync:program:start -->

```rux [Src/Main.rux]
// A function can ask for an interface instead of a concrete type, and then any type that keeps
// the promise may be passed to it. The caller hands over its own thermostat or volume knob, and
// the conversion to the interface happens at the call.
//
// Written with `&`, the parameter borrows, exactly as `&T` did in the Reference lesson: nothing is
// copied, and the function sees the caller's value as it is right now. Written with `&var`, the
// borrow is writable, so a change made through the interface lands on the caller's own variable,
// and the caller writes the loan, `&var heating`, so the call shows that it changes.
//
// The interface has to say which of its requirements write. A requirement with no receiver, or
// with `&self`, only reads the value; one that changes it declares the receiver `&var self`, which
// borrows whichever type implements the interface for writing. Leave that out and every `Adjust`
// below is refused: "method 'Adjust' of 'Thermostat' writes through its receiver, but requirement
// 'Adjust' of interface 'Gauge' only reads it", with the help "declare '&var self' on requirement
// 'Adjust' in interface 'Gauge', or take '&self'".
import Io::PrintLine;

interface Gauge {
    func Label() -> char8[..];
    func Read() -> int32;
    func Adjust(&var self, amount: int32);
}

struct Thermostat {
    degrees: int32;
}

struct Volume {
    level: int32;
}

extend Thermostat : Gauge {
    func Label(&self) -> char8[..] {
        return "thermostat";
    }

    func Read(&self) -> int32 {
        return self.degrees;
    }

    // Adjusting changes the value, so this method takes `&var self`.
    func Adjust(&var self, amount: int32) {
        self.degrees += amount;
    }
}

extend Volume : Gauge {
    func Label(&self) -> char8[..] {
        return "volume";
    }

    func Read(&self) -> int32 {
        return self.level;
    }

    // A volume knob stops at 10, however far it is turned.
    func Adjust(&var self, amount: int32) {
        self.level += amount;
        if self.level > 10 {
            self.level = 10;
        }
    }
}

// Only reads, so a shared borrow is enough.
func Show(gauge: &Gauge) {
    PrintLine("the {} reads {}", gauge.Label(), gauge.Read());
}

// Calls `Adjust`, which changes the value, so the borrow must be writable too. Written as
// `gauge: &Gauge`, the call below is refused: "cannot call 'Adjust' through immutable reference
// '&Gauge'", with the help "declare the reference as '&var Gauge'".
func TurnUp(gauge: &var Gauge, amount: int32) {
    gauge.Adjust(amount);
}

func Main() -> int {
    var heating = Thermostat { degrees: 19 };
    var music = Volume { level: 7 };
    Show(heating);
    Show(music);

    // Each type's own `Adjust` runs: the knob stops at 10, the thermostat does not. Leave out the
    // `&var` and the call is refused: "'TurnUp' writes its argument 'heating', so the loan must
    // be written".
    TurnUp(&var heating, 5);
    TurnUp(&var music, 5);

    // The changes were made to these very variables, not to copies of them.
    Show(heating);
    Show(music);
    PrintLine("heating.degrees is now {}", heating.degrees);

    // A writable borrow needs a writable variable. Declare `heating` with `let` and the call is
    // refused: "'&var' lends for writing, but this place is immutable".
    return 0;
}
```

## Common mistakes

::mistake
**A requirement that does not say it writes.**\
Declare `Adjust` in the interface as `func Adjust(amount: int32);` and every implementation is refused:

```text
error: method 'Adjust' of 'Thermostat' writes through its receiver, but requirement 'Adjust' of interface 'Gauge' only reads it
  help: declare '&var self' on requirement 'Adjust' in interface 'Gauge', or take '&self'
```

Add `&var self` to the requirement.
::

::mistake
**Calling a writing method through a read-only borrow.**\
With `gauge: &Gauge`, the call `gauge.Adjust(amount)` fails with:

```text
error: cannot call 'Adjust' through immutable reference '&Gauge'
  note: 'Adjust' declares a writable receiver '&var Self'
  help: declare the reference as '&var Gauge'
```

A function that changes the value needs `&var Gauge`.
::

::mistake
**Leaving out the `&var` at the call.**\
`TurnUp(heating, 5)` hides that the call changes `heating`, so it is refused:

```text
error: 'TurnUp' writes its argument 'heating', so the loan must be written
  help: write '&var heating'
```

::

::mistake
**Lending a `let` variable for writing.**\
A writable loan needs a writable variable. Declare `heating` with `let` and `TurnUp(&var heating, 5)` fails with:

```text
error: '&var' lends for writing, but this place is immutable
  help: declare 'heating' with 'var' to make it mutable
```

`Show(heating)` still works, because it only reads.
::

## Try it yourself

1. Add a `Fan` with a `speed` that keeps the `Gauge` promise, and whose `Adjust` never lets the speed drop below 0. Turn it down by 5 from 3.
2. Write `func Reset(gauge: &var Gauge)` that brings any gauge back to 0 using only `Read` and `Adjust`.
3. Declare `music` with `let`. Which calls in `Main` still compile, and why?
